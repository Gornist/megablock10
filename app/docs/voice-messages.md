# Голосовые сообщения личного чата

Решения владельца (07.10.2026): логика — как в Telegram; предел 60 с; личный чат раньше фракционного; хранение до сброса персонажа; отчёт «прослушано»
(синие ✓✓) отправителю — да; автопроигрывание следующего — переключатель в настройках; «к уху» не делаем.

| 4 | отчёт «прослушано» отправителю: `MB10LISTEN` v1, синие ✓✓ (`MessageStatus.LISTENED = 5` в той же колонке, схема Room не менялась) | этот PR |

«К уху» не делаем (решение владельца). Отчёт «прослушано» уходит один раз при первом запуске чужого голосового тем же переключателем «Отчёты о прочтении», что и `MB10READ`
(выключен — точка гаснет, автору ничего не уходит); не дошло — через очередь исходящих. У голосовых `MB10READ` (открыл тред) статус не поднимает: синие ✓✓ только после прослушивания.

## Формат записи

AAC-LC, моно, 16 кГц, 20 кбит/с (`MediaRecorder`, MPEG-4, файл `.m4a`; работает со всеми Android ≥ 8, Opus потребовал бы API 29). 60 с ≈ 150 КБ.
Волна — 64 байта (высота столбиков), считается при записи и едет вместе со звуком.

## Провод

Одной строкой по порту чата (47100), в конверте `MB10TO` и с ответом `MB10ACK ok` после сохранения (D2) — как текст:

`MB10VOICE:v1:<от>:<b64 позывной>:<b64 фракция>:<кому>:<время мс>:<id>:<длительность мс>:<b64 волна>:<b64 звук>`

Предел: строка ≤ 256K символов (kit `LineServer.DEFAULT_MAX_LINE_CHARS`) → звук ≤ 180 000 байт (`VoiceLimits.MAX_AUDIO_BYTES`), `id` — `[A-Za-z0-9_-]{8,64}`
(им называется файл — другой id не принимается). Версия — `WireVersion.VOICE`; дашборду не сообщается (чат до коллектора не доходит, пары с Коллектором нет).
Старое приложение молча отбрасывает неизвестную магию: обновляться надо всем одним APK.

## Хранение

Звук — файл `filesDir/voice/<id>.m4a` (`VoiceStore`, запись через временный файл), в Room — обычное сообщение `DM` с маркером вместо текста:
`MB10VM:v1:<id>:<мс>:<b64 волна>`. Дедуп приёма — тот же `countSame` (отправитель + время + тип + маркер). Сброс персонажа стирает папку.
Файл на приёме сохраняется ДО строки в Room и до ответа «доставлено»; сбой записи файла — исключение, подтверждения нет, отправитель повторит из очереди.

## Очередь исходящих (офлайн-получатель)

Как у текста: повторы 2/4/8/15/30 с, дальше раз в минуту, срок 12 ч. В Room-очереди лежит НЕ звук, а строка-ссылка `MB10VREF:v1:…` (то же без звука,
~500 символов); при отправке `OutboxStore` через `VoiceMessenger.expand` подтягивает звук из файла. Файл пропал — запись снимается без «доставлено»,
сообщение остаётся «не ушло». Исход `UNKNOWN` (могло дойти) — статус «ушло» и повтор: получатель дедуплицирует.

## Проверка вживую (PR 1, без интерфейса)

Отладочная команда (debug-сборка): `am broadcast … -a com.megablok10.app.DEBUG_SET --es sayvoice "<ключ получателя>|5"` (5 с случайных байт, `|offline` —
получатель «не в сети»). У получателя должен появиться файл в `files/voice/`, в журнале `voice.recv`, у отправителя `voice.send outcome=DELIVERED`.
