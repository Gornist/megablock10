# Мегаблок №10

Приложение для киберпанк-LARP примерно на 100 игроков: чат, звонки, кошелёк и «кибердека» для взлома узлов — то, что в мире
игры есть у любого жителя мегаблока. Работает **без интернета**, в закрытой Wi-Fi сети площадки. Мастерам — необязательный
веб-дашборд на ноутбуке. Нетраннерам — **«Сеть»**: киберпространство в VR-очках Pico 4 на терминалах площадки (в разработке).

## Для игроков и мастеров

**В телефоне игрока** — четыре вкладки:

| Вкладка | Что там |
|---|---|
| **Чат** | Личная переписка и чат фракции. У своих сообщений отметки: «…» ещё не ушло, «✓» ушло, «✓✓» доставлено, «✓✓» цветом — прочитано (отчёты о прочтении отключаются в Настройках). Не ушедшее уйдёт само, когда собеседник появится в сети. |
| **Звонки** | Голосовые звонки внутри игры. |
| **Кибердека** | Взлом узлов по QR-меткам на площадке: мини-игра на время, награда — эдди, шарды (секретные документы) и демоны (программы для взлома). |
| **Финансы** | Эдди: баланс и переводы. Перевод приходит карточкой в чат, получатель жмёт «Принять». Шарды и демонов можно передать так же — предмет переходит, а не копируется. |

**У мастера** — дашборд-коллектор (`admin-web/`), меню двумя группами:

- **Игра** — обзор и «Требует внимания» (подозрения на подделку, пропавшие со связи, всплески денег, севшие батареи точек),
  лента событий, игроки: состояние, правка баланса и данных (доходит до телефона за ~30 с), повторная выдача персонажа;
  фракции, экономика, переводы, объявления на все телефоны, журнал мастеров.
- **Мир** — узлы (контейнеры) и **точки на площадке**: узел может стоять в мире электронной точкой — QR на e-paper-дисплее
  со звуком (ESP32, [docs/displays.md](docs/displays.md), [docs/sound-nodes.md](docs/sound-nodes.md)). «Устройства» — все
  точки одним списком с состоянием и командами; мастер отправляет на точку QR узла, в каждой локации («Локации») играет свой
  фон из «Каналов звука», **«Громкая связь»** — записанное в браузере объявление на все точки, локации или отдельные точки. «Мастерская» — **QR персонажа** для выдачи игроку, QR контейнеров,
  шардов и RAM для печати, учётные записи мастеров; «Реестр тиражей» — кто забрал редкую награду.

Без дашборда игра идёт как обычно; без точек — QR-метки просто печатаются на бумаге.

**У нетраннера** — «Сеть» (`netrun/`, [docs/netrun.md](docs/netrun.md)): третий интерфейс того же мира. Нетраннер входит
в VR-очках Pico 4 на терминале площадки и от первого лица ходит по узлам Сети: разведка, обход ICE, демоны, кража шардов.
Те же игроки, эдди, шарды и демоны, что в телефоне; дека на запястье, звонки и чат телефона видны в очках. Soft ICE выбрасывает
из Сети и сигналит СБ, Black ICE приносит мастеру карточку флэтлайна. **Статус: прототип**, проверяется на очках владельцем;
для тестеров геймдизайна есть одиночная плоская сборка под Windows ([docs/gamedesign/flat-playtest.md](docs/gamedesign/flat-playtest.md)).

### Что нужно для игры

- Телефоны на **Android 8.0+** (iPhone не поддерживается), у всех — **одна сборка** приложения.
- **Wi-Fi площадки без интернета**, телефоны видят друг друга напрямую: без изоляции клиентов, mDNS разрешён, **порт 47100/TCP**
  открыт между телефонами — [docs/network-spec.md](docs/network-spec.md).
- По желанию — ноутбук мастера с дашбордом в той же сети: [admin-web/README.md](admin-web/README.md).
- По желанию — точки на площадке (CrowPanel ESP32-S3 5.79″, для звука — усилитель MAX98357A, microSD и пачка 4 × 21700):
  [docs/displays.md](docs/displays.md), [firmware/display/README.md](firmware/display/README.md). На настоящей плате прошивка
  ещё не запускалась — всё проверено без железа (прошивка для ПК против сервера, эмулятор Wokwi).
- Для «Сети» — очки Pico 4 (обычные, не Enterprise) на каждый терминал и мини-ПК с сервером мира в той же сети:
  [docs/netrun-vr-hardware.md](docs/netrun-vr-hardware.md). К игре ещё не готово.
- Чек-лист на день игры — [docs/game-day-checklist.md](docs/game-day-checklist.md).

### Установка

1. GitHub → **Actions** → последняя успешная сборка «APK для телефонов» (на каждое слияние в `main`; по тегу `v*` — ещё и
   Release) → артефакт `megablok10-apk`. В имени файла — короткий хеш коммита: по нему видно, какая сборка на каком телефоне.
2. Перекиньте файл на телефон и откройте; разрешите установку из неизвестных источников, затем камеру и микрофон.
3. На первом экране «Сканировать QR персонажа» — код выдаёт мастер; он настраивает связь с сервером и создаёт персонажа.
   Нет камеры — «Нет камеры? Ввести код» и короткий код вида `ABC-DEF`, который мастер видит рядом с QR.
   Код одноразовый; начать заново — «Сбросить сессию персонажа» (Профиль → «Настройки» → «Опасная зона») и новый код
   от мастера.
4. Познакомиться с игроком — открыть «Профиль» (нажать на свой позывной вверху экрана) и показать свой QR; другой игрок
   сканирует его кнопкой «Сканер» в своём «Профиле».
5. Журнал приложения для разбора сбоев — Профиль → «Сеть» → «Журнал приложения» → «Отправить журнал».

**Обновление.** «APK для телефонов» подписан постоянным ключом владельца, поэтому новая сборка ставится поверх старой с
сохранением персонажа. Не годятся для этого debug-APK из «Build debug APK» (`main.yml`): их ключ случайный, поверх Android их не
поставит, а удаление стирает персонажа, деньги и переписку. Переход с такой сборки на подписанную — один раз через удаление.
У всех игроков должна быть одна сборка; посреди игры не обновлять.

**Если пропала связь** — приложение работает дальше, сообщения уйдут позже. Деньги и предметы в очередь не ставятся: пока
получатель не получил перевод, его можно отменить. **Если выключен ноутбук мастера** — не работают только правки мастера и
раздача редких предметов, они догонят, когда сервер вернётся.

## Для разработчиков

**Правила работы, проверки и инварианты — [CLAUDE.md](CLAUDE.md).** Прочитать до первой правки.

### Устройство

- `kit/` — ядро без Android: сеть на площадке (таблица пиров, адресация, конверт с ответом получателя), подписи, передача
  ценностей, синхронизация с сервером. [kit/README.md](kit/README.md)
- `rules/` — правила игры без Android (чистый Kotlin, зависит от `kit`): общие для приложения и Моста «Сети»; там же общие
  JSON-векторы контрактов (`rules/src/test/resources/contracts/`), которые читают и приложение, и коллектор. [rules/README.md](rules/README.md)
- `app/` — приложение: Kotlin, Jetpack Compose, Room; minSdk 26, targetSdk 35. Корень композиции `di/AppGraph`, сценарии,
  ViewModel, экраны. [docs/architecture.md](docs/architecture.md)
- `admin-web/` — дашборд-коллектор мастера: Fastify, better-sqlite3, React, Vite; он же управляет точками на площадке
  (сервер сам подключается к ним по TCP 47200). [admin-web/README.md](admin-web/README.md)
- `firmware/display/` — прошивка точки (QR-дисплей и звук): ядро на C++ без Arduino, сборка для ПК (проверяется настоящим
  сервером) и для ESP32-S3, самопроверка в эмуляторе Wokwi. [firmware/display/README.md](firmware/display/README.md)
- `netrun/` — «Сеть», один проект Godot 4.7 и три сборки: VR-клиент для Pico 4, сервер мира, плоский клиент (боты, отладка,
  одиночная сборка Windows для тестеров). Вид — облако точек, модели из Blender (`netrun/assets/`). [netrun/README.md](netrun/README.md)
- `netrun-bridge/` — Мост «Сети» на мини-ПК (Kotlin/JVM): связывает сервер мира с коллектором и телефонами.
  [docs/netrun-bridge-protocol.md](docs/netrun-bridge-protocol.md)
- `scripts/e2e/` — стенд: сервер и два эмулятора, сценарии. [scripts/e2e/README.md](scripts/e2e/README.md)
- `scripts/` — общие инструменты: проверки (`check.sh`, `verify.sh`), очередь слияний (`train.sh`, `land.sh`), машина
  разработки devbox (`box.sh`, `dbx.sh`, `devbox-*`). Тяжёлое (Gradle, e2e, Godot) идёт на devbox: [docs/devbox.md](docs/devbox.md).

Сеть коротко: телефоны находят друг друга через NSD (mDNS), по подсказкам сервера и по входящим соединениям; обмен — прямым
TCP на постоянный порт 47100. Каждая строка идёт в конверте «кому / от кого», получатель сохраняет её и отвечает своим ключом —
так отправитель знает, что дошло до того самого игрока. Центральный сервер телефонам не нужен.

### Сборка

Нужны JDK 21 (его требует Paparazzi 2; байткод проекта — Java 17) и Android SDK command-line tools.

```bash
sdkmanager "platform-tools" "platforms;android-37.0" "build-tools;36.0.0"   # один раз
./gradlew assembleDebug                                                    # → app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Необязательные настройки в `local.properties`: `mb10.collectorUrl=http://<адрес>:2517` — сервер по умолчанию (иначе адрес
приходит в QR персонажа), `mb10.allowManualSetup=true` — персонаж без QR (только для разработки).

### Проверки

```bash
scripts/setup-hooks.sh                              # один раз: pre-push хук (check.sh --fast, ≤ 1 мин)
scripts/verify.sh                                   # проверки только затронутых областей, вердикт одной строкой (--dry — показать набор)
scripts/check.sh --all                              # всё локально: статика, kit, app, скриншоты, коллектор (сервер и клиент)
scripts/e2e/up.sh && scripts/e2e/run-all.sh         # два эмулятора + дашборд, все сценарии (~17 мин)
admin-web/tools/test.sh all                         # коллектор: server | client | lint | build | all
netrun/tools/dev.sh test                            # «Сеть»: тесты gdUnit4 на devbox (--all — полный прогон)
cmake -S firmware/display -B firmware/display/build && cmake --build firmware/display/build -j && ctest --test-dir firmware/display/build
```

CI — `.github/workflows/main.yml` (сборка, статика, тесты приложения, Моста и коллектора), `apk.yml` (APK для телефонов),
`e2e.yml` (стенд на эмуляторах), `netrun.yml` («Сеть»: тесты, экспорт APK для Pico, сервера мира и exe для тестеров),
`firmware.yml` (прошивка: ядро, сервер против прошивки для ПК, нагрузка, сборка для платы, Wokwi) и `pipeline.yml` (скрипты,
хук, workflows). В `main` — только поездом слияний: [docs/ci.md](docs/ci.md). Обновления зависимостей
предлагает Dependabot (`.github/dependabot.yml`): раз в неделю PR по экосистеме — Gradle, сервер и клиент коллектора, раз в
месяц — действия GitHub. Подробности, грабли и что
никогда не делать (например, `cleanTest*` стирает эталоны скриншотов) — в [CLAUDE.md](CLAUDE.md).

### Осознанные ограничения

- Модель угроз — дружеская игра: сервер принимает баланс из подписанных записей как есть, подписей чата и реестра ключей нет.
- Тираж редкой награды арбитрирует сервер; без сервера заявка рассылается видимым телефонам один раз — офлайн-телефон её не
  дозаберёт (принятый компромисс).
- Разные версии протоколов не общаются: приложение сообщит «игрок с другой версией приложения» — у всех одна сборка.
