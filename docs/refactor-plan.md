эмуляторами на CI ходит: Alice видит Bob по `10.0.2.17`, Bob Alice — по `10.0.2.16`; 12 из 14 сценариев зелёные. Красные — из-за
приложения, класс B2: (1) `item-transfer` — Alice перезапустилась (19:27:10, новый порт 41531), а Bob через 30 с снова получил

## Этап B — сетевой код (до проверки на телефонах: проверять уже итоговый код)

**B1. `PeerDirectory` вместо сырого списка пиров.** Одно место для адресации: `addresses(key)`, `send(key, line): SendOutcome`
(перебор адресов — уже есть `addressesOf`/`sendToFirstReachable`), `online(): List<Peer>` без дублей для экранов. Перевести
`ChatStore`, `OutboxStore`, `CallManager` (сейчас берёт один адрес), `ContactDirectory`, `SecAlertStore`.
*Готово, когда:* `PeerInfo` с host/port не выходит за пределы `PeerDirectory`/`MeshSession`; `grep "peers().find"` пуст.

**B2. Таблица пиров — по ключу игрока.** Записи хранить по `pubKeyB64` со списком адресов и временем; свежий `peer.found`
того же ключа вытесняет адрес прошлого процесса; удачная отправка поднимает адрес вверх, `NOT_REACHED` — опускает.
*Готово, когда:* тест «игрок перезапустил приложение (новый порт) — первая же отправка уходит на новый порт».
*Сделано (kit, `PeerTable`):* ~~адреса по ключу игрока~~ — записи по источникам, у записи NSD история из 3 адресов (имя сервиса
у игрока одно во всех процессах, кэш mDNS после перезапуска отдаёт то новый порт, то прошлый); подсказка сервера больше не
выбрасывается, когда NSD знает игрока (в A4 выбрасывалась как раз верная); loopback-подсказка (стенд) — порт с host-ом из NSD;
порядок: свежее событие первым, `NOT_REACHED` — в конец до удачи, `UNKNOWN` не трогает (исход — из `LineSocketClient`).
Тест `playerRestartedWithNewPortFirstSendGoesToTheNewPort` и сценарий A4 (`staleNsdAnswer…`, `loopbackHint…`) в `PeerTableTest`.
Число игроков на экранах и очередь — по одному адресу на игрока (`bestPerPlayer`). e2e со `static_peers=false` — см. ниже.

**B3. `SessionController` — одно место для фоновой работы.** Вход: «процесс стартовал», «личность появилась/сброшена»,
«экран открыт». Он решает, что запущено: сеть, синк, foreground-сервис (с правилами Android 12+). Сейчас это
`Mb10App.onCreate`, `AppGraph.start*`, `onUiStarted`, `MeshSession.ensureForeground`, `SessionReset`.
*Готово, когда:* JVM-тест на таблицу «событие → что запущено» и никто, кроме контроллера, не зовёт `mesh.start/stop`,
`startCollectorSync`, `MeshForegroundService.start`.

## Этап C — после проверки на телефонах

**C1. Личность в Room, в одной транзакции со стартовыми данными.** Выдача по QR сейчас: личность (SharedPreferences)
→ транзакция Room (записи, баланс); между ними окно, которое закрывает `resumeInterrupted`. Перенос личности в Room убирает
окно и два источника правды. Нужна миграция с переносом ключей из `identity_prefs` без потери (ключ = личность игрока).
*Готово, когда:* `MigrationDataTest` переносит ключи; выдача — одна транзакция; `resumeInterrupted` для выдачи не нужен.
