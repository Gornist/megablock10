# Записи мира для коллектора и быстрые события «Сети» (контракт C2)

Контракт для M4 (Мост пишет записи через `SyncEngine`), M7 (приём на стороне коллектора, соседняя сессия) и L3 (быстрые
события на точки). Протокол Моста с клиентами — [netrun-bridge-protocol.md](netrun-bridge-protocol.md) (C1), план —
[netrun.md](netrun.md). Здесь — только то, что **уходит из Моста наружу**: в коллектор синком и быстрыми событиями.

## 1. Главное: текущий коллектор не принимает неизвестные записи

Проверено по коду `admin-web/server` (только чтение):

- `lib/changeRecord.ts:1-30` — закрытые списки `FIELDS` (12 полей) и `REASONS` (18 причин).
- `lib/changeIngest.ts:106-108` (`validateRecord`) — неизвестное `field` или `reason` даёт `{ok:false, error:"unknown field: …"}`
  / `"unknown reason: …"`. Запись **не сохраняется**, батч не падает: `ingestOne` (там же, стр. 170-172) кладёт её в
  `rejected`, `routes/changes.ts:75-82` возвращает `rejected: [{id, error}]`; ошибки попадают в метрики пульса
  (`pulse.batch`, `routes/changes.ts:76`).
- Kit на этот ответ **удаляет запись из очереди**: `SyncEngine.kt:188` — `queue.deleteByIds(result.rejected.keys)`, плюс
  предупреждение `sync.rejected` (стр. 193-196). Повтора нет — запись потеряна навсегда.
- Остальные проверки (`changeIngest.ts:109-118`): `reason = MASTER_OVERRIDE` запрещён устройству; для всего, кроме `TRANSFER_IN`,
  `actor == subjectKeyB64`; подпись ECDSA P-256 (`SHA256withECDSA`, DER, base64; kit `Ecdsa`) по pipe-строке (`ChangeRecord.signaturePayload`,
  kit `ChangeRecord.kt:29-34`, тот же формат на сервере `changeRecord.ts:75-90`; проверка `lib/crypto.ts`) проверяется ключом `actor` —
  открытым ключом SPKI в обычном base64 (не base64url); ключ мира Моста (`WorldKey`) — такая же пара P-256, не Ed25519; у одного `subject` `seq` уникален
  (`changeIngest.ts:186`); дубль того же `id` с теми же полями — «принято» без второй записи (стр. 177-181), с другими —
  `id already used by a different record`.
- Значения: `valueProblem` (`changeIngest.ts:73-110`) — для полей вне `balance/ramCapacity/callsign/faction` `newValue` обязан
  быть **JSON-объектом** (не массив) до 4096 символов; `sourceRef` ≤ 200, `id` ≤ 100 символов.
- Свёртка `lib/projection.ts:187-237` — `switch (field)` без ветки по умолчанию, `Field` — закрытый тип: новые поля нужно
  явно игнорировать/обрабатывать (иначе проекция мира попадёт в «персонажа»).

**Следствие.** Записи мира в этом формате (раздел 2) текущим коллектором **отбрасываются**. Мост не должен слать их, пока коллектор
не объявил, что понимает (раздел 5, п. 5). Изменение под них — правка M7, не «обходной путь» в нашем коде. Менять существующие
`FIELDS`/`REASONS` и маскировать записи мира под записи игрока (`balance`, `shards.*`) нельзя: подпись игрока Мост поставить не
может, а проекция записала бы мир в «персонажи».

Что коллектор **уже видит без Моста**: перевод эдди и предметов на телефон и с телефона — это обычные карточки Handover, и
записи `TRANSFER_IN` / `ITEM_TRANSFER_IN` / `*_OUT` пишут сами телефоны (с ключом мира в `actor`). Поэтому записи мира не
дублируют движение денег и предметов по телефонам: они говорят о том, что происходит **внутри Сети** и телефону неизвестно.

## 2. Записи мира (синк)

### 2.1 Общие правила

- **Субъект и автор** — ключ мира (тот же, что получатель карточек): `subjectKeyB64 = actor = world_pub`. Подписывает Мост
  (kit `ChangeRecorder` + `ChangeQueue` + `SyncEngine`, как на телефоне; `subjectKey` Моста — ключ мира).
- **Новые `field`** (все начинаются с `net.`): `net.run`, `net.item`, `net.alert`. **Новые `reason`**: `NET_ENTER`, `NET_EXIT`,
  `NET_FLATLINE`, `NET_ITEM_OWNER`, `NET_ALERT`. Это и есть правка M7 (раздел 5).
- `oldValue` — всегда `null` (состояния «до» в виде отдельного документа нет; всё нужное — в `newValue`). `newValue` — JSON-объект
  ≤ 4096 символов, строка байт-в-байт как подписана (Мост сериализует один раз и хранит строку в очереди). Ключи плоские, значения
  — строки/числа/булевы; `payload` предметов в запись **не попадает** (его хранит Мост; коллектор получает его картой Handover).
- **`id` записи** — `w:<field>:<epoch>:<txSeq>:<sourceRef>` (≤ 100 символов; у Моста не длиннее 96). `sourceRef` — id документа Моста
  (сессия, предмет, тревога): мастер по нему находит документ в «сыром виде» Моста. `txSeq` — номер транзакции хранилища Моста
  (`Change.seq`), в которой документ изменился и родилось событие: одно появление события — один номер, поэтому тревога, которую
  мастер снял, а аудитор поднял снова (тот же id документа и `ver = 1`), получает **другой** `id` и отдельную запись. `epoch` — «эпоха»
  базы: 8 символов `0-9a-z`, случайные, создаются один раз при первой инициализации файла базы и хранятся в нём (`meta.epoch`,
  `DocStore.epoch`); после сброса базы (тот же ключ мира, `txSeq` снова с 1) она не даёт новым записям `id` старых, иначе коллектор
  отверг бы их как `id already used by a different record` (раздел 1). Повтор отправки уже поставленной в очередь записи `id` не меняет.
- **Идемпотентность и порядок.** Запись ставится в очередь **в той же транзакции SQLite Моста, что и изменение документов**
  (как `changes.record` на телефоне, CLAUDE.md «Инварианты»): нет транзакции — нет записи, нет записи — нет транзакции.
  Повтор синка ничего не дублирует: `id` тот же, коллектор отвечает «принято» (`changeIngest.ts:177-181`). `seq` монотонный
  по ключу мира и переживает сброс файла базы (свежая база начинает счёт со времени в секундах, раздел 7, п. 5). Если коллектор восстановили из бэкапа, kit сам возвращает потерянное (`SyncEngine.kt:189-192`,
  `requeueAcceptedAbove`).
- `happenedAt` — время изменения документа (`updated`), мс.
- Нагрузка: единицы записей в минуту; лимит 120 запросов/мин на адрес (`routes/changes.ts`) и пачка ≤ `MAX_BATCH` не мешают.

### 2.2 Вход: `net.run` / `NET_ENTER`

Когда: `op.submit_deck` создал сессию (`pending`) — **не** при подтверждении курком: «вход» для мастера — это сданная дека и
занятый терминал. Подтверждение (`active`) — отдельной записью не пишется (мастер видит его по состоянию терминала). Кто читает:
журнал и карточка нетраннера на дашборде («кто сейчас в Сети»), экран «Сеть» мастера.

```json
{"id": "w:net.run:k3f9a2xq:4810:s_9f2c41d07a3e5b60", "subjectKeyB64": "<world_pub>", "seq": 412, "happenedAt": 1790000500000,
 "field": "net.run", "oldValue": null,
 "newValue": "{\"session\":\"s_9f2c41d07a3e5b60\",\"runner\":\"MFkwEwYH…\",\"callsign\":\"Призрак\",\"terminal\":\"t03\",\"node\":\"node_07\",\"deck\":3,\"protected\":true}",
 "reason": "NET_ENTER", "sourceRef": "s_9f2c41d07a3e5b60", "actor": "<world_pub>", "signature": "…"}
```

`deck` — число сданных предметов. Учебный забег — тот же формат (`node` = учебный узел).

### 2.3 Выход: `net.run` / `NET_EXIT`

Когда: `run.finish` с исходом `clean`, `emergency`, `soft_ice`, а также `aborted` (отмена входа: терминал не подтвердили за
`confirm_timeout_s` и т. п.). Исход `black_ice` — это `NET_FLATLINE` (раздел 2.4), `NET_EXIT` для него **не** пишется. Кто читает:
журнал, статистика исходов, счётчик «локдаунов узлов».

```json
{"id": "w:net.run:k3f9a2xq:4977:s_9f2c41d07a3e5b60", "subjectKeyB64": "<world_pub>", "seq": 421, "happenedAt": 1790000900000,
 "field": "net.run", "oldValue": null,
 "newValue": "{\"session\":\"s_9f2c41d07a3e5b60\",\"runner\":\"MFkwEwYH…\",\"callsign\":\"Призрак\",\"terminal\":\"t03\",\"node\":\"node_07\",\"outcome\":\"emergency\",\"duration_s\":400,\"returned\":2,\"burned\":1,\"left_in_node\":1,\"eddies_paid\":0,\"lockdown_until\":0}",
 "reason": "NET_EXIT", "sourceRef": "s_9f2c41d07a3e5b60", "actor": "<world_pub>", "signature": "…"}
```

`outcome` — `clean|emergency|soft_ice|aborted`; `returned/burned/left_in_node` — число предметов по ветвям `moves`;
`eddies_paid` — эдди, ушедшие на телефон (сумма совпадает с `TRANSFER_IN` на телефоне, это сверка, а не движение денег);
`lockdown_until` — для `soft_ice` (из `ValueOps`: `now + soft_ice_reentry_pause_s`).

### 2.4 Флэтлайн: `net.run` / `NET_FLATLINE`

Когда: `run.finish` с исходом `black_ice` (в `ValueOps.updateRunnerAfterFinish` в той же транзакции ставятся `runner.blocked` и
тревога `kind=flatline`). Кто читает: **коллектор должен поставить флаг нетраннера «заблокирован»** (его проверяет M2 до
`op.submit_deck`, netrun.md «Вход», п. 4) и показать мастеру карточку «ФЛЭТЛАЙН»; снимает флаг мастер (разбан, «пощадить»).

```json
{"id": "w:net.run:k3f9a2xq:4977:s_9f2c41d07a3e5b60", "subjectKeyB64": "<world_pub>", "seq": 421, "happenedAt": 1790000900000,
 "field": "net.run", "oldValue": null,
 "newValue": "{\"session\":\"s_9f2c41d07a3e5b60\",\"runner\":\"MFkwEwYH…\",\"callsign\":\"Призрак\",\"terminal\":\"t03\",\"node\":\"node_07\",\"outcome\":\"black_ice\",\"disconnect\":false,\"duration_s\":400,\"left_in_node\":3,\"cause\":\"флэтлайн\",\"alert\":\"al_431_0\"}",
 "reason": "NET_FLATLINE", "sourceRef": "s_9f2c41d07a3e5b60", "actor": "<world_pub>", "signature": "…"}
```

`disconnect: true` — «обрыв до флэтлайна» (в `cause` — `"обрыв до флэтлайна"`); `alert` — id документа тревоги Моста.
Одна запись на сессию (одно закрытие): `NET_EXIT` и `NET_FLATLINE` для одной сессии взаимоисключающи.

### 2.5 Смена владельца предмета: `net.item` / `NET_ITEM_OWNER`

Когда: **только значимые** для игры переходы, не каждый `put` документа `item` (иначе шум): (а) предмет попал в `node:` как
«оставленная добыча» или «мёртвая дека» (`leave_in_node`, `run.finish` → `node`); (б) предмет **взят** из узла (`take_from_node`);
(в) предмет **сгорел** (`burned:`); (г) предмет ушёл из Сети (`phone:`, то есть чек получен). Переходы `inbox → deck` и
`deck → outbox` внутри забега не пишутся (они видны как `NET_ENTER` / `NET_EXIT` и записи телефона). Кто читает: карточка предмета
на дашборде («где копия»: у игрока, в узле, сгорел), расследование «куда делся шард», аудит.

```json
{"id": "w:net.item:k3f9a2xq:4977:it_4c1a0b2e9d7f6a81", "subjectKeyB64": "<world_pub>", "seq": 422, "happenedAt": 1790000900000,
 "field": "net.item", "oldValue": null,
 "newValue": "{\"item\":\"it_4c1a0b2e9d7f6a81\",\"kind\":\"SHARD\",\"from\":\"deck:s_9f2c41d07a3e5b60\",\"to\":\"node:node_07\",\"session\":\"s_9f2c41d07a3e5b60\",\"runner\":\"MFkwEwYH…\",\"op\":\"run.finish\",\"rid\":\"finish:s_9f2c41d07a3e5b60\"}",
 "reason": "NET_ITEM_OWNER", "sourceRef": "it_4c1a0b2e9d7f6a81", "actor": "<world_pub>", "signature": "…"}
```

`from`/`to` — значения `owner` из C1 (раздел 5); `op` — `take_from_node|leave_in_node|run.finish|issue_to_phone`; `rid` — для
сопоставления с повтором. Эдди **не** пишутся этой записью: у них нет документа предмета, а выплата — Handover.

### 2.6 Тревога аудитора: `net.alert` / `NET_ALERT`

Когда: Мост создал документ `alert` (`Auditor.run`, `ValueOps.updateRunnerAfterFinish`). Реально возникают виды (код Моста):

| `kind` в документе | Источник | Смысл |
|---|---|---|
| `flatline` | `ValueOps` (`al_<seq>_<n>`) | флэтлайн; для коллектора это уже `NET_FLATLINE`, отдельная запись `NET_ALERT` **не** дублируется |
| `auditor_item_owner` | `Auditor.checkItem` (`al_a_<hash12>`) | у предмета нет/неверный владелец |
| `auditor_deck_items` | `Auditor.checkDecks` | `deck.items` не совпадает с предметами-владельцами; предметы в деке закрытой сессии |
| `auditor_eddies` | `Auditor.checkEddies` | эдди в минус, закрытая сессия держит эдди, выплата ≤ 0 |
| `auditor_dead` | `Auditor.raiseDeadAlert` | аудитор не работает N проходов подряд |

(Тревоги сервера мира, документ `alert` с `al_<n>`, тоже проходят этим путём; виды — в G/N-карточках. Документы `alert` видов `master_request` и `net_query` — вызовы панели мастера («ждём мастера», «запрос к Сети») — записью не становятся.) Кто читает: «внимание»
мастера (`lib/attention*` на коллекторе) — это единственные записи мира, на которые мастер должен реагировать сразу.

```json
{"id": "w:net.alert:k3f9a2xq:4902:al_a_3f9c1e07b2d4", "subjectKeyB64": "<world_pub>", "seq": 430, "happenedAt": 1790000700000,
 "field": "net.alert", "oldValue": null,
 "newValue": "{\"alert\":\"al_a_3f9c1e07b2d4\",\"kind\":\"auditor_item_owner\",\"msg\":\"it_02bb: владелец deck:s_9f2c, но сессия закрыта\",\"items\":[\"it_02bb\"]}",
 "reason": "NET_ALERT", "sourceRef": "al_a_3f9c1e07b2d4", "actor": "<world_pub>", "signature": "…"}
```

Тревога снимается мастером на Мосте (документ меняется/удаляется); отдельной записи о снятии нет. Новая тревога на то же
расхождение, пока документ жив, не создаётся (id документа от `kind|subject`, `Auditor.kt:115`), значит запись одна. Если мастер
снял тревогу, а расхождение живо, аудитор создаёт документ заново (тот же id, `ver = 1`): это второе появление, у него своя транзакция,
значит своя запись и свой `id` (`txSeq` другой). Запись пишется только при создании документа; правка существующей тревоги записи не даёт.

## 3. Быстрые события на точки площадки

Назначение (netrun.md «Архитектура», «Два пути к коллектору»): эффект на площадке, где важна мгновенность — свет, звук, экран
точки. Данные они **не меняют**, потеряться могут без вреда; решающее остаётся в записях раздела 2.

- **Транспорт.** Мост → коллектор: `POST /api/world-events`, заголовок `X-Game-Secret` (как у `/api/changes`,
  `lib/gameSecret.ts`), тело `{"events": [ … ]}`. Эндпоинта сейчас **нет** (раздел 5, п. 3). Ответ `200 {"accepted": n}`, при
  недоступности — **ничего не копить**: события живы ≈ 5 с (`ttl_ms`), Мост делает одну повторную попытку и забывает.
  Очереди и `Outbox` не используются; события из очереди после обрыва не «догоняются» (иначе сирена зазвучит через минуту).
- **Событие**:

```json
{"id": "ev_7d1c0a", "kind": "trace.hunt", "ts": 1790000650000, "ttl_ms": 5000,
 "node": "node_07", "terminal": "t03", "session": "s_9f2c41d07a3e5b60", "level": "TRACE"}
```

Поля: `id` (уникален, коллектор отбрасывает повтор), `kind`, `ts`, `ttl_ms`, `node`, `terminal` (null, если не про терминал),
`session` (null — без сессии), `level` (уровень trace, только для `trace.*`). Позывной в событие не кладётся (GHOST: правила
сигнала СБ те же, что у `SecAlertStore.decide`, и принадлежат B2/правилам, а не событию).

| `kind` | Когда | Кому (точки) | Что делает |
|---|---|---|---|
| `run.enter` | сессия стала `active` (курок) | терминал `t` | фон «в Сети» на точке терминала; экран точки — «<номер> в Сети» |
| `run.exit` | сессия закрылась (любой исход) | терминал `t` | вернуть фон и экран ожидания |
| `trace.level` | смена уровня trace (SUSPICIOUS→TRACE→LOCKDOWN) | терминал `t` + точки узла `node` | звук/свет по уровню; на TRACE — номер терминала на экран СБ-точки |
| `ice.hunt` | проснулся Black ICE / охота началась | точки узла `node` (если `NIGHTMARE`) | «исчезновение фона» (netrun.md, «Обнаружение»), тихий звук |
| `flatline` | исход `black_ice` | терминал `t`, точки узла | отдельный звук/кадр; мастеру — карточка (запись `NET_FLATLINE`) |
| `lockdown` | узел ушёл в локдаун (`soft_ice` или правило) | точки узла `node` | сирена/свет узла, конец — по `lockdown_until` |
| `alert.master` | новая тревога аудитора | только панель мастера | звонок мастеру, **не** на площадку |

«Кому» определяет **коллектор**, а не Мост: Мост знает `node` и `terminal`, а привязку точек (дисплей ↔ узел, группы, звук) держит
коллектор (`routes/displays.ts` — `/api/displays/:id/node`, `/api/display-groups`; `routes/audio.ts` — каналы/клипы). Как «что»
отображается — настраивает мастер таблицей «событие → клип/картинка/группа точек»; по умолчанию события ничего не делают.
Существующие эндпоинты требуют сессии мастера (`requireMaster`: `routes/audio.ts:237-240`, `routes/displays.ts:354-357`) —
машинные события через них идти не могут, отсюда запрос M7.

Единственное событие, у которого уже есть путь в записях, — флэтлайн: он идёт **и** быстро, **и** надёжно (`NET_FLATLINE`);
если быстрое событие потерялось, точка не прозвучит, но флаг и карточка мастера не пропадут.

## 4. Что рождает запись и событие

| Что происходит в Мосте | Запись синка | Быстрое событие |
|---|---|---|
| `op.submit_deck` → сессия `pending` | `NET_ENTER` | — |
| курок → `active` | — | `run.enter` |
| смена уровня trace (сервер мира) | — | `trace.level` |
| охота Black ICE | — | `ice.hunt` |
| `run.finish` clean/emergency/soft_ice/aborted | `NET_EXIT`, `NET_ITEM_OWNER` (по значимым предметам) | `run.exit` (+`lockdown` при soft_ice) |
| `run.finish` black_ice | `NET_FLATLINE`, `NET_ITEM_OWNER` (мёртвая дека) | `flatline`, `run.exit` |
| `take_from_node`, `leave_in_node` | `NET_ITEM_OWNER` | — |
| тревога аудитора | `NET_ALERT` | `alert.master` |
| эдди на телефон | — (карточка Handover; запись `TRANSFER_IN` пишет телефон) | — |

## 5. Запрос к сессии коллектора (M7)

## 6. Что неясно

- **Флаг при разбане со стороны Моста.** Мост ставит `runner.blocked` сам (`ValueOps`), коллектор — флаг по `NET_FLATLINE`;
  «пощадить» мастер делает в одном месте. **Решение владельца: источник правды — коллектор**, Мост читает его флаг (п. 4);
  `runner.blocked` в Мосте остаётся быстрой защитой до ответа коллектора.
- **Сигнал СБ** (`SEC//MB10`, netrun.md «Обнаружение») идёт в чате фракции правилом B2, а не записью мира; номер терминала в нём
  нужен, но это сообщение, не запись коллектору — вне этого документа.
- **Нужна ли отдельная запись о подтверждении курком** (`pending → active`) для мастера — пока нет (видно по терминалу).
- Тревоги сервера мира (`alert` с `al_<n>`): виды определят G/N-карточки; формат записи `net.alert` их вместит (`kind`, `msg`, `items`).

## 7. Как это сделано в Мосте (M4)

Код — `netrun-bridge/src/main/kotlin/com/megablok10/netrun/bridge/collector/`. Операции с ценностями о записях **не знают**: расширение
коммита `DocStore` (`CommitHook`) в той же транзакции SQLite сравнивает документы «до» и «после» (`WorldRecordDeriver`), подписывает
события ключом мира и кладёт в таблицу `world_records` (kit `ChangeQueue`; `seq` — строка `world_record_seq` в `meta`). Откат
транзакции откатывает и записи; повтор операции по `rid` документов не меняет, значит записей нет. Отправляет kit `SyncEngine`
(`WorldSync`), HTTP — `WorldCollectorTransport` на `java.net.http`; подтверждённые записи 6 часов лежат в журнале (`accepted_at`) и
возвращаются, если коллектор сообщил меньший `knownSeq`.

| Запись | Рождается, когда в транзакции… |
|---|---|
| `NET_ENTER` | создан документ `session` в `pending`; `deck`/`protected` — из документа `deck` этой же транзакции |
| `NET_EXIT` / `NET_FLATLINE` | `session` стал `closed` (`black_ice` — флэтлайн); `returned/burned/left_in_node` — по предметам, вышедшим из `deck:<s>` в `outbox:`/`burned:`/`node:`; `node` — текущий (`world.node`, иначе узел входа); `duration_s` — от курка (`confirmed_at`, нет — от создания) до `finished_at`; `lockdown_until` — из документа узла (только `soft_ice`); `alert` — тревога `flatline` этой же транзакции |
| `NET_ITEM_OWNER` | `item.owner` сменился на значимый переход (раздел 2.5); `op`/`rid` — из документа `op_rid` этой транзакции |
| `NET_ALERT` | создан документ `alert` любого вида, кроме `flatline` (он уже `NET_FLATLINE`), `master_request` и `net_query` (вызовы мастера) |

Решения при чтении C2, которых текст не фиксировал: (1) чек телефона (`outbox → phone:`) идёт без операции — пишется `op = issue_to_phone`,
`rid` = id карточки (`out_transfer`); (2) `master.unstock_node` (`→ burned:master`) пишется как «сгорел» с `op = master.unstock_node`, а создание
предмета в узле (`master.stock_node`) — нет; (3) тревоги `master_request` и `net_query` (MasterOps) — тоже `alert`-документы, но это звонок панели мастера («ждём мастера», «запрос к Сети»), а не тревога аудитора: `NET_ALERT` для них не пишется (M4b), документы остаются;
(4) `id` = `w:<field>:<epoch>:<txSeq>:<sourceRef>` (M4b). Прежний вариант с `ver` документа (`w:<field>:<sourceRef>:<ver>`) ломался дважды:
после сброса базы Моста при том же ключе мира `ver` снова с 1 (те же `id`, коллектор отвечает `id already used by a different record`),
а тревога, снятая мастером и поднятая аудитором заново, получала прежний `id` с `ver = 1` — `WorldRecorder` отбрасывал её как повтор,
а после очистки журнала (6 часов) коллектор отверг бы её; kit удаляет отвергнутое. Теперь `txSeq` — номер транзакции хранилища
(`Change.seq`, общий для всех документов транзакции, растёт монотонно и хранится в `meta.seq`), `epoch` — случайные 8 символов `0-9a-z`,
строка `epoch` в `meta` той же SQLite: создаётся при первой инициализации файла (у базы, созданной до M4b, — при первом открытии после
обновления; записи в её очереди остаются со старыми `id`) и не меняется при перезапуске. Одно событие — одна транзакция — один `id`;
повтор отправки записи из очереди `id` не меняет. Одна транзакция не даёт двух событий с одним `field` и `sourceRef`, поэтому
пара (`txSeq`, `sourceRef`) уникальна внутри поля.
(5) `seq` записей (подписанный номер у ключа мира) у свежей базы начинается не с 1: ключ мира лежит в отдельном файле (`<db>.worldkey`) и
переживает удаление файла базы, а коллектор отвечает `seq already used by a different record` на номер, уже занятый у этого ключа
(`changeIngest.ts:203`; kit удаляет такие записи, потеряно было бы всё, включая флэтлайн). Ключ менять нельзя: на нём доверие телефонов и
`world_pub`. Поэтому при первой инициализации пустой очереди (`world_records` без строк и без счётчика `world_record_seq` в `meta`) счётчик
встаёт на время в секундах; первая запись получает это значение плюс 1. Непрерывность `seq` коллектору не нужна (он проверяет только целое
и уникальность у ключа), записей единицы в минуту, значит номер новой базы заведомо выше любого номера прежней. База, где записи есть, а
счётчика нет, продолжает с `MAX(seq)`; база со счётчиком его не меняет; перезапуск `seq` не пересчитывает. Номера подряд внутри базы
сохраняются, поэтому «дыры» в `seq` у ключа возможны только на стыке двух баз.

Запуск: `--collector http://хост:порт`, секрет игры — `NETRUN_COLLECTOR_SECRET` (тот же, что `GAME_SECRET` коллектора). Без флага Мост
записи всё равно ставит в очередь (она переживает рестарт) и отправит, когда коллектор появится. Перед отправкой транспорт читает
открытый `GET /api/capabilities` и шлёт, только если `world_records` равен 1 (раздел 5, п. 5); иначе очередь стоит, а повтор идёт по
бэкоффу `SyncEngine`. Быстрые события на точки (раздел 3) в M4 не входят.
