# QR персонажа: первый запуск одним кодом

Мастер выдаёт каждому игроку **один QR**, и на первом запуске приложения он делает всё сразу: настраивает сервер и код игры и создаёт персонажа (позывной, фракция, стартовый баланс, ёмкость буфера). Игрок ничего не вводит руками. Код действует **один раз**; повторно его можно применить только после сброса сессии, и новый код выдаёт мастер.

Приложение (`qr/ProvisionStore.kt`) уже умеет принимать такой QR. Генерация кода в «Мастерской» и проверка одноразовости на сервере — сторона коллектора (`admin-web/`), см. раздел «Что нужно от коллектора».

## Формат

```
MB10:PROV:v1:<id>:<b64 url>:<b64 secret>:<b64 callsign>:<b64 faction>:<balance>:<ram>
```

| Поле | Значение |
|---|---|
| `id` | уникальный номер выдачи: буквы, цифры, `-`, `_`, до 64 символов (например UUID без служебных знаков) |
| `url` | адрес сервера мастера, например `http://<адрес>:2517`; пусто — оставить адрес из сборки приложения (`mb10.collectorUrl`) |
| `secret` | код игры (`GAME_SECRET`); пусто — не менять |
| `callsign` | позывной, 1–40 символов |
| `faction` | фракция, до 40 символов (может быть пустой) |
| `balance` | стартовый баланс, целое 0…1 000 000; приложение устанавливает баланс **ровно таким**, а не прибавляет |
| `ram` | ёмкость буфера 6…13; `0` — по умолчанию |

Текстовые поля (`url`, `secret`, `callsign`, `faction`) кодируются base64 (стандартный алфавит, с `=`), как и в остальных QR Мегаблока, чтобы двоеточия и кириллица не ломали разбор. Числа пишутся открытым текстом. Кодек: `Mb10QrCodec.encodeProvision` / `decodeProvision` в `app/src/main/java/com/megablok10/app/qr/Mb10Qr.kt`; правила проверки: `ProvisionRules`.

## Что делает приложение

1. Первый запуск (личности нет) показывает экран «Сканировать QR персонажа». Ручного создания персонажа нет ни в одной раздаваемой сборке, включая debug-APK из CI; разработчик без мастера включает его в своей сборке: `mb10.allowManualSetup=true` в `local.properties` (форма появляется ниже кнопки сканирования).
2. Проверка кода (`ProvisionRules`) и отказ, если: личность уже есть; этот `id` на этом телефоне уже применяли (сообщение «Этот код уже использован. Попросите мастера выдать новый»).
3. Сохраняет адрес сервера и код игры, помечает настройки «выдано мастером» (в Профиль → «Сеть» они становятся только для чтения).
4. Создаёт личность (ключи генерируются на телефоне), отправляет записи `CHARACTER_CREATED`: позывной, фракция, ёмкость буфера (если задана), баланс (если задан) с `sourceRef = id`.
5. Сброс сессии (Профиль → «Настройки» → «Опасная зона» → «Сбросить сессию персонажа») стирает личность и снимает блокировку настроек. Использованные `id` при этом **не забываются**: тот же QR второй раз не примется, нужен новый.

## Что нужно от коллектора

Статус: пункты 1–3 **выполнены** (`POST/GET /api/provisions`, `GET /api/provisions/:id/qr`, `POST /api/players/:key/reissue`; форма «Персонаж» в «Мастерской»; при применении копии сервер отвечает `provision code already applied on another device`, при погашенном коде `provision code is no longer valid (issued again)`, на дашборде тревога `provision_conflict`). Проверено сценариями `scenarios-anomaly/provision-*.sh` и `zz-provisioning.sh` (реальное приложение принимает QR, выданный сервером). Пункт 4 (подпись QR ключом мастера) **не сделан**, ждёт решения организатора. Внешний адрес сервера для QR берётся из `PUBLIC_URL`. Как приложение реагирует на отказ сервера: показывает «Код персонажа уже использован или заменён. Обратитесь к мастеру» и держит плашку в Профиль → «Сеть» до сброса сессии; запись не повторяется (иначе синхронизация зациклилась бы).

1. **Генерация** в «Мастерской» (вкладка, где мастер создаёт контейнеры и шарды): форма «Персонаж» (позывной, фракция, стартовый баланс, RAM), адрес сервера и код игры подставляются из настроек сервера, `id` создаёт сервер (UUID). Результат — строка QR по формату выше (кодек-близнец есть в `admin-web/server/src/lib/mb10QrCodec.ts`) и картинка QR для печати или показа с экрана.
2. **Одноразовость на сервере** (страхует от копирования кода): сервер помнит выданные `id` и привязывает `id` к публичному ключу первого телефона, приславшего запись `CHARACTER_CREATED` с `sourceRef = id`. Второй телефон с тем же `id` получает отказ (запись отклоняется с понятной причиной), на дашборде появляется тревога «Код персонажа применили на двух телефонах». Тот же ключ повторно — не ошибка (переотправка).
3. **Выдача заново после сброса сессии**: кнопка «Выдать заново» у игрока на дашборде создаёт новый `id` (старый погашен). Это то самое «повторно только после сброса сессии».
4. **Опционально, вторая очередь**: подпись QR ключом мастера, чтобы игрок не мог напечатать «свой» код и указать чужой сервер или чужой код игры. Понадобится публичный ключ мастера, зашитый в сборку (`mb10.masterPublicKey`), и проверка подписи на первом запуске. Пока код не подписан: его подделка требует доступа к принтеру или экрану мастера.

## Ввод кода без камеры

Если у телефона нет камеры (решение владельца 19.10), под кнопкой сканирования есть «Нет камеры? Ввести код». Коллектор выдаёт рядом с QR короткий код из 6 знаков, печатается как `ABC-DEF`; алфавит — `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (31 знак, без I, L, O и цифр 0, 1). Общие векторы нормализации и показа — `rules/src/test/resources/contracts/provision-code.json`; их читают приложение и коллектор (`contractProvisionCode.test.ts`).

- **Приложение** нормализует ввод (верхний регистр, пробелы и «-» выбрасываются); если это не ровно 6 знаков алфавита, на сервер не идёт ничего — неверные попытки жгут его лимит (`ProvisionCode`). Сам код в журнал не пишется.
- **Обмен**: `POST {baseUrl}/api/provisions/redeem {"code":"ABCDEF"}` без авторизации → `200 {"qr":"MB10:PROV:v1:…"}` — ровно строка из `GET /api/provisions/:id/qr`, дальше как со сканером (`Mb10QrCodec` → `ProvisionStore.apply`). `404 {"error":"unknown_code"}` — нет такого, уже применён или перевыдан (не различаем). `429 {"error":"rate_limited","retryAfterSec":N}` (и заголовок `retry-after`) — лимит по адресу и общий потолок приложение обрабатывает одинаково.
- **Одноразовость** остаётся за `bindProvision` при применении: сам обмен код не гасит, повтор до применения допустим; применённый или перевыданный код отвечает 404. Код уникален среди непогашенных выдач и хранится в `provisions.short_code`.
- **Защита от подбора** (`lib/redeemLimiter.ts`): 5 неверных подряд с одного IP — пауза 5 минут; общий потолок неверных в час на весь сервер — 100 (`REDEEM_GLOBAL_PER_HOUR`), тогда 429 всем и тревога мастеру «Перебор коротких кодов». Пока лимит сработал, код не проверяется — ответ не подсказывает, верный он или нет. Цена: двое злоумышленников с разных адресов могут закрыть ввод кода для всех на час; QR камерой работает как раньше.
- **Мастер** видит код в списке выдач и в панели QR («код без камеры: ABC-DEF»). `GET /api/capabilities` объявляет `provisionCode: 1`.
- **Адрес сервера** приложение берёт из настроек (сборка или прошлая выдача), иначе игрок вводит его в поле «Адрес сервера»; если в выданном QR адрес пуст, подставляется тот, по которому достучались.
- **Старый сервер**: 404 без тела ошибки, иной код или битый ответ — маршрута нет, приложение пишет «Сервер не поддерживает ввод кода — отсканируйте QR» (`RedeemResult.Unsupported`).

## Сброс сессии

«Сбросить сессию персонажа» возвращает телефон к чистой установке: стираются ключи и **все игровые данные устройства** (кошелёк, предметы, переписка, контакты, остывания и т. д.), чтобы игрок не нашёл остатков и они не мешали новому QR. Персонаж как набор данных остаётся у мастера и выдаётся заново. Подробности и что нужно от сервера — [character-reissue.md](character-reissue.md). Стартовый баланс из QR всё равно задаётся как «установить N».
