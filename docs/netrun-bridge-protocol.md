# Протокол Моста «Сеть» (контракт C1)

Контракт между Мостом (`:netrun-bridge`) и его клиентами по WebSocket: сервер мира (Godot), инструменты мастера, фейки
(F1). Телефон с Мостом по WebSocket не говорит — только карточками kit `Handover` (раздел 8). По этому документу пишутся
B0 (хранилище), B1 (WebSocket), B3 (операции с ценностями), F1 (фейки), V2 (токен терминала), M2/M3/M5.

Версия протокола — **1** (`NETRUN_PROTO = 1`). Она не связана с `WireVersion` приложения: канал телефона живёт по своим
версиям kit.

## 1. Транспорт

- `ws://<мини-ПК>:7410/netrun/v1` (порт — в конфиге Моста; на площадке мини-ПК в LAN, TLS нет — дружеская модель угроз).
- Один текстовый кадр — одно JSON-сообщение в UTF-8. Бинарные кадры — ошибка `bad_request` и закрытие.
- Время — миллисекунды Unix (`Long`), ставит **только Мост**. Числа — целые; JSON без `NaN`.
- Пинг — кадры WebSocket ping/pong: клиент раз в 10 с; Мост закрывает соединение после 30 с тишины. Подписки при обрыве
  пропадают — после переподключения клиент делает `hello` и `sub` заново (получит снимок, раздел 4).
- Неизвестные поля в сообщениях и в `data` игнорируются (вперёд-совместимость); неизвестный `op` — ошибка `bad_request`.

## 2. Конверт

Запрос клиента:

```json
{"v": 1, "cid": "w-1842", "op": "get", "type": "node", "id": "node_07"}
```

| Поле | Что |
|---|---|
| `v` | версия протокола, всегда 1 |
| `cid` | номер запроса в рамках соединения, любая строка ≤ 64 символов; Мост возвращает его в `re`. Для сопоставления ответа, **не** для защиты от повтора |
| `op` | операция (разделы 3–7) |

Ответ — ровно один на каждый запрос, в порядке обработки (не обязательно в порядке отправки):

```json
{"v": 1, "re": "w-1842", "ok": true, "doc": {"type": "node", "id": "node_07", "ver": 12, "created": 1790000000000, "updated": 1790000412000, "data": {"tier": "STANDARD"}}}
```

Ошибка:

```json
{"v": 1, "re": "w-1843", "ok": false, "err": {"code": "version_conflict", "msg": "версия 12, а не 11", "doc": {"type": "node", "id": "node_07", "ver": 12, "created": 1790000000000, "updated": 1790000412000, "data": {"tier": "STANDARD"}}}}
```

Сообщение от Моста без запроса (поток изменений) — без `re`, с `push`:

```json
{"v": 1, "push": "chg", "seq": 50231, "doc": {"type": "session", "id": "s_9f2c", "ver": 3, "created": 1790000500000, "updated": 1790000530000, "data": {"state": "active"}}}
```

### Коды ошибок

| `code` | Когда | Что делать клиенту |
|---|---|---|
| `bad_request` | не JSON, нет поля, неверный тип, неизвестный `op` | ошибка в коде клиента, не повторять |
| `unsupported_version` | `v` или `proto` в `hello` не поддержан; соединение закрывается | обновить сборку |
| `unauthorized` | нет `hello` или неверный ключ роли | — |
| `forbidden` | роли эта операция не разрешена (раздел 3) | — |
| `not_found` | документа нет | — |
| `exists` | создание (`ver: 0`), а документ уже есть; в `err.doc` — текущий | перечитать |
| `version_conflict` | `ver` не совпал; в `err.doc` — текущий | перечитать, применить правку заново |
| `value_field` | общий `put`/`del` трогает ценность или тип `item`, `deck`, `payout`, `op_rid` (раздел 5) | использовать операцию из раздела 6 |
| `wrong_owner` | предмет сейчас не у того владельца, что ждёт операция; в `err.doc` — предмет | перечитать, это не повод повторять с новым `rid` |
| `protected_item` | операция уводит защищённого демона не на телефон | ошибка логики сервера мира |
| `session_state` | сессия не в нужном состоянии (например, `take` в закрытой) | перечитать сессию |
| `rid_mismatch` | `rid` уже использован с **другими** параметрами; ничего не сделано | ошибка в коде клиента |
| `req_state` | `master.decide` по уже решённому запросу другим решением (раздел 6a); в `err.doc` — запрос | показать мастеру итог |
| `bad_token` | токен терминала не сошёлся | очки не пускать |
| `internal` | сбой Моста; транзакция откатилась целиком | повторить **тот же** запрос (с тем же `rid`) |

## 3. Вход: `hello`, роли

Первое сообщение после подключения — `hello`. До него любой другой `op` → `unauthorized`.

```json
{"v": 1, "cid": "1", "op": "hello", "proto": 1, "role": "world", "client": "world-main", "key": "k8w2…"}
```

```json
{"v": 1, "re": "1", "ok": true, "proto": 1, "bridge": "0.3.0", "now": 1790000000000, "world_pub": "MFkwEwYH…"}
```

- `key` — общий секрет роли из конфига Моста (`roles.world.key`, `roles.master.key`); на площадке лежит в конфиге сервера
  мира и инструментов мастера. Модель угроз дружеская: это защита от ошибки, а не от взлома.
- `client` — имя клиента; вместе с ролью — пространство имён `rid` (раздел 6): `world-main` и `master-anna` не пересекутся.
- `world_pub` — публичный ключ мира (получатель карточек на телефоне).

| Операция | `world` (сервер мира) | `master` (инструменты) | `test` (фейки, только если Мост запущен с `--test`) |
|---|---|---|---|
| `get`, `list`, `sub`, `unsub` | да | да | да |
| `put`, `del` (кроме ценностей) | типы `node`, `session` (только `data.world`), `alert` | все типы | все |
| `terminal.auth`, `session.confirm`, `session.abort` | да | `session.abort` | да |
| `terminal.beat` | да | нет | да |
| `op.take_from_node`, `op.leave_in_node`, `op.issue_to_phone`, `run.finish` | да | да (ручной запуск — «кнопка раньше автоматики») | да |
| `master.pause`, `master.link`, `master.goal`, `master.goal_clear`, `master.template_apply` | нет | да | да |
| `master.decide`, `master.reply` | нет | да | да |
| `master.gate`, `net.query` | да | да | да |
| `op.submit_deck` | нет | нет | да (у настоящего Моста его вызывает только приём карточек с телефона, раздел 8) |

## 4. Документы: чтение, запись, подписка

### Схема документа

```json
{"type": "node", "id": "node_07", "ver": 12, "created": 1790000000000, "updated": 1790000412000, "data": {}}
```

| Поле | Что |
|---|---|
| `type` | тип, `[a-z_]{1,32}` (раздел 5) |
| `id` | `[A-Za-z0-9_.:-]{1,64}`; пара `type`+`id` уникальна; одинаковый `id` в разных типах связывает их (`node/node_07` и `node_cfg/node_07`) |
| `ver` | целое ≥ 1; +1 на **каждое** изменение (общим `put` или операцией с ценностью) |
| `created`, `updated` | время Моста; `updated` — по нему видно, что источник замолчал |
| `data` | JSON-объект; схема — по типу (раздел 5) |

### `get`

```json
{"v": 1, "cid": "2", "op": "get", "type": "terminal", "id": "t03"}
```
```json
{"v": 1, "re": "2", "ok": true, "doc": {"type": "terminal", "id": "t03", "ver": 4, "created": 1790000000000, "updated": 1790000300000, "data": {"node": "node_07", "label": "Подвал, стойка 3"}}}
```

Нет документа — `not_found`.

### `list` — все документы типа

```json
{"v": 1, "cid": "3", "op": "list", "type": "node"}
```
```json
{"v": 1, "re": "3", "ok": true, "seq": 50230, "docs": [{"type": "node", "id": "node_07", "ver": 12, "created": 1790000000000, "updated": 1790000412000, "data": {"tier": "STANDARD"}}]}
```

Фильтров нет (масштаб — сотни документов). `seq` — номер последнего изменения в Мосте на момент снимка.

### `put` — запись с проверкой версии

`ver` — версия, которую клиент видел; `0` — создать (документа быть не должно). `data` заменяется **целиком**.

```json
{"v": 1, "cid": "4", "op": "put", "type": "node", "id": "node_07", "ver": 12, "data": {"tier": "STANDARD", "lockdown_until": 1790000900000}}
```
```json
{"v": 1, "re": "4", "ok": true, "doc": {"type": "node", "id": "node_07", "ver": 13, "created": 1790000000000, "updated": 1790000420000, "data": {"tier": "STANDARD", "lockdown_until": 1790000900000}}}
```

Версия устарела — `version_conflict` с текущим документом; клиент перечитывает и решает заново. Повтор `put` после обрыва
безопасен: если первая запись прошла, второй придёт `version_conflict`, и по `err.doc` видно, что правка уже там.

### `del`

```json
{"v": 1, "cid": "5", "op": "del", "type": "alert", "id": "al_17", "ver": 2}
```
```json
{"v": 1, "re": "5", "ok": true}
```

### `sub` / `unsub` — поток изменений

```json
{"v": 1, "cid": "6", "op": "sub", "types": ["node", "session", "item", "terminal", "settings"]}
```
```json
{"v": 1, "re": "6", "ok": true, "seq": 50230, "docs": [{"type": "node", "id": "node_07", "ver": 13, "created": 1790000000000, "updated": 1790000420000, "data": {"tier": "STANDARD"}}]}
```

- Ответ — снимок всех документов этих типов на `seq`; затем каждое изменение с `seq` больше снимка приходит пушем `chg`
  (полный документ после изменения). Удаление — `chg` с `"deleted": true` и последней версией документа.
- `seq` — сквозной счётчик изменений Моста, хранится в SQLite, после перезапуска продолжается. Изменения одной транзакции
  (операция с ценностью трогает несколько документов) приходят подряд с одним `seq` и полем `"last": true` у последнего —
  клиент применяет их пачкой.
- Порядок пушей совпадает с порядком `seq`. Ответ на `sub` приходит раньше любого `chg` с большим `seq`.
- Повторный `sub` в том же соединении добавляет типы (новый снимок только по ним). `unsub` `{"types": [...]}` — убрать.
- Пропусков не бывает, пока соединение живо. После обрыва — `hello` + `sub` заново, снимок заменяет всё, что было у клиента.
  Так же сервер мира берёт состояние после своего перезапуска (M5).

Два кадра одной транзакции:

```text
{"v": 1, "push": "chg", "seq": 50231, "last": false, "doc": {"type": "item", "id": "it_4c1a", "ver": 3, "created": 1790000500000, "updated": 1790000530000, "data": {"owner": "deck:s_9f2c", "kind": "SHARD", "payload": "…", "protected": false, "origin": "node:node_07"}}}
{"v": 1, "push": "chg", "seq": 50231, "last": true, "doc": {"type": "deck", "id": "s_9f2c", "ver": 4, "created": 1790000500000, "updated": 1790000530000, "data": {"items": ["it_01aa", "it_02bb", "it_4c1a"], "protected": "it_01aa"}}}
```

## 5. Типы документов (этапы 0–4)

«Ценность» — поле, которое меняется только операциями раздела 6; общий `put`/`del`, который его меняет (или создаёт/удаляет
документ целиком помеченного типа), получает `value_field`.

| Тип | `id` | Кто пишет | Ценность |
|---|---|---|---|
| `node` | `node_07` | мастер, сервер мира | `eddies` |
| `node_cfg` | как у узла | мастер | — |
| `terminal` | `t03` | мастер; `terminal.beat` сервера мира | — |
| `session` | `s_<16 hex>` | Мост; сервер мира — только `data.world` | весь документ, кроме `data.world` |
| `deck` | как у сессии | только Мост | весь документ |
| `item` | `it_<16 hex>` | только Мост | весь документ |
| `runner` | ключ игрока (base64url без `=`) | Мост, мастер | — |
| `settings` | `global`, `rules`, … | мастер | — |
| `alert` | `al_<n>` | Мост (аудитор, раздел 6a), сервер мира; снимает мастер | — |
| `master_req`, `net_query` | `<вид>:<ссылка>`, `nq_<n>` | только Мост (раздел 6a) | — |
| `template` | `tpl_<имя>` | мастер | — |

**`node`** — постоянное состояние узла.
```json
{"type": "node", "id": "node_07", "ver": 13, "created": 1790000000000, "updated": 1790000420000,
 "data": {"title": "Склад «Арасаки»", "tier": "STANDARD", "tutorial": false, "lockdown_until": 0, "eddies": 300}}
```
`tier` — как `Tier` приложения (`NIGHTMARE` и т. д.); `lockdown_until` — 0 или время конца локдауна; `eddies` — запас эдди в
узле (ценность, меняет только `op.take_from_node`). Предметы узла — документы `item` с `owner: "node:node_07"`.

**`node_cfg`** — числа и наполнение для правил и сервера мира (ICE, пороги). Схема свободная, её задают G/N-карточки.
```json
{"type": "node_cfg", "id": "node_07", "ver": 2, "created": 1790000000000, "updated": 1790000100000, "data": {"ice": [{"kind": "SOFT", "at": [3, 0, 7]}], "trace_per_s": 2}}
```

**`terminal`** — стойка с очками.
```json
{"type": "terminal", "id": "t03", "ver": 4, "created": 1790000000000, "updated": 1790000300000,
 "data": {"label": "Подвал, стойка 3", "node": "node_07", "token_sha256": "9b1f…", "silent": false}}
```
`token_sha256` — SHA-256 токена очков в hex (сам токен в документ не попадает, раздел 7). `silent` — флаг правила B2
«терминал молчит».

**`session`** — один забег одного игрока на одном терминале.
```json
{"type": "session", "id": "s_9f2c41d07a3e5b60", "ver": 3, "created": 1790000500000, "updated": 1790000530000,
 "data": {"state": "active", "terminal": "t03", "node": "node_07", "runner": "MFkwEwYH…", "callsign": "Призрак",
          "enter_rid": "e-7d1c", "confirmed_at": 1790000530000, "loot_eddies": 0,
          "outcome": null, "finished_at": 0, "world": {"connected": true, "trace": 0}}}
```
Состояния: `pending` (дека сдана, очки показывают «Подключается: <позывной>») → `active` (курок нажат) → `closed`
(`outcome`: `clean` | `emergency` | `soft_ice` | `black_ice` | `aborted`). Одна сессия не в `closed` на терминал и на игрока.
`world` — свободный объект сервера мира (подключён ли, trace): его можно писать `put`, остальное — нет.

**`deck`** — что игрок принёс и что несёт сейчас; производный от `item.owner`, держится Мостом в той же транзакции.
```json
{"type": "deck", "id": "s_9f2c41d07a3e5b60", "ver": 4, "created": 1790000500000, "updated": 1790000530000,
 "data": {"items": ["it_01aa", "it_02bb", "it_4c1a"], "protected": "it_01aa"}}
```

**`item`** — предмет внутри Сети.
```json
{"type": "item", "id": "it_02bb7c90e1d4a3f5", "ver": 2, "created": 1790000500000, "updated": 1790000500000,
 "data": {"owner": "deck:s_9f2c41d07a3e5b60", "kind": "DAEMON", "payload": "<строка ItemPayload как в карточке>",
          "protected": false, "origin": "phone:MFkwEwYH…", "in_transfer": "tr_88e1", "out_transfer": null, "handover": null}}
```
- `payload` — строка содержимого из карточки (`ItemPayload`) **байт в байт**; менять её никто не вправе.
- `daemon` / `shard` (M5b) — разбор `payload` для сервера мира, который формата карточки не знает. Мост пишет поле сам: при
  приёме карточки (`op.submit_deck`-путь, раздел 8) и при старте — документам без поля (принятым раньше), через `:rules`
  `ItemPayloadCodec`. Не разобралось — поля нет. Для `kind: "DAEMON"` — `"daemon": {"effect": "GHOST", "tier": 2,
  "name": "Призрак", "cells": ["1C", "BD"]}` (`effect` — имя `DaemonEffect`, `tier` — 1..3, `cells` — цепочка кодов).
  Для `kind: "SHARD"` — `"shard": {"tier": 1, "title": "…", "decrypted": true}` (тело и сумма не выносятся). Сервер мира
  берёт параметры эффекта по уровню из своих данных (`netrun/data/daemons/effects/<ЭФФЕКТ>.json`); эффект, которого в Сети
  ещё нет, — демон в деке виден, но применение отвечает `effect_unsupported` с причиной.
- `owner` — ровно один, из списка:

| `owner` | Значит |
|---|---|
| `inbox:<ключ>` | карточка с телефона принята (чек отправлен), деку ещё не собрали |
| `deck:<сессия>` | в деке забега (принесённое и взятое в узле) |
| `node:<узел>` | лежит в узле (наполнение, оставленная добыча, «мёртвая дека») |
| `outbox:<ключ>` | выдаётся на телефон: карточка Handover в пути; `handover` — `PENDING`/`DELIVERED` |
| `phone:<ключ>` | чек получен — предмет ушёл из Сети; документ остаётся для журнала и аудитора |
| `burned:<сессия>` | сгорел (аварийный выход под охотой Black ICE); документ остаётся |

**`runner`** — нетраннер с точки зрения Сети.
```json
{"type": "runner", "id": "MFkwEwYH…", "ver": 5, "created": 1789990000000, "updated": 1790000600000,
 "data": {"callsign": "Призрак", "blocked": false, "blocked_reason": null, "runs": 3, "tutorial_done": true}}
```
`blocked` ставит Мост при `black_ice`, снимает мастер. `tutorial_done: false` — первый вход идёт в учебный узел.

**`settings`** — числа правил и Моста; мастер правит на ходу.
```json
{"type": "settings", "id": "global", "ver": 7, "created": 1789990000000, "updated": 1790000000000,
 "data": {"confirm_timeout_s": 120, "inbox_timeout_s": 300, "disconnect_grace_s": 20, "soft_ice_reentry_pause_s": 600,
          "terminal_silent_s": 30, "auditor_period_s": 60, "tutorial_node": "node_00"}}
```

**`alert`** — тревога для дашборда (аудитор, сервер мира).
```json
{"type": "alert", "id": "al_17", "ver": 1, "created": 1790000700000, "updated": 1790000700000,
 "data": {"kind": "item_owner", "msg": "it_02bb: владелец deck:s_9f2c, но сессия закрыта", "items": ["it_02bb"]}}
```

## 6. Операции с ценностями

Общие правила для `op.*` и `run.finish`:

- **`rid`** — номер запроса, строка ≤ 128 символов, уникальна в пространстве `role/client`. Мост хранит `rid` вместе с
  параметрами и ответом (в той же транзакции, что и изменения, — в SQLite, бессрочно на сезон).
- **Повтор** с тем же `rid` и теми же параметрами не выполняется второй раз: возвращается сохранённый ответ с
  `"replayed": true` (даже если с тех пор документы изменились). Тот же `rid` с другими параметрами — `rid_mismatch`, ничего
  не сделано. Ответ с ошибкой (`wrong_owner`, `session_state`…) тоже сохраняется и повторяется; `internal` и `bad_request` — нет
  (транзакции не было).
- **Обрыв.** Не получил ответа — после переподключения отправить **тот же** запрос с тем же `rid`; новый `rid` для того же
  намерения запрещён. Сервер мира одноразовый, поэтому `rid` строит **детерминированно** из того, что переживёт его
  перезапуск: `take:<сессия>:<предмет>`, `leave:<сессия>:<предмет>`, `finish:<сессия>`. Тогда после рестарта он может
  повторить запрос вслепую, а снимок `sub` и так покажет итог.
- Каждая операция — **одна транзакция**: все документы (`item`, `deck`, `session`, `node`) меняются вместе или никак; их
  `chg` приходят с одним `seq`. Ошибка посреди — откат целиком, предмет остаётся у прежнего владельца.
- Ни одна операция не создаёт и не уничтожает документ `item`, кроме `op.submit_deck` (создаёт из принятой карточки).
  `burned` и `phone` — тоже владельцы, документ остаётся. Аудитор (`settings.auditor_period_s`) проверяет: у каждого `item`
  ровно один владелец из таблицы; `deck:<s>` — только у не закрытой сессии `s`; `deck.items` = предметы с `owner: deck:<s>`;
  `outbox` без исходящей карточки не бывает. Расхождение → документ `alert`.
- Защищённый демон (`protected: true`) может уйти только в `outbox`/`phone` своего владельца. Любая другая цель —
  `protected_item`.

### 6.1 `op.submit_deck` — сдать деку

Вызывает приём карточек телефона (раздел 8), когда пришёл подписанный запрос входа и все перечисленные в нём карточки уже
приняты (лежат в `inbox:<ключ>`). По WebSocket — только роль `test`.

```json
{"v": 1, "cid": "40", "op": "op.submit_deck", "rid": "enter:e-7d1c", "runner": "MFkwEwYH…", "callsign": "Призрак",
 "terminal": "t03", "items": ["it_01aa7c90e1d4a3f5", "it_02bb7c90e1d4a3f5"], "protected": "it_01aa7c90e1d4a3f5"}
```
```json
{"v": 1, "re": "40", "ok": true, "replayed": false, "session": "s_9f2c41d07a3e5b60", "state": "pending"}
```

Проверки: `runner` не `blocked`; нет его открытой сессии; терминал свободен; узел терминала не в локдауне (иначе
`session_state`); все `items` — `inbox:<runner>`; `protected` ∈ `items`. Итог: `session` в `pending` (узел — учебный, если
`tutorial_done: false`), `deck`, предметы → `deck:<сессия>`. **Отказ** (любая проверка) — предметы остаются в `inbox`, и Мост
сам выдаёт их обратно на телефон (`op.issue_to_phone` с `rid` `refund:<rid входа>`): дека, сданная на занятый терминал, не
застревает. **Повтор**: тот же ответ, вторая сессия не создаётся. **Обрыв**: запрос внутренний, ответ уходит на телефон
чеком на запрос входа (раздел 8); телефон, не получивший чека, шлёт запрос входа заново с тем же `rid`.

Сессия в `pending` дольше `confirm_timeout_s` или `session.abort` → `closed`/`aborted`, вся дека → на телефон.

### 6.2 `op.take_from_node` — взять из узла

Сервер мира: игрок взял шард (или эдди MINER-ом).

```json
{"v": 1, "cid": "41", "op": "op.take_from_node", "rid": "take:s_9f2c41d07a3e5b60:it_4c1a0b2e9d7f6a81",
 "session": "s_9f2c41d07a3e5b60", "node": "node_07", "item": "it_4c1a0b2e9d7f6a81"}
```
```json
{"v": 1, "re": "41", "ok": true, "replayed": false, "item": {"type": "item", "id": "it_4c1a0b2e9d7f6a81", "ver": 3, "created": 1790000000000, "updated": 1790000600000, "data": {"owner": "deck:s_9f2c41d07a3e5b60", "kind": "SHARD", "payload": "…", "protected": false, "origin": "node:node_07", "in_transfer": null, "out_transfer": null, "handover": null}}}
```

Эдди — вместо `item` поле `"eddies": 50`: `node.eddies` −50, `session.loot_eddies` +50; запаса меньше — `wrong_owner`.

Проверки: сессия `active`; предмет `node:<node>`. Иначе — `session_state`/`wrong_owner` (в `err.doc` — где предмет сейчас:
двое схватили один шард — второй получает `wrong_owner` с `owner: deck:<первый>`). **Повтор**: тот же ответ, предмет не
«берётся» второй раз. **Обрыв**: повторить с тем же `rid`; если сервер мира перезапустился — тот же детерминированный `rid`.

### 6.3 `op.leave_in_node` — оставить в узле

Сервер мира: игрок бросил предмет, или при исходе добыча/«мёртвая дека» остаётся в узле.

```json
{"v": 1, "cid": "42", "op": "op.leave_in_node", "rid": "leave:s_9f2c41d07a3e5b60:it_4c1a0b2e9d7f6a81",
 "session": "s_9f2c41d07a3e5b60", "node": "node_07", "item": "it_4c1a0b2e9d7f6a81"}
```
```json
{"v": 1, "re": "42", "ok": true, "replayed": false, "item": {"type": "item", "id": "it_4c1a0b2e9d7f6a81", "ver": 4, "created": 1790000000000, "updated": 1790000650000, "data": {"owner": "node:node_07", "kind": "SHARD", "payload": "…", "protected": false, "origin": "node:node_07", "in_transfer": null, "out_transfer": null, "handover": null}}}
```

Проверки: предмет `deck:<session>`; не `protected` (`protected_item`); сессия не `closed`. **Повтор** и **обрыв** — как 6.2.

### 6.4 `op.issue_to_phone` — выдать на телефон

Предметы из деки (или из `inbox` при отказе входа, или из узла — ручная выдача мастером) и эдди уходят на телефон
карточками Handover от ключа мира.

```json
{"v": 1, "cid": "43", "op": "op.issue_to_phone", "rid": "master-anna:give:17", "runner": "MFkwEwYH…",
 "items": ["it_4c1a0b2e9d7f6a81"], "eddies": 0, "reason": "ручная выдача"}
```
```json
{"v": 1, "re": "43", "ok": true, "replayed": false, "transfers": [{"item": "it_4c1a0b2e9d7f6a81", "transfer": "tr_c0de11"}], "eddies_transfer": null}
```

В одной транзакции: предметы → `outbox:<runner>`, `handover: PENDING`, `out_transfer` — id новой исходящей карточки; карточки
кладутся в `Outbox` Моста (kit). Дальше — обычный `Handover`: `deliver` ставит `DELIVERED` до отправки, откат в `PENDING`
только при `NOT_REACHED`; **`UNKNOWN` не повторяется по другому адресу и не откатывается**; по чеку (`confirmByReceipt`)
предмет → `phone:<runner>`. Адрес телефона — из подсказок коллектора и статического пира, отправка — через `PeerDirectory`.
Эдди — денежная карточка от ключа мира на `eddies` (эмиссия). **Повтор**: тот же ответ, вторых карточек нет. **Обрыв**:
ответ мог не дойти, но карточки уже в `Outbox` и доставятся; повторить с тем же `rid`. Ответ `ok` значит «выдача записана»,
а не «телефон получил» — это видно по `item.owner`.

### 6.5 `run.finish` — исход забега

Сервер мира закрывает сессию одним вызовом: какие предметы куда. Это пачка операций 6.3/6.4 и сгорания в одной транзакции —
чтобы рестарт сервера мира посреди выхода не оставил сессию наполовину разобранной.

```json
{"v": 1, "cid": "44", "op": "run.finish", "rid": "finish:s_9f2c41d07a3e5b60", "session": "s_9f2c41d07a3e5b60",
 "outcome": "emergency", "node": "node_07", "disconnect": false,
 "moves": [{"item": "it_02bb7c90e1d4a3f5", "to": "phone"}, {"item": "it_4c1a0b2e9d7f6a81", "to": "node"}]}
```
```json
{"v": 1, "re": "44", "ok": true, "replayed": false, "session": {"type": "session", "id": "s_9f2c41d07a3e5b60", "ver": 6, "created": 1790000500000, "updated": 1790000900000, "data": {"state": "closed", "outcome": "emergency", "finished_at": 1790000900000}},
 "transfers": [{"item": "it_01aa7c90e1d4a3f5", "transfer": "tr_a1"}, {"item": "it_02bb7c90e1d4a3f5", "transfer": "tr_a2"}], "eddies_transfer": null}
```

- `to`: `phone` (как 6.4), `node` (как 6.3, в узел `node`), `burned`.
- Мост сам добавляет защищённого демона в `phone` и требует, чтобы после `moves` дека была пуста: предмет из деки, не
  упомянутый в `moves`, — `bad_request`, ничего не сделано.
- Мост проверяет `moves` по таблице исходов из netrun.md («Забег»): добыча (`origin: node:*`) при `clean` — только `phone`, при
  остальных — только `node`; демоны при `black_ice` — только `node` («мёртвая дека»), при `emergency` — `phone` или `burned`
  (сервер мира знает, была ли охота), при `clean`/`soft_ice` — только `phone`. Нарушение — `bad_request`.
- `loot_eddies` уходят на телефон только при `clean`, иначе возвращаются в `node.eddies`.
- Побочные изменения той же транзакции: `soft_ice` → `node.lockdown_until`; `black_ice` → `runner.blocked`, `alert`
  «ФЛЭТЛАЙН» (`disconnect: true` — «обрыв до флэтлайна»); `runner.runs` +1, `tutorial_done: true`.
- **Повтор**: тот же ответ. **Обрыв**: повторить `finish:<сессия>`; если сессия уже `closed` другим `rid` — `session_state`
  с документом сессии (исход уже записан).

## 6a. Инструменты мастера (роль `master`)

«Кнопка раньше автоматики» (`docs/netrun.md`, «Устройство Моста»): каждая ручная операция — сообщение ниже; правила Моста
(`MasterRules`) вызывают те же методы, а не пишут документы мимо них. Роль проверяется: `master.*` из `world` — `forbidden`;
`test` разрешён везде (фейки). Операции задают состояние, поэтому повтор безопасен и без `rid`; единственное исключение —
сообщения канала (`mid`). Все ответы — `{"doc": …}` изменённого документа, если не сказано иное. Каждая — одна транзакция.

**Пауза Сети.** `{"op": "master.pause", "on": true, "node": "node_07"}`; без `node` — вся Сеть. Пишет `settings/global.paused`
(+ `paused_at`) или `node_cfg/<узел>.paused`; узла нет — `not_found`. Сервер мира перед шагом ICE и trace читает оба флага:
пауза узла = `settings.global.paused` **или** `node_cfg.<узел>.paused` (`MasterOps.isPaused`); на паузе ICE и trace замирают.
При снятии паузы сроки активных целей (`goal.deadline`) сдвигаются на время паузы; на паузе цели не срабатывают.

**Рубильник связи с площадкой.** `{"op": "master.link", "on": false}` → `settings/global.venue_link` (по умолчанию `true`).
Пока `false`, быстрые события на точки (`netrun-world-records.md`, раздел 3) не отправляются; записи синка и данные мира это
не затрагивает (`MasterOps.venueLinkOn`).

**Цели и сроки узла.** `{"op": "master.goal", "node": "node_07", "kind": "open", "value": 120, "in_s": 600}` (или абсолютный
`"deadline": <мс>`). Пишет `node_cfg/<узел>.goal = {kind, value, deadline, set_at, done, result}`; новая цель заменяет прежнюю,
`master.goal_clear` (`node`) убирает. Правила используют цель вместо сырых чисел: `open` — к сроку снять локдаун узла;
`lockdown` — к сроку закрыть узел на `value` секунд (по умолчанию `soft_ice_reentry_pause_s`), критический шаг — через
«ждём мастера» ниже. Остальные `kind` (`trace`, `ice`, …) читает сервер мира: «к значению `value` примерно к `deadline`».
Выполненная цель получает `done: true` и `result` (`applied` | `denied` | `no_node`). `eddies` узла автоматика не трогает.

**«Ждём мастера».** Перед критическим шагом (`flatline`, `lockdown`, `nightmare`, …) сервер мира или правило спрашивает
`{"op": "master.gate", "kind": "flatline", "ref": "<сессия>", "node": "node_07", "summary": "ФЛЭТЛАЙН: Призрак"}`. Ответ
`{"mode": "auto" | "wait" | "decided", "decision": "approve" | "deny" | null, "req": <документ master_req> | null}`:

- `auto` — для вида выключено (`settings.global.await_<kind>` ≠ 1): применять исход сразу;
- `wait` — создан (или ещё не решён) запрос `master_req/<kind>:<ref>`, исход **не применять**, повторить вызов позже; при
  создании поднимается тревога `master_request` (панель мастера звонит);
- `decided` — мастер решил (`master.decide`) или вышел срок; поступать по `decision`.

`master_req.data`: `kind`, `ref`, `node`, `summary`, `state` (`pending` | `decided`), `default`, `expires_at`, `decision`,
`decided_by` (`master` | `timeout`), `decided_at`. Срок — `settings.global.await_timeout_s` (по умолчанию 60), действие по
таймауту — `await_default_<kind>` (`approve` | `deny`, по умолчанию `approve`); таймаут решает правило `master_req_timeout`
(раз в `master_poll_s`, по умолчанию 1 с), а также любое обращение к просроченному запросу. Новый шаг — новый `ref` (иначе
вернётся старое решение). Ничего в Мосте не убивает персонажа само: флэтлайн по-прежнему применяет вызывающий после `decided`.
Решение: `{"op": "master.decide", "req": "flatline:s_1", "decision": "approve"}`; то же решение повторно — тот же ответ,
другое (или опоздавшее после таймаута) — `req_state`. Автоматика (`bridge`) решать за мастера не может.

**Заготовки.** Документы `template/<id>` (мастер пишет обычным `put`): `{"title", "settings": {…}, "node_cfg": {…}}`.
`{"op": "master.template_apply", "template": "tpl_night", "nodes": ["node_07", "node_08"]}` — одна транзакция: `settings`
сливается в `settings/global` (`world_pub` игнорируется; пишется `template_applied = {id, at}`), `node_cfg` — в
`node_cfg/<узел>` каждого узла. Нет заготовки или узла — `not_found`, ничего не записано; `node_cfg` без `nodes` — `bad_request`.
Ответ: `{"template", "nodes", "settings": [ключи]}`.

**Запрос к Сети.** Канал мастер ↔ нетраннер — документы `net_query/nq_<n>`: `{"runner", "state": "open" | "answered",
"messages": [{"mid", "from": "runner" | "master", "text", "at"}]}`.
`{"op": "net.query", "runner": "Призрак", "mid": "m1", "text": "Где шард?"}` (роли `world`, `master`, `test`; `query` — id,
чтобы дописать в существующий, иначе создаётся новый и поднимается тревога `net_query`) и
`{"op": "master.reply", "query": "nq_5", "mid": "r1", "text": "…"}` (ответ → `answered`). Повтор с тем же `mid` не дублирует
сообщение; текст ≤ 2000 символов.

## 7. Терминал и сессия игрока

Очки не знают ни ключей, ни Моста. В конфиге приложения очков (кладётся через adb при установке стойки) — `terminal` и
`token` (32 случайных байта, base64url). Мастер создаёт документ `terminal` с `token_sha256` этого токена.

1. Очки → сервер мира по ENet: в `auth_callback` — `{"terminal": "t03", "token": "…"}`.
2. Сервер мира → Мост `terminal.auth`:

```json
{"v": 1, "cid": "50", "op": "terminal.auth", "terminal": "t03", "token": "q3Zb…"}
```
```json
{"v": 1, "re": "50", "ok": true, "terminal": {"type": "terminal", "id": "t03", "ver": 4, "created": 1790000000000, "updated": 1790000300000, "data": {"node": "node_07", "label": "Подвал, стойка 3", "token_sha256": "9b1f…", "silent": false}}, "session": null}
```

   `ok: false`, `bad_token` — сервер мира отказывает в `auth_callback`. `session` — открытая сессия терминала (`pending`
   или `active`) или `null` (экран ожидания с внеигровыми правилами). Результат не кешируется: проверка дешёвая.
3. Появилась `pending`-сессия на этот терминал (сервер мира видит её в `sub` на `session`) — очки показывают «Подключается:
   <`callsign`>». Курок → сервер мира:

```json
{"v": 1, "cid": "51", "op": "session.confirm", "session": "s_9f2c41d07a3e5b60", "terminal": "t03"}
```
```json
{"v": 1, "re": "51", "ok": true, "session": {"type": "session", "id": "s_9f2c41d07a3e5b60", "ver": 3, "created": 1790000500000, "updated": 1790000530000, "data": {"state": "active", "confirmed_at": 1790000530000}}}
```

   Идемпотентна по состоянию: уже `active` — тот же ответ; `closed` — `session_state`. Отказ игрока или таймаут:

```json
{"v": 1, "cid": "52", "op": "session.abort", "session": "s_9f2c41d07a3e5b60", "reason": "отказ в очках"}
```
```json
{"v": 1, "re": "52", "ok": true, "session": {"type": "session", "id": "s_9f2c41d07a3e5b60", "ver": 3, "created": 1790000500000, "updated": 1790000560000, "data": {"state": "closed", "outcome": "aborted"}}}
```

   Только из `pending`; дека — на телефон (как 6.4, `rid` `abort:<сессия>`). Повтор — тот же ответ.
   **Heartbeat терминала.** Сервер мира раз в несколько секунд (рекомендуется 5 с) шлёт `terminal.beat` — он обновляет документ
   `terminal`, а правило «терминал молчит» (`terminal_silent_s`) считает молчание по его `updated`. Поля, кроме `terminal`,
   необязательны: `battery` (заряд очков, %), `fps` (кадры в секунду), `link` (качество связи, 0–100); все целые.

```json
{"v": 1, "cid": "53", "op": "terminal.beat", "terminal": "t03", "battery": 80, "fps": 72, "link": 95}
```
```json
{"v": 1, "re": "53", "ok": true, "ver": 5}
```

   Мост пишет в документ `data.battery`/`fps`/`link` (если пришли) и `data.beat_at` (время Моста, меняется на каждый вызов), флаг
   `silent` не трогает. Нет терминала — `not_found`. Роли: `world`, `test`.
4. **Игрок — это сессия, не peer id.** Сервер мира хранит `сессия → peer`; переподключение очков с новым peer id проходит шаг 2
   и получает ту же `active`-сессию → тот же аватар (`node_07/avatar_<сессия>`). 20 с после обрыва (`disconnect_grace_s`)
   отсчитывает сервер мира, затем `run.finish` с `outcome: emergency` и `disconnect: true`. Состояние связи сервер мира пишет в
   `session.data.world` через `put`.

## 8. Канал телефона (для M2/M3)

**QR стойки** (печатается мастером на стойке терминала, читается приложением как любой другой QR Мегаблока, `Mb10QrCodec`):
`MB10:RACK:v1:<терминал>:<base64 host:port>:<world_pub>[:<base64 подпись>]`. `терминал` — id документа `terminal` (`t03`); адрес Моста —
порт `--line-port`, в base64, чтобы двоеточие IPv6 не ломало разбор; `world_pub` — публичный ключ мира как в `settings.global.world_pub`
(стандартный base64 без двоеточий); подпись для игрока («Подвал, стойка 3») необязательна. Телефон запоминает ключ и адрес (статический
пир `PeerTable`) и принимает от этого ключа добычу и эдди без «Принять».

Телефон и Мост — участники kit: Мост держит сервер строк как у приложения, телефон шлёт на адрес из QR стойки (статический
пир) **обычные карточки предметов** (`SendItem`, получатель — `world_pub`), каждая с чеком по `HandoverRules`
(`rejectIncoming`, чек `id|ключ`). Принятый предмет — документ `item` с `owner: inbox:<ключ>`, `in_transfer` = id карточки;
повтор карточки отсекает журнал входящих Моста (тот же `in_transfer` — второй документ не создаётся, чек повторяется).

Транспорт — тот же, что у телефонов (kit `LineServer` с конвертом `MB10TO` и квитанцией `MB10ACK`, `PeerTable`/`PeerDirectory`):
Мост слушает порт `--line-port` (по умолчанию 7411; телефон берёт адрес из QR стойки), а адрес телефона узнаёт из порта в
конверте его строк или из статической записи. Карточка едет телом личного сообщения `MB10CHAT` (как между телефонами), Мост отвечает
чеком тоже личным сообщением. Ключ мира — пара ECDSA в файле `<база>.worldkey` (создаётся при первом старте), публичная часть —
`settings.global.world_pub` и `world_pub` в `hello`; `--world-pub` теперь только сверка (не совпадает с файлом — Мост не стартует).

После карточек телефон шлёт **запрос входа** — подписанную ключом игрока строку `MB10ENTER:v1:<rid>:<терминал>:<ключ>:<base64
позывной>:<transfers через запятую>:<protected_transfer>:<ts>:<подпись>` (подпись — над `ENTER1|rid|терминал|ключ|позывной|
transfers|protected|ts`; в `WireVersion` приложения — `ENTER`, `ENTERED`, кодек — `netrun/NetrunWire.kt`, близнец `PhoneWire` Моста), содержимое — такое:

```json
{"rid": "e-7d1c", "terminal": "t03", "runner": "MFkwEwYH…", "callsign": "Призрак",
 "transfers": ["tr_88e1", "tr_88e2"], "protected_transfer": "tr_88e1", "ts": 1790000499000, "sig": "MEUCIQ…"}
```

Мост ждёт, пока все `transfers` придут в `inbox` (не дольше `inbox_timeout_s`), и зовёт `op.submit_deck` с
`rid: enter:<rid>`. Ответ на телефон — подписанный ключом мира результат: `{"rid": "e-7d1c", "ok": true, "session": "s_9f2c…"}`
или `{"rid": "e-7d1c", "ok": false, "code": "session_state", "msg": "терминал занят"}` (дека в этом случае уже выдаётся
обратно). Телефон без ответа повторяет запрос с тем же `rid`. Карточки в `inbox` без запроса входа дольше `inbox_timeout_s` —
обратно на телефон (`rid` `refund:<in_transfer>`). Флаг нетраннера (коллектор) проверяет M2 до `op.submit_deck`.

На проводе ответ — строка `MB10ENTERED:v1:<rid>:<1|0>:<base64 сессия>:<base64 code>:<base64 msg>:<подпись ключа мира>` (подпись над
`ENTERED1|rid|ok|сессия|code|msg`), отправляется телефону тем же транспортом без повторов: потерялась — телефон повторит запрос, Мост
ответит из сохранённого результата по `rid`. Флаг заблокированного нетраннера из коллектора (M4) Мост пока не читает: действует только
`runner.blocked` в документах Моста (его ставит `black_ice`).

## 9. Что не входит

Записи для коллектора и быстрые события на точки — C2 (`docs/netrun-world-records.md`). Каталог событий Сети и правила
(B2) — свои документы; здесь только то, что ходит по WebSocket.
