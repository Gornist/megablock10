# Бриф для сессии коллектора: «Сеть» со стороны `admin-web/`

Этот документ — задание для сессии, которая ведёт коллектор и дашборд мастера (`admin-web/`). Остальные части «Сети»
сделаны в другой сессии на ветке `agent/netrun`. В `main` их пока нет, поэтому документы читайте оттуда:
`git show agent/netrun:docs/<файл>`.

## Что такое «Сеть» — коротко

Нетраннер садится у стойки-терминала, телефоном сдаёт «деку» демонов и в VR-очках проходит узлы киберпространства.
Добыча возвращается на телефон. Части:

- **Мост** (`:netrun-bridge`, Kotlin, на том же мини-ПК). Он хранит состояние Сети документами, держит ключ мира
  и обменивается с телефонами карточками с квитанциями — как ещё один участник игры. API Моста — WebSocket
  `ws://<сервер>:<порт>/netrun/v1`, роль `master` для мастера.
- **Сервер мира** (Godot) и **очки** с коллектором напрямую не говорят.
- **Коллектор** остаётся тем же: синк записей с телефонов. Центральным хранилищем Сети он не становится.

Документы на ветке `agent/netrun`:

- `docs/netrun.md` — план. Нужны разделы «Решения владельца», «Инструменты мастера», «Кто что делает».
- `docs/netrun-bridge-protocol.md` — протокол Моста. Нужны разделы 2–5 (конверт, роли, документы, подписка),
  6.5 (`run.finish`), **6a (инструменты мастера)** и 7 (терминал и сессия).
- `docs/netrun-world-records.md` — записи мира в синк коллектора. **Раздел 5 — ваш список задач (M7)**.

## Что нужно от коллектора

Задачи по порядку важности. Можно делать по одной, каждая полезна сама по себе.

### 1. Принимать записи мира (M7)

Сейчас коллектор отбрасывает записи с незнакомым `field`/`reason` в `rejected` (`admin-web/server/src/lib/changeIngest.ts`,
около строк 106–108). При этом kit удаляет запись из очереди, и она теряется молча. Поэтому Мост не начнёт писать
записи мира, пока коллектор их не понимает.

- Принимать поля `net.run`, `net.item`, `net.alert` и причины `NET_ENTER`, `NET_EXIT`, `NET_FLATLINE`, `NET_ITEM_OWNER`,
  `NET_ALERT`. Формат и примеры JSON — в `netrun-world-records.md`, раздел 2.
- В проекции персонажей эти записи **не учитывать**. `subject` у них — ключ мира, а не игрок; мир не должен появиться
  в списке персонажей.
- Признак «коллектор понимает записи мира», чтобы Мост мог проверить его до отправки. Предложение — в разделе 5 того же
  документа.

### 2. Быстрые события на точки площадки

`POST /api/world-events` с `X-Game-Secret`, без очереди. Семь видов событий: `run.enter`, `run.exit`, `trace.level`,
`ice.hunt`, `flatline`, `lockdown`, `alert.master` (раздел 3 `netrun-world-records.md`). Какие дисплеи и звуки получают
событие, решает коллектор. Нужна настройка «узел Сети ↔ точка площадки».

### 3. Получатели сигнала СБ — документ `settings/sec` для Моста

Мост сам шлёт фракции СБ сигнал `SEC//MB10`, когда нетраннер дошёл до уровня TRACE: тем же форматом, что телефон-взломщик,
с номером терминала. Но ключи телефонов по фракциям знает только коллектор. Нужен способ передать Мосту документ:

```json
{ "factions": { "<фракция>": ["<ключ телефона>", "…"] }, "default_faction": "<фракция СБ>" }
```

Ещё нужно поле `owner_faction` у документа узла (`node`), если владелец узла задаётся мастером. Простейший путь — коллектор
пишет эти документы в Мост через `put` с ролью `master` при старте и при изменении персонажей. Пока документа нет,
сигнал СБ никуда не уходит.

### 4. Экран «Сеть» для мастера (P8)

Всё есть в API Моста (роль `master`, раздел 6a протокола). Экран только показывает и вызывает:

- **Узлы:** состояние, цель и срок (`master.goal`), локдаун, пауза (`master.pause` — вся Сеть или узел).
- **Нетраннеры в Сети:** сессии, уровень trace, дека.
- **Терминалы и очки:** документ `terminal` — `battery`, `fps`, `link`, `beat_at`. Флаг `silent` означает, что очки молчат.
- **Рубильник связи с площадкой:** `master.link`.
- **«Ждём мастера»:** документы `master_req` (флэтлайн, локдаун) с кнопками решения `master.decide`. По таймауту
  применяется действие по умолчанию, это решает Мост.
- **Карточка флэтлайна.** Тревога `alert` вида «ФЛЭТЛАЙН». Решение владельца: **«пощадить» решает коллектор, он источник
  правды**, Мост читает его флаг (раздел 2.4 и 6 `netrun-world-records.md`). Программа никогда не убивает персонажа сама.
- **Тревоги аудитора:** `alert` вида `auditor_*` — рассинхрон предметов; мастеру важно увидеть сразу.
- **«Запрос к Сети»:** канал `net_query` и ответ `master.reply`.
- **Заготовки:** документы `template/*`, применяются через `master.template_apply`.
- **Флаг нетраннера на персонаже:** кто может входить в Сеть. Он же — блокировка после флэтлайна (`runner.blocked`
  в Мосте и флаг в коллекторе).

### 5. Наполнение узлов из «Мастерской»

Шарды и демоны для узлов. Не горит: сейчас Мост наполняется тестовым `--seed`.

## Ограничения и правила

- Работать только в `admin-web/`. Протокол Моста и записи мира — контракт: если что-то в нём неудобно, не обходите,
  а напишите в основную сессию (`agent/netrun`), там поправят протокол.
- Совместимость: текущие телефоны и текущий Мост должны продолжать работать. Новый коллектор не должен ломать старый синк.
- Интернета на площадке нет: никаких внешних зависимостей.
- UI — из общих компонентов дизайн-системы, рамки скошенные, элементы компактные.
- Тяжёлые проверки (сборка, e2e) — на машине разработки devbox по скиллу `.claude/skills/devbox/`.
- Мост можно поднять на devbox для ручной проверки: `netrun/tools/live_run.sh` на ветке `agent/netrun` показывает, как его
  запускать с `--test --seed`.
