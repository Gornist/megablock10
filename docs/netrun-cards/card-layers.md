# Карточка LAYERS — «Панели и текст как слои композитора OpenXR» (по плану для владельца: чёткие прямые линии/текст как в лобби Pico)

Рабочая копия/ветка: **`~/Developer/megablock10-wt/gd-layers`**, `agent/gd-layers` — стоит на ветке PR #110 (`agent/gd-aa`: там `shared/render_config.gd`, [render] в netrun.cfg). Правила — `rules-godot.md`. Sonnet, коммит на шаг, зелёные тесты. Зона: `netrun/client/`, `netrun/shared/`, `netrun/tests/`. НЕ трогать `netrun/assets/`, `docs/gamedesign/`, `scripts/e2e/`.

## Зачем
Сейчас 2D-панели (дека/телефон, взлом, итог забега) — `SubViewport` + 3D-квад (Sprite3D) в eye-буфере: проходят дисторсию и растеризацию 2160 px/глаз, прямые линии и текст «пилят». OpenXR composition layer (Godot 4.3+: `OpenXRCompositionLayerQuad`, свойства `layer_viewport`, `quad_size`, `alpha_blend`, `sort_order`, метод `is_natively_supported()`, `intersects_ray()`) рисует тот же вьюпорт компоситором в разрешении дисплея — как лобби Pico. Версия Godot проекта 4.7.2.

## Досье
- Панели: `client/ui/deck_panel.gd` (SubViewport VIEW_SIZE, `_viewport.render_target_update_mode`, показ на квадe — найди как: Sprite3D/MeshInstance3D с `ViewportTexture`), `client/ui/breach_panel.gd` (768×512, Sprite3D), итог — `client/ui/end_screen.gd` (проверь, SubViewport или Label3D), указка/нажатия — `client/ui/deck_pointer.gd` + `shared/deck_pointer_math.gd` (пересечение луча руки с плоскостью панели → координаты во вьюпорте).
- XR-вход: `client/xr_rig.gd:start_xr()` (флаг `xr_active`), конфиг — `RenderConfig` (`shared/render_config.gd`, секция [render], применение в `xr_rig.gd`).
- Данных про то, как панель позиционируется относительно головы/руки, нет — смотри код; панель лежит в 3D как Node3D, слой должен повторять её `global_transform`.

## Шаги
1. **L1 — ключ `layers`:** в `RenderConfig` ключ `layers` = "on" | "off" (по умолчанию **"off"** — включаем по слову владельца после проверки на очках), чистый маппинг + тесты (как для aa/fringe), в строку журнала `render … layers=…`.
2. **L2 — хост слоя:** новый `client/ui/xr_layer_host.gd` (`class_name XrLayerHost`, extends Node3D): `setup(viewport: SubViewport, size_m: Vector2, face: Node3D)`; создаёт `OpenXRCompositionLayerQuad` (дочерний узел), `layer_viewport = viewport`, `quad_size = size_m`, `alpha_blend = true` (панели полупрозрачные: transparent_bg), `sort_order` по умолчанию; каждый кадр (или в `_process`) копирует `face.global_transform` в слой (слой и 3D-квад совпадают); включается ТОЛЬКО если `xr_active` (проверь XRServer/интерфейс OpenXR initialized), `layers == on` и `OpenXRCompositionLayerQuad` существует и `is_natively_supported()`; иначе остаётся прежний 3D-квад (ничего не меняется). Когда слой активен — 3D-квад панели скрывается визуально (visible=false у меша/спрайта; указка использует математику плоскости, а не меш — убедись, что `deck_pointer` не зависит от видимости; если зависит от физики/AABB — оставь невидимый меш `layers_mask`/`transparency=1`, не удаляй). Тест (без XR): хост без XR/при off не создаёт слой и не прячет квад; при включении через «фальшивый» путь — только логика выбора (вынеси `static func should_use_layer(xr: bool, cfg_on: bool, supported: bool) -> bool` и тестируй её).
3. **L3 — подключить панели:** deck_panel (+ телефон/вкладки в ней), breach_panel, итог забега — через `XrLayerHost`; размеры в метрах берутся из существующих констант панели (ширина/высота квада). Указка/нажатия должны работать как раньше (ray ↔ плоскость ↔ координаты вьюпорта). Если у end_screen Label3D, а не SubViewport — НЕ переделывай, опиши в отчёте.
4. Проверки: `dev.sh test` по затронутым (render_config_test, deck_*test, breach_*test, deck_pointer*, node_scene_test, новые) + `dev.sh test --all` в фоне; `scripts/zone-check.sh godot`. Вид и работа слоя на Pico не проверяются на devbox — в отчёте так и написать.
