# Юзабилити приложения игрока: причины и текущее состояние

Веб-интерфейс мастера ведёт Коллектор (`admin-web/`), здесь только Android-приложение игрока.

## Зачем всё это

Игроку на LARP приложение нужно на ходу: одной рукой, в полутьме, между делами. Аудит показал три главные проблемы: **взлом не
помещался на экран** (результат был ниже сетки, тесты делали `scroll_down`), **служебная шапка съедала около пятой части высоты**,
**каждая карточка занимала 100–120 dp ради одного действия**. Плюс 40 из 146 размеров шрифта были 9–10 sp, а рамки — то скошенные, то
прямоугольные («два дизайн-языка»).

## Принципы (действуют)

1. **Один экран — одно главное действие**, остальное на уровень ниже (раскрытие по тапу, окно).
2. **Список плотный:** строка ≈ 48 dp, карточки с кнопками — не в списках; кнопка действия показывается по тапу на строку («Передать», «Сообщение / Звонок»).
3. **Хром ≤ 10 % высоты:** шапка скрывается на вложенных экранах, нижнее меню 52 dp; «всё нормально» — точкой или тоном, а не текстом.
4. **Скос везде:** любая рамка — через `MbChamfer` / `Modifier.mbFrame`, прямоугольная считается ошибкой (`NoRectangularBordersTest`).
5. **Минимум 11 sp** для всего, что нужно прочитать; масштаб шрифта 1,3× не ломает экраны (`FontScaleTest`).
6. **Главные действия — в нижней трети экрана** (над меню, под большим пальцем).
7. **Во время таймера взлома ничего не прокручивается** и нет лишних панелей.

## Как это выглядит по экранам

| Экран | Состояние |
|---|---|
| **Первый запуск** (`SetupScreen`) | «Сканировать QR персонажа» (QR от мастера: ключ, позывной, фракция, остаток); под сканером «Нет камеры? Ввести код» — поле короткого кода `ABC-DEF` и, если сервер не задан, «Адрес сервера». Код меняется на тот же QR через `POST /api/provisions/redeem`; сервер без такой ручки — сообщение «сервер не поддерживает ввод кода». Код действует один раз; повторно — после сброса сессии и с новым кодом. Ручное создание личности есть только в dev-сборке. Контракт выдачи — `docs/provisioning-qr.md` |
| **Чат** | Список бесед (непрочитанные сверху, превью в одну строку), «Новый чат», фракционный чат; переписка — Breadcrumb «Сообщения › контакт» с кнопками «Позвонить» и «Перевод», пузыри с отметками доставлено / прочитано, голосовые сообщения, карточки перевода и передачи предмета с «Принять», `MbComposer` с кнопкой «Отправить». Кнопка «Перевод» открывает Финансы с выбранным получателем, «Передать предмет» — меню «шард / демон» с выбором предмета |
| **Звонки** | Списки «Контакты» и «Недавние»; входящий — `MbDialog` «Отклонить / Принять», идущий — зелёная плашка `MbBanner` под статус-баром с «Завершить» (со второго нажатия), экран гаснет у уха |
| **Кибердека** | Вкладки «Демоны / Шарды» (состояние переживает смену вкладки), плотные строки демонов ≈ 48 dp, тап раскрывает «Передать»; шард читается в окне; кнопки «Войти в Сеть» (очки, `NetrunScreen`) и «Сканер» внизу; отказ сканирования контейнера — `MbBanner` danger над вкладками |
| **Взлом** | Один экран без прокрутки (проверено на 360 × 640 dp): таймер, буфер, матрица, последовательности; во время взлома шапки нет; итог — оверлей в теме Success с кнопкой, подсказка новичку при первом входе, вибрация на тап / совпадение / ловушку / итог |
| **Финансы** | Плитка баланса (крупная, с суммами за сутки), «Новый платёж» (форма — окно, подтверждение — `MbDialog` danger), операции по дням, «Отменить» у недоставленного перевода |
| **Профиль / Настройки / Сеть** | Открываются из шапки (портрет) как отдельный экран вне оболочки с тремя вкладками. Профиль — карточка и QR контакта (показывается по тапу), контакты со «Сканер». Настройки — переключатели уведомлений, звуков, отчётов о прочтении, автопроигрывания голосовых, звуков взлома; сообщения мастера; «Опасная зона» внизу со сбросом сессии. Сеть — плитки узлов, очереди синка и журнала; адрес коллектора и код игры, метка и очистка журнала |
| **Везде** | Уведомления — `AppSnack` вместо `Toast`; нет связи с коллектором — плашка в оболочке; пустые экраны — `MbEmptyState` с действием; системные отступы (edge-to-edge) и «Назад» — см. гайдлайн, раздел 4 |

## Что не сделано

- Замер производительности перерисовки матрицы взлома на слабом телефоне (на эмуляторе задержек не видно).
- Вибрация и звук интерфейса по гайдлайну (раздел 9) — отдельной задачей; сейчас вибрация есть во взломе.
- Живая проверка яркости на улице и «самого маленького игрового телефона» — Т13 в [live-test-plan.md](../live-test-plan.md).

## Как проверять

- `scripts/e2e/audit-screens.sh` — снимки экранов приложения на эмуляторе (листы «до / после» кладут в `docs/ux/`).
- Paparazzi: `KitCatalogTest` (компоненты), `*ScreenTest`, `FontScaleTest`, `SmallScreenBreachTest`; `NoRectangularBordersTest` держит запрет на прямоугольные рамки.
- Сценарии `scripts/e2e/scenarios/*.sh` ищут элементы по тексту: переставили «Передать» или «Взломать контейнер» — правьте их вместе с интерфейсом.
