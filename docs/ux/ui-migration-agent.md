# Инструкция для агента: миграция интерфейса на новый стиль

Для отдельной сессии (Claude Code или другой агент), которая переносит утверждённый стиль в Compose-приложение игрока.
Промпт для запуска — в конце файла.

## Задача

Перенести внешний вид из прототипа в дизайн-систему `app/src/main/java/com/megablok10/app/ui/theme/` и пересобрать экраны из неё
по [плану миграции](ui-migration-plan.md), этап за этапом (M0 → M6). Логика приложения не меняется — только слой отрисовки.

## Прочитать до начала (в этом порядке)

1. [CLAUDE.md](../../CLAUDE.md) — правила репозитория: git, проверки, инварианты. Они важнее этой инструкции.
2. [ui-style-guide.md](ui-style-guide.md) — как должно выглядеть: токены, шрифты, фаски, размеры, компоненты, «нельзя».
3. [ui-migration-plan.md](ui-migration-plan.md) — что делать и в каком порядке, соответствие старых и новых компонентов, открытые вопросы.
4. [prototype/mb10-ui-kit.html](prototype/mb10-ui-kit.html) — живой эталон. Открыть в браузере; вкладка «Компоненты» — каталог,
   «Экраны» — 19 экранов. Точные цвета, размеры и отступы — в его CSS (блок «ТОКЕНЫ» и разделы по компонентам). Спорный случай решает прототип.
5. [docs/architecture.md](../architecture.md), [android-handoff.md](../android-handoff.md) — устройство приложения.
6. Нынешняя дизайн-система: `ui/theme/Color.kt`, `DesignSystem.kt`, `Shapes.kt`, `Components.kt`, `Type.kt`, `ui/nav/AppShell.kt`.

## Границы

**Можно менять:** `ui/theme/**`, `ui/nav/**`, `ui/screens/*Screen.kt`, `CallOverlay.kt`, `AnnouncementDialogHost.kt`,
`ItemTransferUi.kt`, `breach/BreachScreen.kt`, `res/font/**`, скриншот-тесты и эталоны `app/src/test/snapshots/`,
координатные скрипты `scripts/e2e/audit-screens.sh` и `demo.sh`, документы `docs/ux/**`, раздел UI в `docs/architecture.md`.

**Только отдельным шагом с тестом и по таблице «Нужны данные» плана:** ViewModel (счётчики непрочитанного, баланс в шапке, состояние синка).

**Нельзя:**
- `admin-web/` — это другая сессия;
- сеть, синк, хранилища, Room-схема, журнал и события `Mb10Log`, строки `MB10DBG`, `scripts/e2e/log-contract.tsv`;
- инварианты из CLAUDE.md (транзакции, `SendOutcome.UNKNOWN`, адреса пиров, фоновый старт);
- тексты, по которым стенд нажимает элементы («Взломать контейнер», «Принять», «Принято», «Отправить», «Настройки», «Демоны», «Шарды»,
  имена демонов мок-взлома) — только вместе с правкой `scripts/e2e` в том же коммите. Кнопка-иконка подходит, если её `contentDescription` —
  тот же текст: стенд ищет и по нему.

## Порядок работы

1. **Ветка.** `scripts/agent-worktree.sh new ui-kit` — своя копия и ветка `agent/ui-kit`. В `main` не коммитить.
2. **M0.** Если в ветке нет `docs/ux/ui-style-guide.md`, `ui-migration-plan.md`, `ui-migration-agent.md`, `prototype/mb10-ui-kit.html` — они
   лежат незакоммиченными в основной копии `/Users/peachbite/Developer/megablock10/docs/ux/`. Скопировать и закоммитить первым коммитом.
   Затем задать владельцу **открытые вопросы из плана** (раздел «Открытые вопросы владельцу») и дождаться ответов; ответы записать в план.
3. **Дальше по этапам M1 → M6**, внутри этапа — маленькими шагами. После каждого шага:
   - сборка и тесты зелёные (раздел «Проверки»);
   - намеренно изменившиеся скриншоты перезаписаны `./gradlew recordPaparazziDebug` и закоммичены вместе с правкой;
   - коммит на русском: что и почему; добавлять в индекс только свои файлы по путям (не `git add -A`: в репозитории работают параллельные сессии);
   - в плане пункт отмечен ~~зачёркнуто~~ + хэш коммита, с короткой строкой «Сделано: …».
4. **Экраны (M4) — по одному**, каждый отдельным коммитом, и после каждого — e2e на CI (`e2e.yml` на ветке). Не браться за следующий
   экран, пока предыдущий не зелёный.
5. **Перед M5 (удаление старого)** — убедиться `grep`-ом, что старые компоненты больше нигде не используются.
6. В `main` — только по команде владельца, перемоткой, с зелёными CI и e2e.

## Проверки

| Что | Команда |
|---|---|
| Быстро (≤ 1 мин) | `scripts/check.sh --fast` |
| Всё локально | `scripts/check.sh --all` |
| Unit-тесты app + скриншоты | `./gradlew verifyPaparazziDebug` (без скриншотов — `testDebugUnitTestNoScreenshots`) |
| Перезаписать эталоны скриншотов | `./gradlew recordPaparazziDebug` |
| Статика | `./gradlew :app:detekt :kit:detekt :kit:animalsnifferMain :app:lintDebug` |
| e2e | локально `scripts/e2e/up.sh && scripts/e2e/run-all.sh`; на CI — `e2e.yml` на ветке |

- **Никогда `./gradlew cleanTest*`** — Paparazzi считает `app/src/test/snapshots/` выходом задачи, clean сотрёт закоммиченные эталоны.
  Нужен прогон без кэша — `--rerun-tasks`. Стёрлись — `git restore app/src/test/snapshots`.
- В облачной сессии без Android SDK `:app` не собирается — проверка только через CI (`main.yml`, `e2e.yml` на ветке). Не писать «проверено»,
  не дождавшись зелёного CI. После каждого пуша досмотреть прогон CI до конца.
- Красный e2e — сначала журнал (`journal_cat`, шаг «Журналы красных сценариев» в логе job), потом гипотезы. Разовый красный — не «флейк».

## Как переносить компонент

- Имена — из гайдлайна (`MbButton`, `MbListItem`, `MbDialog`…), файлы — `ui/theme/components/`.
- Цвета — только токены `MbColors` из `CompositionLocal` (темы Default / Breach / Success). Ни одного `Color(0x…)` на экранах.
- Рамка — только `MbChamfer`/`Modifier.mbFrame` одной из трёх форм (std / tab / dlg). Ни `Modifier.border` без формы, ни `RoundedCornerShape`.
- Нажимаемое — `Modifier.minimumInteractiveComponentSize()` (48 dp) при любом размере рисунка.
- Иконка без текста — `contentDescription`; декоративная — `null`.
- Состояния: нажато / выключено / фокус — у кнопок, строк, вкладок.
- Текст — `sp`, не мельче 11 sp; проверять системный масштаб шрифта 1,3×.
- Шрифты — `res/font` (Fira Sans Condensed, IBM Plex Mono, статичные TTF, лицензия OFL рядом), не Downloadable Fonts: на площадке нет интернета.
- Каждый компонент — в Paparazzi-каталоге (`kitCatalog`), каждый экран — свой снимок с фейковым состоянием.

## Готово, когда

- все этапы плана отмечены, в `ui/` нет старых компонентов, шрифтов и `MB10Colors`;
- экраны совпадают с прототипом по цветам, формам, размерам и порядку элементов;
- CI и e2e зелёные, проверка на устройствах (M6) записана в план;
- гайдлайн и прототип обновлены, если по ходу пришлось что-то менять в стиле (с согласия владельца).

## Когда остановиться и спросить владельца

- Нужно поменять что-то вне границ (сеть, данные, тексты для стенда без правки стенда, `admin-web`).
- Прототип и гайдлайн противоречат друг другу, или экрана/состояния нет в прототипе.
- Экран взлома не помещается на 360 × 640 dp даже после ужатия.
- e2e красный, и журнал не объясняет почему.
