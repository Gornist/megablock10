# План миграции интерфейса на новый стиль

Перенос утверждённого стиля из HTML-прототипа ([prototype/mb10-ui-kit.html](prototype/mb10-ui-kit.html), правила —
[ui-style-guide.md](ui-style-guide.md)) в Compose-приложение игрока. Прототип в приложение не встраивается (WebView отклонён):
переносится только внешний вид в дизайн-систему `ui/theme/`, затем экраны пересобираются из неё. Состояние отмечайте здесь:
~~зачёркнуто~~ + коммит.

## Что не меняется

Меняется только слой отрисовки (`ui/theme/`, `ui/nav/`, `ui/screens/*Screen.kt`, `breach/BreachScreen.kt`). Не трогать:

- ViewModel, хранилища, сеть, синк, журнал, строки `MB10DBG`, контракт журнала (`scripts/e2e/log-contract.tsv`).
- Инварианты из [CLAUDE.md](../../CLAUDE.md): транзакции, `SendOutcome.UNKNOWN`, адреса пиров, фоновый старт.
- Тексты, по которым стенд находит элементы (`tap_text` в `scripts/e2e`): «Взломать контейнер», «Принять», «Принято», «Отправить»,
  «Настройки», «Демоны», «Шарды», имена демонов мок-взлома. Стенд ищет и по `text`, и по `contentDescription` — кнопка-иконка
  годится, если у неё такая подпись. Меняете текст — правьте стенд в том же коммите.

Если для экрана не хватает данных (счётчики непрочитанного, состояние синка), это отдельный маленький шаг в ViewModel —
с тестом, в своём коммите, до шага с экраном (см. «Нужны данные», ниже).

## Как вести работу

- Отдельная ветка через `scripts/agent-worktree.sh new ui-kit` (ветка `agent/ui-kit`), один исполнитель.
- Каждый шаг ниже — один или несколько коммитов, после каждого сборка и тесты зелёные (`scripts/check.sh --fast`,
  `./gradlew verifyPaparazziDebug`), для шагов M4 — ещё e2e на CI (`e2e.yml` на ветке).
- Скриншоты Paparazzi при намеренной смене вида перезаписываются (`./gradlew recordPaparazziDebug`) и коммитятся вместе с правкой.
  **Никогда `cleanTest*`** — сотрёт эталоны.
- В `main` — по команде владельца, перемоткой.

## Риски

- **Экран взлома не влезет** на маленьких телефонах с ячейками 48 dp → запасной вариант: 44 dp и ужатая панель последовательностей; решать по M6.
- **e2e по координатам** (`audit-screens.sh`, `demo.sh`) сломаются от новой высоты меню и шапки — это вспомогательные скрипты, не CI; править в M3.
- **Свечение (blur) в Compose** нагружает рендер на слабых телефонах → свечение только там, где указано в гайдлайне; при просадке — заменить на яркую рамку.
- **Параллельные сессии**: миграция трогает все экраны; на время M4 другие правки экранов — только через эту ветку.
