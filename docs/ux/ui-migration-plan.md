# План миграции интерфейса на новый стиль

Перенос утверждённого стиля из HTML-прототипа ([prototype/mb10-ui-kit.html](prototype/mb10-ui-kit.html), правила —
[ui-style-guide.md](ui-style-guide.md)) в Compose-приложение игрока. Прототип в приложение не встраивается (WebView отклонён):
переносится только внешний вид в дизайн-систему `ui/theme/`, затем экраны пересобираются из неё. Состояние отмечайте здесь:
~~зачёркнуто~~ + коммит.

## Что не меняется

Меняется только слой отрисовки (`ui/theme/`, `ui/nav/`, `ui/screens/*Screen.kt`, `breach/BreachScreen.kt`). Не трогать:

- ViewModel, хранилища, сеть, синк, журнал, строки `MB10DBG`, контракт журнала (`scripts/e2e/log-contract.tsv`).
- Инварианты из [CLAUDE.md](../../CLAUDE.md): транзакции, `SendOutcome.UNKNOWN`, адреса пиров, фоновый старт.
- Тексты, по которым стенд находит элементы (`tap_text` в `scripts/e2e`): «Взломать контейнер», «Принять», «Принято», «Отправить»,
  «Настройки», «Демоны», «Шарды», имена демонов мок-взлома. Стенд ищет и по `text`, и по `contentDescription` — кнопка-иконка
  годится, если у неё такая подпись. Меняете текст — правьте стенд в том же коммите.

Если для экрана не хватает данных (счётчики непрочитанного, состояние синка), это отдельный маленький шаг в ViewModel —
с тестом, в своём коммите, до шага с экраном (см. «Нужны данные», ниже).

## Как вести работу

- Отдельная ветка через `scripts/agent-worktree.sh new ui-kit` (ветка `agent/ui-kit`), один исполнитель.
- Каждый шаг ниже — один или несколько коммитов, после каждого сборка и тесты зелёные (`scripts/check.sh --fast`,
  `./gradlew verifyPaparazziDebug`), для шагов M4 — ещё e2e на CI (`e2e.yml` на ветке).
- Скриншоты Paparazzi при намеренной смене вида перезаписываются (`./gradlew recordPaparazziDebug`) и коммитятся вместе с правкой.
  **Никогда `cleanTest*`** — сотрёт эталоны.
- В `main` — по команде владельца, перемоткой.

## Этапы

**M0. Подготовка.** Прототип и гайдлайн — в `docs/ux/` (сделано вместе с этим планом). Владелец отвечает на открытые вопросы (ниже).
*Готово, когда:* вопросы закрыты, ветка `agent/ui-kit` создана.

**M1. Токены, шрифты, формы.** `ui/theme/MbColors.kt` (три темы), `MbTypography` (таблица гайдлайна, раздел 3), `MbDimens`
(отступы 10/8/4, 48 dp), `MbChamfer` и `Modifier.mbFrame`. Шрифты Fira Sans Condensed и IBM Plex Mono — статичные TTF в `res/font`
(лицензия OFL — положить `OFL.txt` рядом с исходниками шрифтов). `MB10Colors` пока отдаёт новые цвета под старыми именами, чтобы
всё собиралось; экраны не трогаем.
*Готово, когда:* сборка и тесты зелёные; `ScreenshotTest.designSystem` перезаписан и показывает новые цвета и фаски; detekt без новых находок.
*Риск:* размер APK (+≈1 МБ на 6 файлов) — приемлемо.

**M2. Компоненты.** По одному файлу на группу в `ui/theme/components/`: `MbButton`/`MbIconButton`/`MbKeyCap`/`MbActionBar`,
`MbTabs`/`MbBreadcrumb`/`MbSectionTitle`/`MbMetaLine`, `MbListItem`, `MbTag`/`MbStatusText`, `MbTile`/`MbCard`/`MbPortrait`/`MbQr`,
`MbDialog`/`MbBanner`, `MbFormRow`/`MbToggle`/`MbSlider`, `MbEmptyState`/`MbSkeleton`, `MbBubble`/`MbPayBubble`/`MbComposer`,
взлом: `MbPanel`/`MbTimer`/`MbBuffer`/`MbCodeMatrix`/`MbLog`. Иконки прототипа (24×24, штрих 1,7) — `ImageVector` в `MbIcons`.
Каждый компонент: `minimumInteractiveComponentSize`, `contentDescription`, состояния нажато/выключено/фокус, `@Preview`.
*Готово, когда:* новый Paparazzi-тест `kitCatalog` снимает все компоненты во всех состояниях и темах (аналог вкладки «Компоненты»
прототипа) и совпадает с прототипом на глаз; старые компоненты ещё живы.

**M3. Оболочка.** `MbAppShell`: шапка (портрет → профиль, позывной, фракция, €$, узлы), параметр `header = false` для вложенных
экранов, меню из 4 иконок с подписью активного и счётчиками, edge-to-edge с системными отступами. `AppSnack` → плашка.
*Готово, когда:* все вкладки открываются в новой оболочке; Paparazzi-снимок оболочки; e2e зелёный (координатные скрипты
`audit-screens.sh`, `demo.sh` поправлены под новую высоту меню — 52 dp вместо ≈62).

**M4. Экраны — по одному, каждый отдельным коммитом с e2e.** Порядок — от частых к редким, взлом отдельно:
1. Чат: список (непрочитанные сверху), переписка (Breadcrumb с «Позвонить»/«Перевод», пузыри, Composer; кнопка «Отправить» —
   иконка с подписью «Отправить» для стенда).
2. Звонки: список, `CallOverlay` → `MbDialog` входящего (Отклонить | Принять) и `MbBanner` идущего.
3. Финансы: баланс-плитка, операции (статус и время под суммой), перевод → `MbDialog` tone danger (Отмена | Подтвердить).
4. Кибердека: демоны (имя — коды, ниже эффект), шарды (журнал с «язычком», чтение в `MbDialog`), `ItemTransferUi`.
5. Взлом (`BreachScreen`): тема Breach, без шапки и подвала, ячейки 48 dp, «Выйти» у таймера, итог в теме Success.
   *Условие:* помещается без прокрутки на 360 × 640 dp; `perf-breach.sh` не хуже прежнего; стенд перестаёт делать `scroll_down` на результате.
6. Профиль / Настройки / Сеть — три вкладки одного экрана (сейчас `ProfileScreen` + `SettingsScreen` + `StatusScreen`).
7. Объявление мастера (`AnnouncementDialogHost`) → `MbDialog`.
8. Состояния на всех экранах: пусто (`MbEmptyState` с действием), загрузка (`MbSkeleton`), нет связи (`MbBanner` danger).

*Готово (для каждого экрана), когда:* экран собран только из `Mb*`-компонентов (ни одного `Color(0x…)`, `border` без формы, `RoundedCornerShape`);
Paparazzi-снимок экрана с фейковым состоянием; e2e на CI зелёный; проверен масштаб шрифта 1,3×.

**M5. Уборка.** Удалить старые компоненты, формы, `MB10Colors`-псевдонимы, шрифты Jura/JetBrains Mono/IBM Plex Sans; обновить
`docs/architecture.md` (раздел про UI) и `docs/android-handoff.md`; `docs/ux/ux-plan.md` — отметить закрытые пункты.
*Готово, когда:* `grep` не находит старых имён; check и e2e зелёные.

**M6. Проверка на устройствах** (по [device-testing.md](../device-testing.md)): яркость на улице ночью и днём, TalkBack проходит
основные сценарии (прочитать сообщение, ответить, перевести деньги, принять звонок), масштаб шрифта 1,3×, самый маленький
телефон из игровых, взлом без прокрутки. Итог — строка в этом плане.

## Открытые вопросы владельцу

1. Жёлтый в старой системе значил «от мастера/системы», в новой — «деньги и новое». Объявление мастера теперь узнаётся по окну
   (тёмно-синее, иконка колокола). Согласны?
2. Вибрация и звук (гайдлайн, раздел 9) — делать в этой миграции или отдельной задачей?
3. `AmountField` с цифровой клавиатурой и провижининг (`provisioning-qr.md`) в прототипе не нарисованы — переносить «по гайдлайну»
   или сначала прототипировать?
4. Порог «самый маленький игровой телефон» для проверки взлома без прокрутки: 360 × 640 dp достаточно?

## Риски

- **Экран взлома не влезет** на маленьких телефонах с ячейками 48 dp → запасной вариант: 44 dp и ужатая панель последовательностей; решать по M6.
- **e2e по координатам** (`audit-screens.sh`, `demo.sh`) сломаются от новой высоты меню и шапки — это вспомогательные скрипты, не CI; править в M3.
- **Свечение (blur) в Compose** нагружает рендер на слабых телефонах → свечение только там, где указано в гайдлайне; при просадке — заменить на яркую рамку.
- **Параллельные сессии**: миграция трогает все экраны; на время M4 другие правки экранов — только через эту ветку.
