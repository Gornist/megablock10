# Менеджер devbox — ТЗ сессии «Devbox»

Решение владельца 13.10: «с devbox слишком часто возникают непонятки — нужна сессия на Sonnet, которая управляет машиной удалённо,
держит очереди задач и отдельные экземпляры программ для сессий, чтобы они не мешали друг другу, всё запускает вовремя и перепроверяет
себя». ТЗ собрано опросом сессий Godot, Android App, Collector, LARP, Дронкарта, Nomad Surf (Blender — по журналу 08–13.10).

## Машина

`nick-arasaka-micro`: Ubuntu, GTX 1650 4 ГБ (драйвер 595.99), 8 ядер; ssh `devbox` = Tailscale 100.80.115.46 (LAN 192.168.1.141 ключ не
пускает), пользователь `nick`. GNOME/Wayland, автовход nick: автозапуск `~/.config/autostart/devbox-session.desktop` → `~/box/repo/scripts/devbox-session-start.sh`
(клон репозитория, `scripts/box.sh sync`; с 13.10 — не ручная копия): incy VPN → Tailscale → adb → Blender c blender-mcp на 9876 →
редактор Godot → самопроверка. adb — user-служба `box-adb`. Подробности сборок — skill `devbox`, Godot на devbox — `docs/netrun-devbox.md`.

- Устройства пропадают из USB, и никто этого не видит час; Pico видна только в порту 2-4 и после своей перезагрузки.
- Чужие тапы: `taptext` Android App попал в Chrome с картой Дронкарты (12.10).
- Общие `7777`, `~/pico-cfg`, `~/pico/netrun-client-cfg.apk`, `~/.godot`-кэш, `~/assets-work/out` (две сборки ассетов из разных worktree
  затирают друг друга), `/tmp/display.lock` и одна видеокарта, один стенд e2e, один демон Gradle.
- 12.10 ~15:40 devbox 5 мин не отвечал во время Cycles-рендера (Nomad Surf) — тяжёлое на GPU шло параллельно.
- Автозапуск — ручная копия скрипта, правка в репозитории (#184) до devbox не дошла.
- Причина падения Blender 13.10 (крэш-отчёт `~/box/blender-crash-1013-083827.txt`): `libdecor-gtk.so` в `wl_display_dispatch` при создании
  окна на Wayland — гонка со стартом графического сеанса, не сам Blender. Лечение в автозапуске: ждать графику, повторять (до 3 раз),
  последняя попытка без плагина рамок (`LIBDECOR_PLUGIN_DIR=/nonexistent`).
- **«adb сам перезапускается» — это Godot** (13.10, журнал `journalctl --user -u box-adb`: adb пишет цепочку процессов kill-server):
  каждый `godot --headless --import` (в т. ч. из `gdunit.sh`) на выходе звал `adb kill-server` — настройка редактора
  `export/android/shutdown_adb_on_exit`, по умолчанию включена. Пять убийств за 10 минут: рвётся Pico и телефоны, пропадают
  forward/reverse у всех. Исправлено строкой `export/android/shutdown_adb_on_exit = false` в
  `~/.config/godot/editor_settings-4.7.tres` (бэкап рядом, `.box-bak`); `box.sh status` показывает счётчик убийств и «кто».
  Новая версия Godot с другим именем файла настроек — повторить (проба предупредит замечанием о свежем убийстве).

## Обязанности

1. **Статус одной строкой** — `scripts/box.sh status` (Mac → ssh): сеть (Tailscale/LAN), аптайм, GPU (драйвер, память), диск, нагрузка;
   устройства (serial, модель, Wi-Fi/IP, время, VPN, что на переднем плане, кем занято); порты 9876/8000/9500/7777/2517/2527/4174/8765;
   голова очереди и брони. Вердикт 1–5 строк, код 0/1.
2. **Очередь по классам** (`box queue add|ls`): `gpu` — экспорт Godot, сборка Blender, Cycles (в т. ч. Nomad Surf), эмуляторы e2e —
   строго по одной; `gradle` — по одной (общий flock `dbx.sh`); `light` — параллельно. Место и примерное ожидание видны каждому.
3. **Брони** (`box lease <ресурс> <сессия> <мин>`): Pico, RCPad, XCover7, стенд e2e, порты. Пока бронь — чужие команды к ресурсу отказываются
   с понятным текстом; бронь истекает сама. Флаг «очки на владельце» — бронь владельца, ставит Godot или он сам.
4. **Экземпляры на сессию** (`box up <служба> <сессия>`): сервер стенда Godot, копия коллектора со своей БД, статика Дронкарты — порт из пула,
   свой каталог; `box down`. Blender — один общий с бронью (GPU 4 ГБ), второй экземпляр только по решению владельца.
5. **adb как постоянный user-сервис**, не зависящий от ssh-сеансов; все команды — только с `-s <serial>`.
6. **Проверка после загрузки** (user-сервис или автозапуск из репозитория вместо ручной копии): Tailscale (перезапуск, если нужно), adb и
   устройства, Blender 9876 (ждать графику, повтор после segfault), редактор Godot. Итог — сообщением сессиям, которые держат брони, и Pipeline.
7. **Перепроверка себя**: после каждого действия — `box status` и сравнение с ожидаемым; расхождение — повтор один раз, дальше — владельцу.
   Журнал действий и сбоев `~/box/journal.jsonl`; раз в день — короткая ретро Pipeline (skill `retro`).
8. **Ответы сессиям** на «дай мне X» (SendMessage): устройство, порт, место в очереди, снимок экрана устройства, статус;
   «собери ассеты из worktree X» / «сними кадры X» / «тесты A,B» → очередь и вердикт строкой + путь к журналу или сетке.
9. **Свои каталоги вывода на worktree:** `~/assets-work/<ветка>`, `~/pico-cfg/<сессия>`, APK с именем ветки — вместо общих.

## Нельзя

- **Без владельца:** перезагружать devbox, менять драйверы и пакеты, вводить пароли; системные настройки телефонов и очков (Wi-Fi, время,
  поворот, трекинг, датчики, setprop); ставить и удалять приложения и данные на телефонах владельца; трогать очки, пока он в них.
- **Без сессии-хозяина:** `gradlew --stop`, убивать чужие эмуляторы, стенды и процессы; `~/cp2020-lore` (LARP); `~/surf-blender`,
  `~/blender-5.2.2`, `surf-decals`/8765 (Nomad Surf); база и секреты `~/live-collector`; вкладки Chrome на телефонах; чистить чужие `~/wt-*`.
- Код проектов, `main`, CI — не его (как у всех: PR и поезд Pipeline).

Код выхода — команды; 3 — таймаут ожидания |

Чужую бронь гасить нельзя без `--force` |
| `box.sh guard on\|off\|status` | таймер-страж `box-pico-guard` (раз в минуту, `ctl.sh pico guard`): Awake без брони дольше 3 мин → гасит. Включается **только этой командой** — действует на очки без человека; `status` показывает Awake без брони как замечание |

Загрузочная проверка (`devbox-session-start.sh`): Tailscale перезапускается **только** если не Running (раньше — всегда, роняя ssh);
adb — проверка службы; Blender — ждёт графику, повторяет, сохраняет крэш-отчёт; редактор Godot — только ждёт и сообщает; в конце та же
проба. Итог — `~/box/boot.report` (его показывает `status`); сообщением сессиям с бронями и Pipeline итог станет в D2, когда появятся брони.

**Не сделано и почему:** watchdog Tailscale (причину потери ssh 12–13.10 по журналам не восстановить — на обеих загрузках автозапуск
довёл Tailscale до Running; при ближайшем сбое смотреть `journalctl -u tailscaled` и `~/.local/state/devbox-session.log`); перезагрузочный
путь проверен только прогоном `boot-check` и подложным Blender с двумя падениями — полная загрузка требует владельца.

### D4: как подключить свой скрипт (две строки, без переделки)

`scripts/box.sh` работает и на Mac (по ssh), и на самом devbox (локально). Устройство — по имени `rcpad` | `xcover7` | `pico` (серийник приводится сам).

```bash
# 1. перед командой к устройству/порту: чужая бронь — отказ с «кто и до когда» (код 1), своя или свободно — 0
scripts/box.sh check rcpad "Android App" || exit 1
# 2. тяжёлое — в очередь класса (gradle | gpu | light); код выхода — команды, 3 — таймаут ожидания
scripts/box.sh run gpu Godot --name shot -- bash -c 'netrun/tools/dev.sh shot …'
# 3. своя служба на своём порту и в своём каталоге
scripts/box.sh up stand Godot -- ~/pico-cfg/srv_p2.sh {PORT}
```

Классы: `gradle` — тот же замок, что у `dbx.sh`, стенда e2e и раннера CI (ничего не менять); `gpu` — отдельный замок, **не** `/tmp/display.lock`:
внутри `run gpu` команда сама может брать `flock /tmp/display.lock` (так делают кадры Godot и Blender) — если бы классы совпадали, она
заблокировала бы сама себя. Бронь очков — только через `pico wake`/`sleep` (сами `KEYCODE_POWER` не жать).

### Д5: очки без человека (13.10, поручение владельца: «я не могу присутствовать при каждом тесте»)

Что сломалось: окно «Слишком темно» — Unity-оверлей, uiautomator его не видит, а `pico_fg` брал первое совпадение из `dumpsys window`
по всем дисплеям и задачам (устаревший `HandDialogActivity`), поэтому `pico ready` дважды сказал «ГОТОВО» на тёмных очках; в пакете
`com.pvr.seethrough.setting` живут и окно границы, и «Слишком темно» — тап по координатам границы по одному пакету был бы вслепую.

**Замер на живых очках 13.10 18:40** (Awake под бронью, окно «Слишком темно» на кадре):

| Источник | Значение | Смысл |
|---|---|---|
| `settings global pvr.app.data.light_warning_state` | `1` | окно «Слишком темно» показано (подтверждено кадром) |
| `dumpsys activity activities` → `mResumedActivity` | `com.pvr.seethrough.setting/.MainActivity` | то же окно; верхняя активность — надёжный источник |
| `settings global pvr.app.data.top_app_on_default_display` | то же | совпало; запасной источник |
| `getprop sys.pxr.boundary.ready` | `0` | граница не готова (в здоровом состоянии значение **не наблюдалось**) |
| `getprop sys.pxr.trackingservice.algstate` | `1` (спящие: `2`) | состояние трекинга; семантику не знаю |
| `getprop sys.pxr.trackingservice.alg_confidence` | `0` | уверенность трекинга; `<= 0` считаем «не готово» (гипотеза) |

Правила (`pico ready` / `pico fg`): `light_warning_state=1` → физическая причина; верхняя активность — пакет из `PICO_BAD_PKGS`
(системные) → окно; не из `PICO_OK_PKGS` (игра, лаунчер) → неизвестное окно; `boundary.ready != 1` → граница; `alg_confidence <= 0` →
трекинг. Списки расширяются файлами `~/box/pico-ok-pkgs` и `~/box/pico-bad-pkgs` (по строке); `PICO_REQUIRE_BOUNDARY=0` отключает проверку
границы, если окажется, что в здоровом состоянии она 0. Тап по координатам окна границы — только при `light_warning_state != 1`.
Каждый успех пишет в журнал событие `pico-state` со значениями — по ним эталон здорового состояния уточнится.

| Команда | Что делает |
|---|---|
| `box.sh pico ready <владелец>` | идемпотентно: проверка по состоянию системы, брони не снимает; «НЕ ГОТОВО» — PNG, строка в `~/box/attention.log`, очки гасятся, бронь остаётся |
| `box.sh pico fg` | одна строка: `окно=… light=… граница=… трекинг=… вердикт=ok\|причина`; код 0 — здоровое |
| `box.sh pico start <владелец> <пакет/активити>` | `am start` + проверка, что игра на переднем плане («kept for the user», «not started», ошибка → НЕ ГОТОВО) |
| `box.sh pico run <владелец> <мин> [--timeout сек] [--port N] [--dir каталог] -- команда…` | бронь → разбудить → ready → `logcat -c`, снимок «до» → команда → снимок «после», `logcat -d` → погасить → снять созданные брони (всё через `trap`: при `Ctrl-C`/`TERM`/любом выходе) |

Выход `pico run`: код команды; `20` — не готово или после прогона на очках вылезло окно; `21` — бронь `pico` чужая; `124` — таймаут;
`2` — ошибка аргументов. Окружение команды: `PICO_SERIAL`, `PICO_RUN_DIR` (по умолчанию `~/box/runs/<время>-<владелец>`: `screen-before.png`,
`screen-after.png`, `logcat.txt`), `BOX_OWNER`, `BOX_CTL`. Вердикт — последняя строка: `pico run: ОК — команда rc=N за T с; окно …; каталог …`,
`pico run: НЕ ГОТОВО — …`, `pico run: ТАЙМАУТ …`, `pico run: команда rc=N, НО после неё на очках: …`.

`~/box/attention.log` — «нужен человек» (темно, нет контроллера, неизвестный пакет, окно не ушло, очки не погасли): строка
`время | владелец | причина | PNG`, одинаковые подряд не дублируются; читает обход Pipeline и пишет владельцу.

Чего `pico run` **не делает** сознательно: не меняет системных настроек очков (`svc power stayon`, `global_6dof`, `setprop` — только
владелец), не трогает приложение Godot (`netrun.cfg`, `force-stop` — внутри команды хозяина, под её `trap`), не жмёт кнопок вне белого списка.

Приёмка каждого шага: скрипт печатает вердикт, `lint-pipeline` зелёный, проверка на devbox описана в PR (skill `pr`), перезагрузка — только
с владельцем.
