# netrun-assets — вид Сети без потерь времени

Черновик skill лежит в `netrun/assets/skill/netrun-assets/` (зона Blender); в `.claude/skills/` его переносит Pipeline manager.
Стиль и контракт — в `netrun/assets/STYLE.md` (правила, решения владельца) и `ARCHITECTURE.md` (конвейер, контракт узлов); здесь только цикл и грабли.

## Зона и порядок
Пишем `netrun/assets/**` и `netrun/tests/assets_*`; сеть, `netrun/shared`, `netrun/server`, `node_view.gd`, `ice_view.gd` — Godot (просить сообщением: файл, что, зачем).
Своя worktree (`scripts/agent-worktree.sh new <имя>`), явные пути в `git add`, перед PR `scripts/zone-check.sh blender`, в main — через Pipeline («готово к слиянию: PR N»).

## Цикл (всё с Mac, тяжёлое на devbox)
1. Правка `src/*.py` / `shaders/*.gdshader` / `asset_materials.gd` / `preview_capture.gd` — Edit/Write.
2. `netrun/assets/tools/pipeline.sh build` — Blender на devbox → glb → validate (лимиты tris/точек/штрихов), MANIFEST. Сборка детерминирована (`PYTHONHASHSEED=0`, `lib.canon_faces`):
   после неё `git status` показывает только ассеты, которые ты правил; если поменялось что-то ещё — это баг детерминизма, не коммитить молча.
3. `netrun/tools/dev.sh test` — gdUnit по изменённым (`assets_models_test`). «Изменённый код не затрагивает тестов» значит, что НИЧЕГО не проверено (правился только `.py`):
   тогда тест ассета запусти явно или проверь glb числами из отчёта build.
4. Кадры: `pipeline.sh shots <каталог> --tier=BASE [--only=a,b] [--grid]` → смотреть ОДИН кадр (`sips -Z 1000 in.png --out out.png` на Mac) или `--grid`; серия по чек-листу — агент `visual-reviewer` (sonnet).
   Правка только шейдера (`*.gdshader`) пересборки не требует — сразу `shots`.
5. Числа вместо глаз: `pipeline.sh stats <кадры|каталог> --ref <референс.png>` (см. ниже).
6. Перед PR: `scripts/verify.sh --full`, `scripts/zone-check.sh blender`; ждать CI — `scripts/ci-wait.sh pr N` в фоне.

## Грабли (все были на деле)
- На Mac нет `timeout`, Pillow, ImageMagick, bash 3.2: картинки обрабатывать на devbox (`sips` есть). Одна задача на devbox: `pipeline.sh` берёт flock, второй ждёт (до 30 мин) — исполнителей по одному.
- У каждого нового `.glb` должен быть закоммичен `.glb.import` (его делает Godot на devbox; без него превью рисует пустой кадр «No loader found»). После правки glb в чужой копии (клиентская сцена) нужен импорт: прогнать `dev.sh test`, иначе кадр со старым кэшем.
- Если скрипт ассета упал с Traceback, `build` его не соберёт, а `rsync --delete` сотрёт tracked glb, код выхода 0: смотреть вывод на Traceback.
- `--tier` в просмотре по умолчанию HARD (синий); окружение клиента в BASE бирюзовое — снимать `--tier=BASE`.
- Чёрное нельзя сделать полупрозрачным аддитивным смешиванием (чёрный в `blend_add` невидим): стекло — тёмно-бирюзовый цвет с низкой альфой. Непрозрачный чёрный (`solid_dark`) глубину пишет, остальное — нет (`depth_draw_never`).
- Имя меша выбирает шейдер (`*_skirt`, `*_mist`, `*_glass`, `*_hang` и др., `AssetMaterials.apply`); имя, занятое другим ассетом (`ice_haze`), ломает сборку — `grep` перед новым суффиксом.
- Ориентация: «перед» ассета в Godot — −Z (хранилище); клиент ставит yaw+PI. Контракт узлов (`State_*`, `Tier_*`, `ShardSlot`, `Screen`, `ScreenAnchor`) — в ARCHITECTURE.md; менять только вместе с Godot-сессией.
- Не удалять старые glb, пока клиент их использует (vault_open/closed жили до перехода на vault.glb). Бюджеты Pico 4 не измерены — слои прозрачности (ореол, вуаль, дымка, стекло) считать дорогими, нужен замер на очках.

## Числовая проверка кадра (`pipeline.sh stats`)
Столбцы: `lum` яркость, `dark` доля чистого чёрного, `lit` доля светящегося, `cyan`/`blue` доля бирюзы/синего среди светящегося, `red` доля красного, `hor` яркость горизонта к средней, `topbot` потолок/пол.
Замер 06.10 по двум референсам CDPR (кадр с человеком и кадр с «дождём»): lum 19–25, **dark ≈ 0** (чистого чёрного нет — везде тёмная бирюзовая дымка), lit 16, cyan 96–98, blue 0, red 0, hor 1,4–1,9, topbot 0,4–0,6.
Наши кадры комнаты: dark 11–36 (чернее референса), cyan 75–90, hor 1,1–1,9. Ориентиры для окружения BASE без существ: blue < 15, red < 1, cyan > 85, hor > 1,3.
Вывод для правок: «похоже на референс» = заполнить пустоту между плитами тёмной бирюзовой дымкой (dark ↓) и держать горизонт ярче средней (hor ↑). Цифры — подсказка, вердикт выносит человек.

## Карточка исполнителю (sonnet) — шаблон
Файл в scratchpad, перечитать до отправки. Разделы: цель одной фразой (+ решение владельца дословно); ветка/worktree; зона записи (список путей) и чужое; досье (≤10 ссылок `файл:строка`, текущие параметры); бюджет и лимиты validate;
шаги — каждый один коммит на русском (что и ПОЧЕМУ) + `Co-Authored-By`; проверки (build, `dev.sh test`, кадры ≤3 итерации, один кадр за раз); запреты (push, main, `git add -A`, python-heredoc, sleep > 30, файлы вне зоны);
отчёт ≤12 строк (статус, коммиты, проверки, параметры «было→стало», пути кадров, что смотрел глазами, вопросы). После отчёта оркестратор САМ: `git status`, `git diff --name-only <merge-base>..HEAD | grep -v ^netrun/assets/`, один кадр, тест — отчётам на слово не верить
(исполнитель писал «проверено», когда `dev.sh test` ничего не запускал; один раз молча поменял решение владельца — ослабил дымку).
