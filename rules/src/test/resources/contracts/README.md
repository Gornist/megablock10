# Общие векторы контрактов

Один файл — один контракт между зонами. Формулы подписи, строки карточек и крипто лута живут в 2–4 копиях (приложение, Мост,
коллектор, тесты); без общего известного ответа расхождение находится на площадке, а не в CI (аудит 17.10, `review-contracts.md` №3–4).
Здесь — **известные ответы**: сторона контракта читает файл и сверяет им свою реализацию. Файлы правятся только вместе с форматом
(формат меняется по правилам «Контракт между зонами» из `CLAUDE.md`: сначала читающая сторона).

| Файл | Что стережёт | Читают |
|---|---|---|
| `change-record.json` | байты подписи записи (`payload_utf8`), проверка подписи ECDSA P-256/SHA-256/DER, закрытые списки `fields` и `reasons` | приложение (`ChangeRecordContractTest`); коллектор — `changeRecord.ts`; Мост — `WorldRecordDeriver` |
| `cards.json` | карточки денег `TX v2`, предметов `ITEM v2`, чек `RCPT v1`: строка и байты подписи (`TX2\|…`, `ITEM2\|…`, `id\|ключ`) | приложение (`CardsContractTest`); Мост — `PhoneWire` |
| `qr.json` | QR контейнера, шарда, RAM-апгрейда, персонажа, сигнала СБ; `rejected` — строки другой версии, которые декодер обязан отвергнуть | приложение (`QrContractTest`); коллектор — `mb10QrCodec.ts`; Мост — `PhoneWire` |
| `loot-crypto.json` | ключ лута (постоянный и HKDF от секрета игры), блок AES-256-GCM `IV ‖ шифртекст ‖ тег` | приложение (`LootCryptoContractTest`); коллектор — `lootCrypto.ts` |

Правила файлов:

- значения посчитаны **независимо от Kotlin-кода** (Node и стандартная криптография); имена векторов — по-русски, для сообщения при падении;
- JSON-`null` и пустая строка различаются только там, где это часть формата (`change-record.json`: оба дают пустое поле в байтах подписи);
- ключи и подписи карточек — условные строки: их криптография в этих векторах не проверяется, проверяется только состав байт;
- читатель находит файлы вверх от рабочего каталога модуля: `rules/src/test/resources/contracts/` (образец — `ContractVectors` в `app/src/test/.../contracts/`).
