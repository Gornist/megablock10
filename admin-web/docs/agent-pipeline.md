# Пайплайн работы агента над коллектором

Как вести задачи в `admin-web/` быстро и дёшево по токенам. Общие правила проекта — `CLAUDE.md` (зоны, слияния, проверки); здесь то, что
специфично для коллектора. Скрипты проверки — `admin-web/tools/`. Основная статья расхода — прочитанные байты и картинки: они остаются в
контексте и оплачиваются на каждом следующем ходу (целые документы, скриншоты браузера, правки через `python3 - <<EOF` вместо Edit, ожидание
CI опросами).

## 1. Кто что делает

| Исполнитель | Что | Выигрыш |
|---|---|---|
| **Главный агент (Sonnet)** | разговор с владельцем, план, карточки, ревью диффа (`git diff --stat`, потом точечные куски), коммит, правки до ~3 вызовов | — |
| **Haiku 5.5 (агент `scout`) / Explore** | поиск «где X» (ответ `файл:строка` + ≤ 10 строк), выписка раздела из большого документа, разбор лога упавшего теста, механическая замена по точному списку | 20–80 тыс. токенов чтения остаются у агента, главному приходит ≈1 тыс. |
| **Sonnet-субагент** | реализация по карточке: 3–10 шагов, по коммиту на шаг, команда приёмки | контекст главного не забивается; общий расход примерно тот же |
| **Opus** | контракты с Мостом и внешними протоколами, миграции БД и путь приёма/целостности (деньги игроков), auth/crypto/`GAME_SECRET`, ревью рискованного диффа, разбиение эпика на карточки | дорогой по лимитам — звать точечно |

**Делегировать, если выполнены ВСЕ условия:** задача описывается карточкой на один экран; приёмка проверяется командой; файлы не пересекаются
с другой текущей работой; агенту придётся прочитать > 30 тыс. токенов, а отчёт уложится в 2 тыс.
**Не делегировать:** нужен диалог с владельцем или угадывание намерения; сквозной дизайн; push, `main`, удаления; задача меньше трёх вызовов.
Решения владельца, где иначе пришлось бы угадывать, — сначала допрос (skill `grilling`), потом код.

## 2. Стадии

| Стадия | Как | Параллельно? | Барьер |
|---|---|---|---|
| Разведка | Haiku на чтение: `файл:строка` + выжимка | да, до 3 | — |
| План | главный пишет карточки (в файл, перечитать один раз) | нет | согласие владельца, если меняется контракт или UX |
| Реализация | Sonnet-агенты, файлы не пересекаются | до 2 (в отдельных worktree) | после каждого шага `tools/test.sh <часть>` и коммит |
| Проверка | главный: `tools/test.sh all` (или `scripts/verify.sh`) | нет | всё зелёное **своими глазами**, отчётам агентов не верить на слово |
| PR и CI | `scripts/zone-check.sh collector`, пуш, PR (skill `pr`), `scripts/ci-wait.sh pr N` в фоне; пока ждём — следующая независимая работа | да | зелёный CI; `ci-wait` может ответить «зелёное», пока job ещё идут, — сверить `gh pr checks N` |
| Слияние | сообщение Pipeline manager: «готово к слиянию: PR N — что внутри; дверь/радиус; порядок/пара; ждёт ли решения владельца». Вливает поезд Pipeline (`scripts/train.sh`) и владелец (`scripts/land.sh N`) | нет | агентам перемотка `main` запрещена хуком |
| Уборка | `land.sh` сам убирает ветки `agent/*` влитых PR и чистые worktree; прочее — `scripts/agent-worktree.sh gone <имя>`, удаляет владелец | — | — |

Новая задача — в новой worktree: `scripts/agent-worktree.sh new <имя>`, затем `admin-web/tools/wt-deps.sh`. Нет текущей задачи — верхняя строка
`[collector]` из `docs/backlog.md`, пометить `[~] (Коллектор)`.

**Контракт между зонами** (версии `/api/capabilities`, формат записей мира, сообщений Моста, QR, приложение↔коллектор): `main` должен быть зелёным
после каждого слияния — сначала читающая сторона принимает и старую, и новую версию, потом пишущая поднимает версию; парные PR идут в одном порядке,
сосед предупреждён сообщением. Новый открытый маршрут — запись в `OPEN` теста `routesAuth.test.ts` с причиной.

**Не раздувать контекст главного:** в отчётах субагентов нет кода; главный не перечитывает файлы, которые прочитал агент, а смотрит его дифф;
длинный вывод — в файл, в контекст только `tail -n 30` или grep по вердикту; большие документы (`admin-web/README.md`, протокол Моста) —
`grep -n` по заголовкам и Read с `offset/limit`.

## 3. Скрипты (`admin-web/tools/`)

Один скрипт — одна ответственность; в stdout 1–5 строк вердикта, полный лог — `/tmp/mb10-tools/`, код выхода 0/1.

| Скрипт | Что делает |
|---|---|
| `test.sh server\|client\|lint\|build\|all [--grep шаблон]` | сам выбирает Node, части идут по очереди (8 ГБ), вердикт вида `server: ок — 451 из 461, пропущено 10 (15с)` или имена упавших тестов |
| `wt-deps.sh [server\|client]` | в свежем worktree заменяет симлинки `node_modules` на `npm ci` (иначе версии основной копии не совпадут с веткой) |
| `preflight.sh` | (только чтение) ahead/behind относительно `main`, правки вне зоны `admin-web/`, неотслеживаемое в зоне |
| `ci.sh [ветка] [workflow]` | запуск CI на запушенной ветке без PR и ожидание одной строкой; для PR есть `scripts/ci-wait.sh pr N`. Запускать в фоне |
| `merge-ready.sh <ветка>`, `branch-gone.sh <ветка>…` | (только чтение) проверка перемотки и «ветка влита целиком»; слияниями и уборкой теперь ведают Pipeline и `land.sh`, скрипты нужны разве что вне процесса PR |

Общие скрипты проекта (`scripts/`): `verify.sh` (проверки затронутых областей одной строкой), `zone-check.sh collector`, `ci-wait.sh`, `agent-worktree.sh`.

### Node
Нужен **Node ≥ 22**: `better-sqlite3` 13 на Node 20 падает SIGSEGV, vitest 5 на 20 не стартует. Скрипты берут `$NODE_BIN`, затем
`/opt/homebrew/opt/node@22/bin`, затем `node@26` и `/opt/homebrew/bin`; хук пуша (`scripts/check.sh`) требует то же и без подходящего Node
останавливается с подсказкой (`brew install node@22` или `NODE_BIN=<каталог с node>`).

## 4. Шаблоны

**Карточка субагента** (писать в файл, перечитать, потом передавать; без самоисправлений в тексте, без «и т. п.» и открытого «исследуй», без
вставленных логов, одна задача на карточку):
- Цель — одна фраза. Ветка и worktree. Зона записи — список путей.
- Контекст — до 10 ссылок `файл:строка`, без вставки документов.
- Шаги: каждый — один коммит на русском («что и почему») + `Co-Authored-By`.
- Проверка после шага — точная команда `admin-web/tools/test.sh …`; «готово» — команда и ожидаемый вердикт (числа до правок).
- Запрещено: push, `main`, `git add -A`/`git add .`, файлы вне зоны, правка файлов через `python3 - <<EOF`, чтение больших документов целиком.

**Отчёт субагента (≤ 15 строк, без пересказа кода):** `СТАТУС: готово | заблокирован (чем)`; коммиты (sha и тема); проверки (команда → вердикт);
отклонения от карточки; вопросы; затронутые файлы.

**Параллелизм на Mac 8 ГБ:** Gradle на Mac — никогда (он на devbox, `scripts/dbx.sh`); не больше 2 тяжёлых Node-процессов одновременно (vitest/jsdom и
`tsc` — по ≈1–1,5 ГБ); перед тяжёлым запуском `pgrep -fl 'gradle|vitest|emulator|tsc'` — соседние сессии делят память; агенты на чтение почти не едят
память — можно до 3.

## 5. Антипаттерны

| Плохо | Как надо |
|---|---|
| `python3 - <<EOF` или `sed -i` для правок | `grep -n` → Read с `offset/limit` на ≈40 строк → Edit; повторы в одном файле — `replace_all`; массовая правка > 5 файлов — Haiku по точному списку (хук отклоняет python-heredoc) |
| чтение файла целиком | `grep -n -C3`, Read с `limit`, документы — по разделу |
| скриншоты браузера | `get_page_text`, `read_page`, `find`; состояние — `javascript_tool`; скриншот только для вёрстки (фаски, плотность), `scale: 0.5` |
| ручное ожидание CI (`sleep`, опрос `run list`) | `scripts/ci-wait.sh pr N` в фоне; `Monitor` только для настоящего потока событий |
| сотни вызовов Bash | склеивать независимые чтения в один вызов; вывод с `--silent`/`-q` и `\| tail` |
| «доверять отчёту агента» | после агентов один раз самому: `tools/test.sh all` и `git diff --stat origin/main..HEAD` (число файлов вне зоны — 0) |

## 6. Что НЕ автоматизировать (и почему)

- **Push в `main`, rebase, `--force`, `--no-verify`** — цена ошибки: переписанная история или обход хука. Часть запретов проверяет хук
  `.claude/hooks/guard-bash.sh`; в `main` вливают поезд Pipeline и владелец.
- **Удаление веток и worktree** — ветку, влитую пересборкой, по хешу не сопоставить; вердикт даёт `land.sh` или `agent-worktree.sh gone`,
  удаляют по слову владельца; чужие копии не трогать.
- **Автоповтор CI «до зелёного»** — маскирует флапающие тесты. Единственное исключение — явный сбой окружения вне кода PR (например, обрыв сети
  при скачивании NDK в job `build`): упавший job перезапускается один раз, причина называется в сообщении Pipeline.
- **Автокоммит агентами в общую ветку и автослияние веток агентов** — только через ревью главного.
- **Перезапись эталонов и снимков** — только намеренно, вместе с правкой.
- **Живая проверка против настоящего Моста** остаётся рецептом, не скриптом (слишком много развилок): Мост на devbox (`docs/netrun-devbox.md`,
  ключи роли `NETRUN_KEY_MASTER=…`), на Mac туннель `ssh -N -L 7510:127.0.0.1:7510 devbox`, коллектор с `BRIDGE_URL`/`BRIDGE_MASTER_KEY` на свободном
  порту и своей БД, сценарий через `curl`/`fetch` под сессией мастера. **Уборка обязательна**: остановить Мост, туннель и коллектор, стереть seed и
  временные БД. Пароли и токены — только временные, в чат и репозиторий не писать. Постоянного живого коллектора на devbox нет (после переустановки
  devbox 30.10.2026 `~/live-collector` не восстанавливали): стенд поднимают заново, когда понадобится, и на отдельном порту, не занятом стендом e2e
  (`scripts/e2e/`) и сервисами devbox (`docs/devbox.md`).
