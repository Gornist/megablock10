# Пайплайн работы агента над коллектором

Как вести задачи в `admin-web/` быстро и дёшево по токенам. Выведен из разбора реальной сессии (≈60 ч: 1166 вызовов Bash, 281 правка,
274 чтения, ≈180 вызовов браузера) и проверен на двух рефакторингах и задаче «Сеть». Скрипты — `admin-web/tools/`.

**Где уходили токены.** Чтения — 6,9 млн символов ответов (≈25 тыс. на вызов: читались целые документы — `README.md` 55 КБ,
`docs/netrun-bridge-protocol.md` 58 КБ), Bash — 1,7 млн, скриншоты браузера — 1,5 млн. 123 раза правки шли через `python3 - <<EOF`
вместо Edit; CI ждали 5–8 вызовами с `sleep`; Node выбирался руками при каждом пуше.

## 1. Кто что делает

| Исполнитель | Что | Выигрыш |
|---|---|---|
| **Главный агент (Sonnet)** | разговор с владельцем, план, карточки, ревью диффа (`git diff --stat`, потом точечные куски), коммит, решение о CI, слияние по команде, правки до ~3 вызовов | — |
| **Haiku / Explore** | поиск «где X» (ответ `файл:строка` + ≤ 10 строк), выписка раздела из большого документа, разбор лога упавшего теста, механическая замена по точному списку | 20–80 тыс. токенов чтения остаются у агента, главному приходит ≈1 тыс. |
| **Sonnet-субагент** | реализация по карточке: 3–10 шагов, по коммиту на шаг, команда приёмки | контекст главного не забивается и не сжимается; общий расход примерно тот же |
| **Opus** | только контракты с Мостом и внешними протоколами, миграции БД и путь ingest/целостности (деньги игроков), auth/crypto/gameSecret, ревью рискованного диффа перед слиянием, разбиение эпика на карточки | дорогой по лимитам — звать точечно |

**Делегировать, если выполнены ВСЕ условия:** задача описывается карточкой на один экран; приёмка проверяется командой; файлы не
пересекаются с другой текущей работой; агенту придётся прочитать > 30 тыс. токенов, а отчёт уложится в 2 тыс.
**Не делегировать:** нужен диалог с владельцем или угадывание намерения; сквозной дизайн; push, main, удаления; задача меньше трёх
вызовов (карточка дороже работы).

## 2. Стадии

| Стадия | Как | Параллельно? | Барьер |
|---|---|---|---|
| Разведка | Haiku на чтение: `файл:строка` + выжимка | да, до 3 | — |
| План | главный пишет карточки (в файл, перечитать один раз) | нет | согласие владельца, если меняется контракт или UX |
| Реализация | Sonnet-агенты, файлы не пересекаются | до 2 (в отдельных worktree) | после каждого шага `tools/test.sh <часть>` и коммит |
| Проверка | главный: `tools/test.sh all` | нет | всё зелёное **своими глазами**, отчётам агентов не верить на слово |
| CI | `tools/ci.sh` в фоне; пока ждём — ревью следующей карточки | да | зелёный CI на точном sha |
| Слияние | `tools/merge-ready.sh` — вердикт; сам push — по команде владельца | нет | явная команда владельца |
| Уборка | `tools/branch-gone.sh` — вердикт; удаление руками | — | вердикт «целиком» |

**Не раздувать контекст главного:** в отчётах субагентов нет кода; главный не перечитывает файлы, которые прочитал агент, а смотрит
его дифф; длинный вывод — в файл, в контекст только `tail -n 30` или grep по вердикту; вперёд читать `docs/progress.md`,
`git log -10`, `git diff --stat`, а большие документы — `grep -n` и Read с `offset/limit` (README коллектора целиком не читать).

## 3. Скрипты (`admin-web/tools/`)

Один скрипт — одна ответственность; в stdout 1–5 строк вердикта, полный лог — `/tmp/mb10-tools/`, код выхода 0/1.

| Скрипт | Что делает |
|---|---|
| `test.sh server\|client\|lint\|build\|all [--grep шаблон]` | сам выбирает Node, части идут по очереди (8 ГБ), вердикт `server: ок — 390 из 400, пропущено 10 (15с)` или имена упавших тестов. `all` ≈ 40 с |
| `ci.sh [ветка] [workflow]` | запуск CI на запушенной ветке, свой run ищется по sha и времени, ожидание, вердикт одной строкой; при провале — упавшие job и ≤ 30 строк журнала. **Запускать в фоне** (`run_in_background`) — придёт одно уведомление |
| `preflight.sh` | (только чтение) ahead/behind относительно main, правки вне зоны `admin-web/`, неотслеживаемое в зоне |
| `merge-ready.sh <ветка>` | (только чтение) перемотка возможна? CI зелёный именно на этом sha? Печатает команду слияния, **не выполняет** |
| `branch-gone.sh <ветка>…` | (только чтение) сравнивает содержимое файлов ветки с `origin/main`: `git cherry` врёт, когда ветку влили пересборкой |
| `wt-deps.sh [server\|client]` | в свежем worktree заменяет симлинки `node_modules` на `npm ci` (иначе версии основной копии не совпадут с веткой) |

Живая проверка против настоящего Моста (туннель, seed, `devjob`) пока рецептом, не скриптом: см. раздел 6 — слишком много развилок,
скрипт без `trap`-уборки хуже ручного.

### Node
Нужен **Node ≥ 22**: `better-sqlite3` 13 на Node 20 падает SIGSEGV, vitest 5 на 20 не стартует. Скрипты берут `$NODE_BIN`, затем
`/opt/homebrew/opt/node@22/bin`, затем `/opt/homebrew/bin` (26). **Хук `git push`** (`scripts/check.sh`) знает только 22 и 20 и без
`node@22` берёт 20 — пуш падает на тестах сервера. До правки хука: `NODE_BIN=/opt/homebrew/bin git push …` или `brew install node@22`.

## 4. Шаблоны

**Карточка субагента** (писать в файл, перечитать, потом передавать; без самоисправлений в тексте, без «и т. п.» и открытого
«исследуй», без вставленных логов, одна задача на карточку):
- Цель — одна фраза. Ветка и worktree. Зона записи — список путей.
- Контекст — до 10 ссылок `файл:строка`, без вставки документов.
- Шаги: каждый — один коммит на русском («что и почему») + `Co-Authored-By`.
- Проверка после шага — точная команда `admin-web/tools/test.sh …`; «готово» — команда и ожидаемый вердикт (числа до правок).
- Запрещено: push, main, `git add -A`/`git add .`, файлы вне зоны, правка файлов через `python3 - <<EOF`, чтение больших документов целиком.

**Отчёт субагента (≤ 15 строк, без пересказа кода):** `СТАТУС: готово | заблокирован (чем)`; коммиты (sha и тема); проверки
(команда → вердикт); отклонения от карточки; вопросы; затронутые файлы.

**Параллелизм на Mac 8 ГБ:** Gradle на Mac — никогда; не больше 2 тяжёлых Node-процессов одновременно (vitest/jsdom и `tsc` —
по ≈1–1,5 ГБ; браузерная панель с vite считается за один); перед тяжёлым запуском `pgrep -fl 'gradle|vitest|emulator|tsc'` —
соседние сессии делят память; devbox — одна задача на машину; агенты на чтение почти не едят память — можно до 3.

## 5. Антипаттерны

| Было | Как надо |
|---|---|
| `python3 - <<EOF` для правок (123 раза) | `grep -n` → Read с `offset/limit` на ≈40 строк → Edit; повторы в одном файле — `replace_all`; массовая правка > 5 файлов — Haiku по точному списку |
| чтение файла целиком | `grep -n -C3`, Read с `limit`, документы — по разделу |
| скриншоты (≈1,5 млн симв.) | `get_page_text`, `read_page`, `find`; состояние — `javascript_tool`; скриншот только для вёрстки (фаски, плотность), `scale: 0.5` |
| ручное ожидание CI (`sleep` + `run list` + `watch`) | `tools/ci.sh` в фоне; не крутить `Monitor` по `git log` — агенты в фоне и так присылают уведомление; `Monitor` только для настоящего потока событий |
| 1166 вызовов Bash | склеивать независимые чтения в один вызов; вывод с `--silent`/`-q` и `\| tail` |
| «доверять отчёту агента» | после агентов один раз самому: `tools/test.sh all` и `git diff --stat origin/main..HEAD` (число файлов вне зоны — 0) |

## 6. Что НЕ автоматизировать (и почему)

- **Push в `main`, rebase, `--force-with-lease`, `--no-verify`** — цена ошибки: переписанная история или обход хука. Скрипт печатает
  команды, выполняет человек/главный по явной команде владельца. Порядок слияния: `merge-ready.sh` → если main ушёл вперёд:
  `git rebase origin/main`, `push --force-with-lease`, повторный `ci.sh` → `git push origin <sha>:main --no-verify`.
- **Удаление веток и worktree** — ветку, влитую пересборкой, по хешу не сопоставить; ошибочный вердикт уничтожит работу. Вердикт даёт
  скрипт, удаляют руками; чужие копии без ведома владельца не трогать.
- **Автоповтор CI «до зелёного»** — маскирует флапающие тесты (один такой агент уже нашёл: гонка в синке СБ).
- **Автокоммит агентами в общую ветку и автослияние веток агентов** — только через ревью главного.
- **Перезапись эталонов/снимков** — только намеренно, вместе с правкой.
- **Живая проверка на Мосте как скрипт** — рецепт: на devbox `devjob start` Моста из ветки `agent/netrun`
  (`netrun-bridge/build/install/netrun-bridge/bin/netrun-bridge --port 7510 --line-port 7511 --db /tmp/x.db --test --seed seed.json`,
  ключи `NETRUN_KEY_MASTER=km …`), на Mac `ssh -N -L 7510:127.0.0.1:7510 devbox`, коллектор с `BRIDGE_URL`/`BRIDGE_MASTER_KEY=km` на
  свободном порту и своей БД, сценарий через `curl`/`fetch` под сессией мастера; **уборка обязательна**: остановить задачу и туннель
  и коллектор, стереть seed и `/tmp/*.db` на devbox. Пароль/токены — только временные, в чат и репозиторий не писать.

## 7. Что вне зоны `admin-web/` (предложения владельцу, сам не менял)

1. Хук пуша `scripts/check.sh`: добавить `/opt/homebrew/bin` (Node 26) в перебор или потребовать ≥ 22 вместо тихого отката на 20.
2. `scripts/agent-worktree.sh`: опция «настоящий `npm ci` вместо симлинка `node_modules`» (сейчас — `tools/wt-deps.sh`).
3. Настройки харнесса (`.claude/settings*.json`): allowlist на `admin-web/tools/*.sh` (меньше запросов разрешений); deny на
   `git add -A*`, `git push*--force*`, `git push*:main*` вместо правила «в памяти»; хук, отклоняющий `python3 - <<` при правке
   файлов в `admin-web/`. Решение за владельцем.
