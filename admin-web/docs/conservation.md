# Коллектор: состояние на консервацию (11.11.2026)

Решение владельца 11.11.2026: проект консервируется, всё, что есть, задокументировано и лежит на GitHub. Это документ для того, кто через
месяц или год откроет `admin-web/` и должен за час понять, что работает, чего нет и как это поднять. Устройство и справочник —
[admin-web/README.md](../README.md); контракт выдачи персонажа — [provisioning-qr.md](../../docs/provisioning-qr.md) и
[character-reissue.md](../../docs/character-reissue.md); день игры — [game-day-checklist.md](../../docs/game-day-checklist.md); сеть
площадки — [network-spec.md](../../docs/network-spec.md).

## 1. Что работает

Проверено на `main` (3bfa5630, 11.11.2026): `admin-web/tools/test.sh all` — сервер 451 из 461 (10 пропущено, провалов нет), клиент 101 из 101,
lint и сборка клиента без ошибок; CI (`main.yml`, job `admin-web`) зелёный на последнем PR коллектора. Сквозной стенд на двух эмуляторах (`scripts/e2e/`,
CI `e2e.yml` на PR с правкой `app/`, `kit/`, `scripts/e2e/`) в этой проверке не гонялся.

- **Приём записей** `POST /api/changes`: подпись ECDSA P-256, закрытые списки полей и причин, идемпотентность по `id` и `(subject, seq)`, откат
  всего батча при сбое, лимит запросов, секрет игры. Покрыт тестами, включая конфликт `seq` и откат (`changeIngestBatch.test.ts`).
- **Снимки персонажей, пульс, тревоги, проверки целостности** — всё считается из таблицы `changes`; пороги настраиваются переменными `ATTN_*`/`ANOM_*`.
- **Дашборд мастера** (React): Обзор, События, Игроки, Фракции, Экономика, Переводы, Объявления, Журнал, Устройства, Узлы, Сеть, Локации, Громкая
  связь, Каналы звука, Мастерская (генератор QR), Реестр тиражей.
- **Рычаги мастера**: правка и массовая правка, объявления, аннулирование и возврат слотов, закладки, откладывание тревог, новые мастера, CSV-выгрузка.
- **Выдача персонажей**: QR, одноразовость, «Выдать заново», короткий код для телефонов без камеры (`POST /api/provisions/redeem`) с защитой от подбора.
- **Арбитраж уникальных слотов** (`POST /api/slots/:slotRef/claim`).
- **«Сеть»**: приём записей мира (`net.run|item|alert|breach`), быстрые события на точки, связь с Мостом по WebSocket (проверена против фейкового Моста
  `npm run fake-bridge` и против настоящего на стенде), допуск нетраннеров, наполнение узлов. Без `BRIDGE_MASTER_KEY` выключено, остальное работает.
- **Точки на площадке**: сервер ведёт QR-дисплеи и звук по TCP 47200, батарею, локации, громкую связь (проверено с прошивкой для ПК `display_host`).
- **Резервные копии** раз в 30 минут (`VACUUM INTO`, последние 20), боевой режим `MB10_MODE=production`, systemd-юнит.
- **Контракты с приложением и Мостом**: общие известные ответы в `rules/src/test/resources/contracts/*.json`, правило версий `capabilities`
  (`world_records 2`, `world_events 1`, `provisionCode 1`).

## 4. Известные проблемы и подводные камни

- **Лимитеры только в памяти** (`/api/changes`, `/api/world-events`, обмен кода): после перезапуска счётчики и паузы обнуляются.
- **Миграции только вперёд.** Версия схемы — `PRAGMA user_version`; кода отката нет. Старый код на БД после новой миграции (последняя — №8, колонка
  `provisions.short_code`) не проверялся: для возврата — копия БД из `backups/`, снятая до обновления.
- **Копии лежат на той же машине.** `BACKUP_DIR` — тот же диск; интернета на площадке нет. Раз в игру и после неё копировать `data/backups` на внешний
  носитель руками.
- **`GAME_SECRET` менять нельзя в ходе игры:** он же даёт ключ шифрования лута — напечатанные QR перестанут читаться, устройства разлогинятся.
- **`PUBLIC_URL` задать до печати QR персонажей:** он попадает внутрь кода.
- **Боевой режим не стартует** без `GAME_SECRET` от 8 символов и хотя бы одного мастера: код выхода 78, systemd не перезапускает (`journalctl -u mb10-admin`).
- **Разные наборы `wireVersions`** в парке (старая и новая сборка) дают мастеру предупреждение «Другая версия протоколов» — это ожидаемо при обновлении.
- **Микрофон для громкой связи** браузер даёт только по https или на localhost: по http из сети объявление записывают на телефон и загружают файлом.
- **Флейк `audio.test.ts`** («громкая связь: клип докачивается») мигнул один раз; зона Физических узлов.
- **`scripts/ci-wait.sh`** может ответить «зелёное», пока часть job ещё идёт, — сверять `gh pr checks N`; job `build` иногда падает от сети (скачивание NDK) —
  перезапуск упавшего job.
- **Устарело, но не в зоне коллектора:** `docs/netrun-collector-brief.md` («в `main` пока нет», «на ветке `agent/netrun`»). Скрипты `admin-web/tools/merge-ready.sh`
  и `branch-gone.sh` пережиты процессом слияний через Pipeline и нужны разве что вне процесса PR.

## 5. Как поднять коллектор с нуля

### 5.1. На площадке (сервер 10.10.0.10, порт 2517, без интернета)

Интернета на площадке нет и не будет: всё готовится заранее на машине с интернетом.

1. **Подготовка (дома).** Node ≥ 22 (на Node 20 `better-sqlite3` падает SIGSEGV). Клон репозитория, затем:
   ```bash
   cd admin-web/server && npm ci && npm run build
   cd ../client && npm ci && npm run build        # собирает SPA в client/dist
   ```
   `better-sqlite3` — нативный модуль: собирать на машине той же ОС, архитектуры и версии Node, что у сервера (или выполнить `npm ci` на самом сервере до
   выезда). Всю папку `admin-web/` вместе с `node_modules` и собранными `dist` увезти на носителе; Node 22 — тоже (пакет или tarball).
2. **Мастер и данные.** На сервере, в `admin-web/server`: `npm run create-master -- "Имя"` — токен печатается один раз, сохранить. Тот же `DB_PATH`, что у службы
   (по умолчанию `./data/mb10-admin.sqlite`).
3. **Служба.** Юнит `admin-web/deploy/mb10-admin.service` (инструкция в его начале): поправить `User`/`WorkingDirectory`/пути, `GAME_SECRET` (от 8
   символов), `PUBLIC_URL=http://10.10.0.10:2517`; `systemctl enable --now mb10-admin`. Без systemd: `MB10_MODE=production GAME_SECRET=… PUBLIC_URL=… PORT=2517 npm start`.
4. **Проверка.** `curl http://10.10.0.10:2517/api/health` → `{"ok":true}`; `curl …/api/capabilities` → `{"world_records":2,"world_events":1,"provisionCode":1}`;
   дашборд в браузере `http://10.10.0.10:2517`, вход — именем и токеном мастера; в `data/backups/` через несколько минут появился файл.
5. **Сеть.** Адрес сервера фиксирован (резерв DHCP на шлюзе); один SSID, одна подсеть 10.10.0.0/23; изоляция клиентов и фильтрация multicast выключены; порт 2517
   открыт для телефонов; ИБП на шлюз, коммутатор и сервер. Сервер сам подключается к точкам по TCP 47200 — точкам нужны постоянные IP (резерв DHCP), Wi-Fi площадки
   должен вещать и в 2,4 ГГц (ESP32).
6. **Телефоны.** Одна сборка приложения на всех (APK из GitHub Actions, `apk.yml`). Игрок сканирует QR персонажа из «Мастерской» → «Персонаж» (адрес, код игры и персонаж
   приходят в одном QR) или вводит короткий код.
7. **Точки.** В «Локациях» добавить точку (id, постоянный IP, локация, узел), прошить строкой из коллектора, дождаться «на связи» ≤ 30 с — [displays.md](../../docs/displays.md),
   [sound-nodes.md](../../docs/sound-nodes.md).
8. **«Сеть» (если нужна).** Мост `netrun-bridge` на том же мини-ПК; в окружении коллектора `BRIDGE_MASTER_KEY` (ключ роли `master` Моста) и при необходимости `BRIDGE_URL`
   (по умолчанию `ws://127.0.0.1:7410/netrun/v1`) — [docs/netrun-devbox.md](../../docs/netrun-devbox.md), [netrun-bridge-protocol.md](../../docs/netrun-bridge-protocol.md).
9. **День игры** — по [game-day-checklist.md](../../docs/game-day-checklist.md): резервные копии, QR узлов и персонажей, батареи точек, «не менять `GAME_SECRET`».

**Восстановление из копии** (службу остановить): `rm -f mb10-admin.sqlite-wal mb10-admin.sqlite-shm; cp backups/<файл>.sqlite mb10-admin.sqlite`, затем запуск.
Телефоны досылают записи, принятые после момента копии; правки и объявления мастера после него придётся повторить.

### 5.2. На devbox (стенд живой проверки с телефонами)

devbox — машина разработки, не игровой сервер: Ubuntu, `192.168.1.141`, пользователь `nick` (после переустановки 30.10: `ssh-keygen -R 192.168.1.141`), правила — [docs/devbox.md](../../docs/devbox.md).
Коллектора на ней постоянно нет; поднимать нужно под задачу и на своём порту.

```bash
ssh devbox
# Node 22 и клон ~/megablock10 — scripts/devbox-setup.sh и scripts/devbox-bootstrap.sh (если после переустановки их ещё нет)
cd ~/megablock10/admin-web/server && npm ci && npm run build
cd ../client && npm ci && npm run build
cd ../server
export DB_PATH=$HOME/live-collector/data/mb10.db PORT=2527 GAME_SECRET=<не короче 8> PUBLIC_URL=http://192.168.1.141:2527
npm run create-master -- "Имя"            # токен — в файл вне репозитория, в чат не писать
nohup node dist/index.js > $HOME/live-collector/log.txt 2>&1 &
```

- **Порт:** 2517 занят стендом e2e (`scripts/e2e/up.sh`), 2527 использовался прежним живым стендом; `PUBLIC_URL` — адрес devbox в LAN, который телефоны видят в одной сети с ним.
- **Телефоны** подключены к devbox по USB (XCover7, RCPad) — бронь устройства `scripts/box.sh lease xcover7 Коллектор <мин>`, управление `scripts/phone.sh`; выдача персонажа и
  проверка — через дашборд на `http://192.168.1.141:2527`.
- Форма запуска через `scripts/box.sh up <служба> <сессия> --port N` (свой экземпляр службы с портом и каталогом) в `docs/devbox.md` «D4» описана, но для коллектора не проверялась.
- **Стенд e2e** (два эмулятора и коллектор :2517) поднимает `scripts/e2e/up.sh` и гоняет `scripts/e2e/run-all.sh`, подробности — `scripts/e2e/README.md`.
- По окончании работы остановить процесс и удалить БД и токен: `kill` процесса, `rm -rf ~/live-collector`.

### 5.3. На Mac (разработка и тесты)

`brew install node@22`, `scripts/agent-worktree.sh new <имя>`, `admin-web/tools/wt-deps.sh`, затем `admin-web/tools/test.sh all`. Сервер для разработки:
`cd admin-web/server && PORT=2517 npm run dev`, клиент — `cd admin-web/client && npm run dev` (Vite с прокси `/api` → :2517).
