# Мастерский веб-дашборд — коллектор

Отдельная папка проекта (не Android, не Gradle): сервер и дашборд мастера для живой игры. Состояние на 30.10.2026 (`main`).

**Что это.** Телефоны игроков шлют на сервер подписанные записи об изменениях (`POST /api/changes`); сервер хранит их как единственный
источник правды, собирает из них снимок каждого персонажа, считает подсказки и тревоги и даёт мастеру экраны и рычаги (правки, объявления,
выдача персонажей, арбитраж тиражного лута, QR для печати). К нему же подключены «Сеть» (через Мост), электронные точки на площадке
(QR-дисплеи и звук) и стенд e2e. Один процесс Node, одна БД SQLite, без Docker и без интернета на игре.

| Где | Что |
|---|---|
| `server/` | Fastify + better-sqlite3 + TypeScript. `src/routes/` — API, `src/lib/` — приём, проекция, проверки, подсказки, `src/net/` — клиент Моста, `src/displays/`, `src/audio/` — точки (зона Физических узлов), `src/db/` — схема и миграции |
| `client/` | React + Vite + TS без UI-фреймворка. Меню — `src/nav.ts`, экраны — `src/routes.tsx` |
| `deploy/mb10-admin.service` | systemd-юнит для выделенной машины |
| `tools/` | скрипты проверки для агентов — [docs/agent-pipeline.md](docs/agent-pipeline.md) |
| `../docs/provisioning-qr.md`, `../docs/character-reissue.md` | контракт выдачи персонажа (пишет коллектор, читает Android) |

## Важно про Node

Нужен **Node ≥ 22** (в CI — 22 LTS; `engines` в `server/package.json`): `better-sqlite3` 13 на Node 20 падает SIGSEGV, vitest 5 на 20
не стартует. На Mac Node 22 стоит keg-only:

```bash
brew install node@22
export PATH="/opt/homebrew/opt/node@22/bin:$PATH"   # или добавить в PATH заранее на ноутбуке мастера
```

На выделенной машине (`deploy/mb10-admin.service` запускает `/usr/bin/node`) проверьте `node -v` — должно быть v22.x и выше.
Проверки одной командой и в нужном Node — `admin-web/tools/test.sh all` (см. [docs/agent-pipeline.md](docs/agent-pipeline.md)).

## Запуск на игре (один процесс, без Docker)

```bash
cd admin-web/server && npm install
cd ../client && npm install && npm run build   # собирает SPA в client/dist

cd ../server
npm run create-master -- "Имя мастера"   # один раз — печатает токен для входа, больше нигде не покажется
PORT=2517 npm run build && npm start
```

Сервер сам раздаёт собранный `client/dist` с того же порта (`http://<ip ноутбука>:2517`) — второй процесс не нужен; mDNS не используется,
телефоны получают адрес из QR персонажа. Ещё одного мастера можно завести без консоли: `POST /api/masters` (токен виден один раз в ответе).
`GET /api/health` — проверка живости без авторизации.

## Оформление

Тот же визуальный язык, что у Android-приложения игрока (`docs/ux/ui-style-guide.md`, живой эталон — `docs/ux/prototype/mb10-ui-kit.html`):
кабинет мастера и телефон читаются как один продукт.

- **Роли цвета** (токены — `client/src/design/tokens.css`, один цвет — одна роль): `acc` (бирюзовый — активное, фокус, основная кнопка),
  `money` (жёлтый — **только** деньги и счётчики нового), `ok`/`warn`/`bad` (подтверждено / ждёт действия / ошибка), `chrome` (приглушённый
  красный — линии, неактивные пункты, подписи). Действие мастера в ленте изменений узнаётся по метке «МАСТЕР», а не по цвету.
- **Шрифты** — самохостинг через `@fontsource/*` (интернета на игре нет): Fira Sans Condensed (текст и заголовки), IBM Plex Mono (моно).
- **Формы рамок** — [augmented-ui](https://github.com/propjockey/augmented-ui) (`client/public/vendor/augmented-ui.min.css`, статикой, не
  через сборщик; как обновить — `client/public/vendor/README.md`). Три силуэта по роли элемента: **std** (правый верхний + левый нижний
  угол) — кнопки, панели-карточки; **tab** (правый нижний) — плитки, метки, поля, строки меню; **dlg** (правый верхний + полоса `dlgBar`
  слева) — модальные окна. Ховер и фокус — `filter: drop-shadow(...)`, а не `box-shadow` (его обрезало бы вместе с углом).
- **Анимации** — только статус-сигналы (пульс «на связи», пульс срочной тревоги) и переходы на hover/focus; отключаются через
  `prefers-reduced-motion`. Ни анимаций при скролле, ни движущегося скан-лайна: это рабочий инструмент на живой игре.
- **Раскладка** — своя (гайдлайн рассчитан на 360–390 dp, дашборд — на широкий экран). Меню слева на всю высоту, две группы по вопросу
  мастера: «Игра» (Обзор, События, Игроки, Фракции, Экономика, Переводы, Объявления, Журнал) и «Мир» (Устройства, Узлы, Сеть, Локации,
  Громкая связь, Каналы звука, Мастерская, Реестр тиражей); громкая связь — ещё и кнопкой в шапке. Уже 900 px (телефон мастера) меню
  становится полосой сверху (`App.tsx`, `design/layout.css`). Прежние адреса экранов (`displays`, `sound`) перенаправляются (`nav.ts`).

## Секрет игры

`POST /api/changes`, `POST /api/slots/:slotRef/claim` и `POST /api/world-events` открыты без авторизации мастера — на них стучатся устройства
игроков и Мост; подлинность записи гарантирует её подпись ECDSA. `GAME_SECRET` — необязательный общий пароль игры от случайного шума в той
же Wi-Fi-сети (автосканеры, чужой телефон), не замена подписи и не авторизация игрока:

```bash
GAME_SECRET=какая-нибудь-строка npm start
```

Если задан — сервер требует заголовок `X-Game-Secret` с тем же значением на этих эндпоинтах, иначе 401 (счётчик «неверный секрет» идёт
в пульс). Не задан — проверка выключена. В приложении секрет вводится там же, где адрес коллектора (Профиль → «Сеть» → «Мастерский
коллектор»), или приходит полем QR персонажа ([docs/provisioning-qr.md](../docs/provisioning-qr.md)).

`GAME_SECRET` также определяет ключ шифрования лута в QR контейнеров и шардов (`lib/lootCrypto.ts` → `deriveLootKey`, HKDF-SHA256;
зеркало на Android — `LootCrypto.deriveKey`; без секрета ключ один на все игры). Отсюда правило **не менять `GAME_SECRET` в ходе игры**:
смена разлогинит устройства и сделает нечитаемыми уже напечатанные, но ещё не отсканированные QR.

## Боевой режим

`MB10_MODE=production` (в systemd-юните включён) — защита от запуска «открытым» по недосмотру. Сервер не стартует (код выхода 78, systemd
его не перезапускает), пока не выполнено всё из списка:

- задан `GAME_SECRET` длиной от 8 символов (заглушка из юнита не принимается);
- в базе есть хотя бы один мастер (`npm run create-master`).

Причины отказа печатаются в лог (`journalctl -u mb10-admin`). Без переменной (разработка, тесты) ограничений нет.

## Резервные копии и выгрузка

Сервер сам, без внешних крон-скриптов, каждые `BACKUP_INTERVAL_MS` (плюс один раз при старте) снимает консистентную копию БД через
`VACUUM INTO` в `BACKUP_DIR` и хранит последние 20 файлов. На выделенной машине это единственная копия состояния игры. Копия — целая БД:
вся история `changes` (из неё пересчитывается любое состояние игроков), очередь доставки правок, журнал мастеров, наблюдение, контейнеры,
заявки на слоты, мастера и хэши сессий.

**Восстановление** (сервер остановить, иначе он перезапишет файл):

```bash
sudo systemctl stop mb10-admin
cd admin-web/server/data
rm -f mb10-admin.sqlite-wal mb10-admin.sqlite-shm      # хвосты старой базы
cp backups/mb10-admin-<время>-<суффикс>.sqlite mb10-admin.sqlite
sudo systemctl start mb10-admin
```

Телефон хранит принятые сервером записи ещё 6 часов (журнал подтверждённых). После восстановления сервер отвечает телефону меньшим
последним номером его записей (`knownSeq`), и телефон сам досылает всё, что было принято после момента копии. Правки и объявления мастера
после момента копии досылать некому — их придётся повторить.

**CSV** (`GET /api/export/<вид>.csv`, нужна сессия мастера): `players`, `nodes`, `slots`, `history` (вся история `changes` по порядку
получения) и `audit` (журнал действий мастеров). CSV — для чтения и таблиц, не для восстановления.

## Автозапуск на выделенной машине (systemd)

Для Raspberry Pi или любого Linux-хоста в игровой сети — юнит `admin-web/deploy/mb10-admin.service` (сам не активируется, установка и правка
путей — см. комментарий в начале файла). Автозапуск при включении машины и перезапуск при падении (`Restart=on-failure`).

## Приём записей и контракты с телефоном

- **`POST /api/changes`** — батч подписанных записей (не больше 200). Проверка ECDSA-подписи (secp256r1, байты подписи — десять полей через
  `|`, `lib/changeRecord.ts`), закрытые списки полей и причин, значения по виду поля, идемпотентность по `id` (повтор той же записи — «принято»;
  другая запись с занятым `id` — отказ) и по `(subjectKeyB64, seq)` (другая запись с занятым `seq` — отказ `seq already used by a different record`).
  Битая запись не роняет батч; батч пишется одной транзакцией, исключение посередине откатывает всё. Каждый отказ приходит в `rejected` с причиной —
  **телефон после отказа удаляет запись из очереди**, поэтому новое поле или причина сначала принимается здесь, и только потом начинает
  отправляться (правило ниже).
- **Таблица причин** — `REASON_INFO` в `lib/changeRecord.ts`: на каждую причину подпись для дашборда и признаки `gainsBalance` (баланс по ней
  законно растёт), `reward` (награда за игру — пульс и выбросы), `transfer` (деньги лишь переезжают между игроками). `Reason`, `REASONS`,
  подписи и четыре списка проверок выводятся из неё; новая причина добавляется только там.
- **`GET /api/capabilities`** (открытый, лимитированный): `{"world_records":2,"world_events":1,"provisionCode":1}`. `world_records` — какие записи
  мира принимает приём (1 — `net.run|item|alert`, 2 — ещё `net.breach`/`NET_BREACH`); `world_events` — есть `POST /api/world-events`;
  `provisionCode` — есть обмен короткого кода. **Правило версий** (`docs/netrun-world-records.md`, п. 5 раздела 5): коллектор принимает записи и
  события всех прежних версий; читать старый формат он перестаёт только после того, как Мост перестал его писать. Пишущая сторона поднимает версию
  только после того, как читающая принимает и старую, и новую.
- **Heartbeat.** Тем же запросом телефон шлёт `presence`: `appVersion`, `wireVersions` (любые ключи `^\w{1,16}$`, значения 0…999, до 8 — сервер
  их не сверяет, мастер видит расхождения в «Требует внимания»), очередь неотправленных записей (`pendingCount`, `oldestPendingAgeMs`), порт чата.
- **Общие известные ответы** лежат в `rules/src/test/resources/contracts/*.json` (README рядом): байты подписи, подписи ECDSA, списки полей
  и причин, строки QR, ключи и блоки лута, короткий код. Их читают тесты приложения и коллектора; расхождение краснит CI, а не обнаруживается на
  площадке. Формат меняется только вместе с файлом и по правилу версий выше.
- **Ограничение частоты.** На `/api/changes` — 120 запросов в минуту на адрес (телефону нужно ~2), сверх лимита 429 с `Retry-After`, приложение
  повторяет с нарастающей паузой.
- **Время сервера.** «За час», динамика узла и «последний взлом» считаются по времени прихода записи на сервер, а не по часам телефона.
- **Миграции БД** — `PRAGMA user_version`, база — версия 1, дальнейшие изменения таблиц добавляются элементами `MIGRATIONS` в `db/index.ts`
  (порядок проверяет `validateMigrationSequence`, тесты — `dbMigrations.test.ts`); аналог для Android — `docs/db-migrations.md`.
  Снимок персонажа считается SQL-агрегатом по `changes` на каждый запрос, отдельной таблицы-снимка нет.
- **Формат JSON** в `oldValue`/`newValue` для `daemons.*`, `shards.*`, `counters.*` — рабочий, формально не зафиксированный; при расхождении
  смотреть `projection.ts` (сервер) и `ShardStore`/`DaemonStore`/`SecAlertStore`/`BreachScreen` (клиент).
- **Типы ответов API** описаны один раз в `server/src/apiTypes.ts`, клиент импортирует их оттуда; справочник причин и типов для фильтров
  отдаёт `GET /api/meta` (единственный источник подписей).

## Управление игрой (экраны и API поверх наблюдения)

### Обзор → «Требует внимания» (`GET /api/attention`)

Правила — функции в `lib/attentionRules/` (реестр — `lib/attention.ts`), ничего не пишут и не решают за мастера: отрицательный баланс, крупное
поступление за час, пропавший со связи игрок, узел с исчерпанным тиражом, который продолжают ломать, повторно аннулированный слот, правка
мастера, не дошедшая до игрока (критично, если телефон на связи), другая версия приложения или протоколов, записи не доходят до сервера,
батарея точек, флэтлайн и тревоги аудитора «Сети», перебор коротких кодов персонажа, тревоги пульса и проверки целостности.

Пороги — переменные окружения (минуты, если не сказано иное): `ATTN_BALANCE_JUMP` (1000), `ATTN_SILENT_MIN` (10; короче ~40 с не ставить: телефон
шлёт heartbeat раз в ~30 с), `ATTN_SILENT_MAX_MIN` (180), `ATTN_UNDELIVERED_MIN` (2), `ATTN_SYNC_STUCK_MIN` (3), `ATTN_TRANSFER_STUCK_MIN` (10),
`ATTN_INTEGRITY_HOURS` (12, часы). «Разрыв цепочки баланса» на стенде e2e появляется всегда: debug-команды `--es balance N` меняют баланс без записи
об изменении; в настоящей игре так делает только мастер, а его правки детектор исключает.

**Проверки целостности** (`lib/integrity.ts`, без изменения протокола): разрыв цепочки баланса (`oldValue` записи не равен `newValue` предыдущей
у того же игрока; значения мастера не в счёт), один платёж или предмет, полученный двумя игроками (модифицированный клиент), перевод без пары
дольше `ATTN_TRANSFER_STUCK_MIN`, сумма перевода не сходится, крупный рост баланса по причине, не дающей денег. Зависший платёж мастер разбирает
правкой баланса игрока, приложение само его не отменит.

**Пульс игры** (`GET /api/pulse?minutes=60`, графики на Обзоре): раз в `PULSE_INTERVAL_MS` (60 с) в таблицу `pulse_samples` пишется снимок —
игроки на связи (окно `ONLINE_WINDOW_MS`, 5 мин), записи и heartbeat, отклонённые записи по причинам, отказы по лимиту и секрету, задержка приёма,
взломы, выданные эдди, переводы, недоставленные правки. Хранится неделю. По нему работают детекторы (`lib/anomalies.ts`), они без состояния:
тревога живёт, пока условие держится на последних сэмплах, и сама гаснет.

| Детектор | Пороги (по умолчанию) |
|---|---|
| массовая потеря связи: онлайн ниже доли пика два сэмпла подряд | `ANOM_SILENCE_RATIO` 0,7; `ANOM_SILENCE_MIN_PEAK` 5 |
| всплеск отклонений (подпись и чужой автор — срочно) | `ANOM_REJECT_MIN` 10; `ANOM_REJECT_SHARE` 0,3 |
| лимит запросов, неверный секрет игры | — |
| тормоза сервера | `ANOM_SLOW_MS` 500 |
| часы устройства спешат | `ANOM_CLOCK_AHEAD_MIN` 5 |
| скачок эмиссии эдди (3 минуты против часа, нужно ≥ 20 сэмплов; медиана и MAD·1,4826, а не константы) | `ANOM_EMISSION_MIN` 1000 |
| игроки-выбросы за 15 минут по взломам и эдди (нужно ≥ 5 активных) | `ANOM_OUTLIER_MIN_BREACHES` 10; `ANOM_OUTLIER_MIN_EDDIES` 2000; `ANOM_OUTLIER_SIGMAS` 5 |

Если сэмплер не работает, тревог по пульсу нет. Тревогу можно отложить («⏸ 30 мин», `POST /api/attention/snooze`): она молчит и вернётся сама, если
условие останется; действие пишется в журнал мастеров. Кнопка 🔔 включает звук и метку `(!)` в заголовке вкладки при новой срочной тревоге.
**Подбор порогов:** `GET /api/anomalies/replay?from=&to=&stepMin=` прогоняет детекторы по записанному пульсу и отвечает эпизодами; прогоните им
стендовый прогон или прошлую игру и поправьте `ANOM_*`. Для стенда окно «на связи» сокращается `ONLINE_WINDOW_MS`, пульс — `PULSE_INTERVAL_MS`.

### Игроки, правки, объявления

- **Игроки** (`GET /api/players`, `/api/players/:key`, `…/history`): таблица с поиском, фильтром, сортировкой, колонкой «Очередь» (неотправленные записи
  телефона); карточка — снимок, демоны, шарды, история, ручная правка. **Состояние на момент T** — `?until=<мс>` (по часам сервера) для разбора споров.
- **Правка мастера** (`POST /api/players/:key/override`, `MASTER_OVERRIDE`, обязательное основание в `source_ref`, пишется в `audit_master`) и
  **массовая правка** (`POST /api/players/bulk-override`): выбранным, фракции или всем; «установить» или «прибавить» (`+200`, RAM зажимается в 6–13);
  обязательный предпросмотр (`dryRun`) и основание. Правка доставляется, пока телефон не подтвердит применение (`ackIds`); не смог — сообщает
  причину (`failures`), после 5 отказов подряд (или сразу, если повтор бесполезен) сервер перестаёт её слать, и она появляется в «Требует внимания»
  с причиной и числом попыток. Применённая правка встаёт в хронологию телефона по его последнему `seq` в момент применения; неприменённая в снимке
  не участвует — там то, что у игрока на телефоне.
- **Объявления** (`POST/GET /api/announcements`, `GET …/:id/recipients`) — всем или фракции; телефон получает их тем же опросом, что и правки;
  подтверждение даёт статус «доставлено N из M» и список тех, кому не дошло.
- **Фракции** (`GET /api/factions`) и **Экономика** (`GET /api/economy`): деньги, боевая активность, свои/чужие взломы, кому уходят сигналы СБ;
  эдди в обороте по времени, источники эмиссии (без переводов), медиана, топ-10 %, Джини, богатейшие. **Переводы** (`GET /api/transfers`) —
  односторонние подсвечены, отмена отправителем помечается «отменён отправителем».
- **События** (`GET /api/events`) — фильтры по игроку, фракции («без фракции» — `__none__`), типу (деньги / демоны и шарды / взломы / сигналы СБ /
  действия мастера / профиль / Сеть), причине, узлу и периоду, пагинация; первая страница обновляется сама. **Живая лента** Обзора —
  `GET /api/changes/recent?since=` (опрос, не SSE). Мастерские записи не считаются признаком «на связи».
- **Журнал** (`GET /api/audit`) — кто из мастеров, когда и что делал. **Закладки** (`/api/watch`, `PUT/DELETE /api/watch/:key`) — общий список
  игроков «под наблюдением» с пометкой, виден на Обзоре.
- **Узлы** (`GET /api/nodes`, `/api/nodes/:id?hours=`): взломы за час, почасовая динамика исходов, список взломщиков. **Реестр тиражей**
  (`GET /api/slots`, `POST /api/slots/:ref/revoke|restore`): арбитраж уникальных слотов — заявки `POST /api/slots/:slotRef/claim`
  (по секрету игры и подписи ключа); если коллектор недоступен, уникальный слот не выдаётся, обычный лут и эдди начисляются как всегда.
- **Мастерская** (`POST /api/containers`, `/api/master/containers|shards|ram`): генератор QR контейнеров, шардов, RAM-апгрейдов, QR персонажа и
  узла Сети прямо в браузере — конструктор слотов лута, картинка QR и сырая строка для печати, «На дисплей». Шифрование слота (AES-256-GCM, ключ
  игры) и формат QR — те же, что в приложении (`lib/lootCrypto.ts`, `lib/mb10QrCodec.ts`; сверяются общими векторами). Контейнеры сразу пишутся в
  БД, шард и RAM-токен — без сохранения.

## Выдача персонажа

Мастерская → «Персонаж» (позывной, фракция, баланс, RAM): `POST /api/provisions`, `GET /api/provisions` (+ `/:id/qr`, пока код не применён),
`POST /api/players/:key/reissue` («Выдать заново» на карточке игрока). Адрес сервера и код игры подставляет сервер (`PUBLIC_URL`, иначе адрес,
по которому открыт дашборд; `GAME_SECRET` в API не отдаётся, но лежит в самом QR). Формат QR, поведение приложения, одноразовость, короткий код
для телефонов без камеры и защита от его подбора — [docs/provisioning-qr.md](../docs/provisioning-qr.md); сброс сессии и повторная выдача —
[docs/character-reissue.md](../docs/character-reissue.md).

Кратко: код одноразов (`bindProvision` привязывает `id` к ключу первого телефона; второй получает отказ, на Обзоре — срочная тревога «Код персонажа
применили на двух телефонах»). `CHARACTER_RESET` не стирает параметры в снимке, игроку ставится `sessionResetAt`. Повторная выдача гасит прежний код,
а когда новый телефон применяет новый, прежний ключ становится «заменён» (`replacedBy`), у нового видна ссылка на предыдущую сессию (`replaces`).
Заменённые ключи и игроки со сброшенной сессией не считаются в Экономике, Фракциях, Обзоре, тревогах и рассылках (в списке скрыты под «выбывшие N»).
Короткий код (`ABC-DEF`, 6 знаков) показан мастеру рядом с QR; телефон обменивает его на ту же строку QR через открытый `POST /api/provisions/redeem`
(5 неверных подряд с адреса — пауза 5 минут, общий потолок `REDEEM_GLOBAL_PER_HOUR` — 429 всем и тревога мастеру).

## Точки на площадке: QR-дисплеи и звук

Узел-контейнер в мире может быть электронной точкой — ESP32 + e-paper (CrowPanel 5.79″), со звуком — ещё microSD, усилитель и динамик. Сервер сам
подключается к точкам по TCP (порт 47200, подписанные кадры), браузер к ним не ходит. Прошивка — [firmware/display](../firmware/display/README.md).

- **QR на точке.** «На дисплей» у готового QR в Мастерской и в карточке узла: сервер рисует 1-битный кадр из той же строки, что для печати.
- **Где что** (меню «Мир»): **Устройства** — все точки списком (связь, батарея, локация, узел, звук; фильтры, поиск) → карточка точки с командами;
  **Узлы** — секция «Точка» (привязать / отвязать; одна точка — один узел); **Локации** — точки по местам; **Громкая связь** — объявление,
  записанное в браузере или загруженное файлом, на все точки / локации / выбранные, ход по каждой; **Каналы звука** — плейлисты фона.
- **Батарея** каждой точки — %, остаток «≈ N ч»; севшие — сверху и в «Требует внимания».

Протокол, API (`/api/displays*`, `/api/display-groups*`, `/api/audio/*`), настройки `DISPLAY_*`, размер QR на панели и чек-листы для железа —
[docs/displays.md](../docs/displays.md); звук, железо, питание — [docs/sound-nodes.md](../docs/sound-nodes.md). Без железа: `npm run mock-display`
(точка-имитация), прошивка для ПК `display_host` (`--roles display,audio`), `npm run display-load`, `npm run display-print-sheet`. Микрофон для записи
объявлений браузер даёт только по https или на localhost — по http из сети объявление записывают на телефон и загружают «из файла».

## «Сеть» (VR-забеги нетраннеров)

Нетраннер сдаёт «деку» телефоном и проходит узлы в VR. Состояние Сети хранит **Мост** (`netrun-bridge`, Kotlin, на том же мини-ПК); коллектор
остаётся хранилищем игры и для Сети делает четыре вещи. Контракты: [docs/netrun-bridge-protocol.md](../docs/netrun-bridge-protocol.md) (протокол
Моста) и [docs/netrun-world-records.md](../docs/netrun-world-records.md) (записи мира). Без `BRIDGE_MASTER_KEY` всё это выключено, остальной
коллектор работает как раньше.

| Переменная | По умолчанию | Что |
|---|---|---|
| `BRIDGE_MASTER_KEY` | — | ключ роли `master` Моста; нет ключа — экран «Сеть» пишет «Мост не настроен» |
| `BRIDGE_URL` | `ws://127.0.0.1:7410/netrun/v1` | адрес Моста |
| `NET_SEC_SYNC_MS`, `NET_RUNNER_SYNC_MS` | `30000` | как часто сверять документы `settings/sec` и флаги допуска (кроме сверки при каждом подключении) |

**1. Записи мира.** Мост пишет в обычный `POST /api/changes` записи с ключом мира: поля `net.run`, `net.item`, `net.alert`, `net.breach`, причины
`NET_ENTER`, `NET_EXIT`, `NET_FLATLINE`, `NET_ITEM_OWNER`, `NET_ALERT`, `NET_BREACH`. Они сохраняются как все записи (подпись, идемпотентность),
видны в «Событиях» с типом «Сеть» (взлом хранилища — «Взлом хранилища: «позывной», узел, тир, исход, эдди»), но **не** попадают в проекцию
персонажей, балансы, «в сети», целостность и пульс — ключ мира не игрок. Мост читает `GET /api/capabilities` до отправки (см. «Приём записей»).
`NET_FLATLINE` ставит игроку флаг «допуск в Сеть закрыт» (`net_runner_flags`) и тревогу «Флэтлайн»; тревоги аудитора (`NET_ALERT`) — тоже в «Требует внимания».
Причина блока взлома `COOLDOWN` в `BREACH_BLOCKED` — обычная строка с подписью «узел остывает»; поля остывания узла коллектор не пишет и не читает.

**2. Быстрые события на точки.** `POST /api/world-events` (с `X-Game-Secret`, без очереди): `{events:[{id, kind, ts, ttl_ms, node, terminal, session, level}]}`,
виды `run.enter`, `run.exit`, `trace.level`, `ice.hunt`, `flatline`, `lockdown`, `alert.master`. Просроченные (`ts + ttl_ms`) и повторные (по `id`)
отбрасываются. Что играть и на какой точке, решает мастер на экране «Сеть» → «Площадка»: клип по виду события и привязка точки к узлу или терминалу
(`GET /api/net/world-events/config`, `PUT …/actions/:kind`, `PUT /api/net/point-links/:id`, `POST …/test`). По умолчанию события ничего не играют;
`alert.master` на площадку не идёт — только звонок в панели мастера.

**3. Мост ↔ коллектор.** Браузер к Мосту не подключается. Сервер держит одно WebSocket-соединение (`hello` роли `master`, подписка на `node, node_cfg,
session, deck, terminal, alert, master_req, net_query, template, settings`; версия протокола — `BRIDGE_PROTO` в `net/bridgeProtocol.ts`), хранит
копию документов в памяти и отдаёт её через `GET /api/net/state`. Обрыв: переподключение с нарастающей паузой, новый снимок заменяет копию, пока Моста
нет — `bridge: "down"` и пустые данные. Кнопки мастера — REST под `requireMaster`, каждая в журнале: `POST /api/net/pause|link|goal|goal/clear|decide|reply|template/apply`,
`DELETE /api/net/alerts/:id?ver=`, `POST /api/net/ops` (ручные операции с ценностями: `rid` создаёт экран один раз на нажатие, при повторе он тот же — Мост
выполнит операцию один раз). Ответ Моста с отказом доходит как есть: `503 bridge_unavailable`, `409` (конфликт версий, `req_state`, `rid_mismatch`…), `404`.

**4. Свои данные в Мост** (`put` с проверкой версии, при `version_conflict` — перечитать и повторить):
- `settings/sec` — получатели сигнала СБ `{factions: {<фракция>: [ключи телефонов]}, default_faction}` из действующих игроков; пишется при подключении
  и раз в `NET_SEC_SYNC_MS`, только если изменился. Фракция по умолчанию и фракция-владелец узла задаются на экране «Сеть» (`GET/PUT /api/net/sec`,
  `PUT /api/net/nodes/:id/owner`);
- `runner/r_<первые 32 hex SHA-256 ключа>` (ключ игрока — в `data.key`) — решения мастера по нетраннеру: `blocked`/`blocked_reason` («пощадить» и
  ручное закрытие: `POST /api/net/runners/:key/spare|block`), `allowed` («нетраннер», белый список: `PUT /api/net/runners/:key/allowed`), `faction`
  персонажа. Ведутся только игроки, о ком мастер что-то решил; остальным документы создаёт Мост при первом входе. Коллектор — источник правды;
  список: `GET /api/net/runners`, `/api/net/runners/:key`, `GET /api/net/access`;
- `settings/global.require_allowed` — «в Сеть входят только отмеченные нетраннеры» (`POST /api/net/require-allowed`). По умолчанию выключено.

**Экран «Сеть»** (меню «Мир»): шапка (состояние Моста, пауза Сети, рубильник связи с площадкой), «Ждём мастера» с таймером, флэтлайн с «пощадить», тревоги
аудитора, узлы (цель со сроком, пауза, владелец), нетраннеры в Сети, терминалы и очки, «Запрос к Сети», заготовки, фракция СБ и звуки площадки. Блок
«Допуск в Сеть» — на карточке игрока.

**Наполнение узлов** (Мастерская → «Узел Сети»): мастер кладёт в узел шарды, демонов и эдди и убирает лишнее; Мост предметы сам не выдумывает. Экран
присылает предметы в человеческом виде, коллектор собирает payload по `ItemPayloadCodec` Моста (`lib/netPayload.ts`) и шлёт `master.stock_node` /
`master.unstock_node`: `POST /api/net/nodes/:id/stock|unstock`, `GET /api/net/nodes/:id/items` (что лежит в узле, без тел шардов). Это операции с
ценностями: id предметов без явного задания выводятся из `rid` и номера — те же байты при повторе, Мост не создаст копий. Шард с «требует взлома»
кладётся нерасшифрованным.

**Разработка без Моста:** `npm run fake-bridge` (в `server/`) поднимает пустышку по протоколу с примером Сети, дальше
`BRIDGE_URL=ws://127.0.0.1:7410/netrun/v1 BRIDGE_MASTER_KEY=master-key npm run dev`. Это не эталон правил Моста — только то, чем пользуется коллектор;
тесты клиента Моста и экранов идут против него же (`server/src/net/fakeBridge.ts`). Запуск настоящего Моста на машине разработки — [docs/netrun-devbox.md](../docs/netrun-devbox.md).

## Сторона телефона

Код приложения — зона Android; здесь только то, что нужно знать при работе с коллектором (подробности — `docs/android-handoff.md`).
- Записи (`ChangeRecord`, `ChangeRecorder`, `SyncEngine` в `kit`, `collector/CollectorSync.kt` в приложении) складываются в локальную очередь
  (Room, `pending_change_records`, переживает перезапуск) и отправляются с нарастающей паузой; `seq` — сквозной счётчик в `IdentityStore`.
- Адрес и код игры — Профиль → «Сеть» → «Мастерский коллектор»; обычно приходят QR персонажа и там только читаются (снимаются сбросом сессии);
  пусто — ничего никуда не шлётся, игра работает как раньше.
- Уникальные слоты (`copies > 0`) арбитрирует сервер (`SlotClaimStore`, `POST /api/slots/:slotRef/claim`); бесконечные слоты и игра без коллектора —
  по-прежнему локально между телефонами.
- Записи эмитятся по игровым событиям: создание персонажа, исход взлома и причины блока (нет связи / кулдаун / пусто), выдача лута, эдди за взлом,
  деньги из шарда, обе стороны перевода (и его отмена до доставки — `TRANSFER_CANCELLED` с тем же `txId`), скан и расшифровка шарда, апгрейд RAM,
  сигнал СБ (ушёл / подавлен), сброс сессии.

## Границы

- Очереди «фиксера» (ожидание подтверждения уникального слота) и mDNS нет: недоступный коллектор — слот не выдаётся, адрес приходит из QR персонажа.
- Подписи QR мастера нет (подделка требует доступа к принтеру или экрану мастера); предметы при повторной выдаче не возвращаются
  ([docs/character-reissue.md](../docs/character-reissue.md)).
- Сквозной прогон со сканированием QR камерой не автоматизирован (камера не эмулируется); события взлома, переводы, правки мастера и прочее
  прогоняет стенд e2e (`scripts/e2e/`) debug-командами приложения, телефонную камеру проверяют на живых телефонах.
- Состояние хранится в одном процессе и одной БД; нагрузка на 100 устройств не проверялась (стенд — два эмулятора).
