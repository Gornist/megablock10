# Мастерский веб-дашборд — коллектор

Отдельная папка внутри проекта (не Android, не Gradle). Бэкенд, фронт и
Android-клиент (инструментация основных игровых событий) — рабочие,
проверены сквозным тестом с реальным устройством. Что именно ещё не
охвачено на стороне игры — см. «Чего ещё нет».

## Важно про Node

Нужен **Node 22 LTS** (так же, как в CI; `engines` в `server/package.json`).
`better-sqlite3` — нативный модуль, для самой свежей версии Node (26 на момент
написания) прекомпилированных бинарей может ещё не быть, а из исходников он
не собирается. На Mac Node стоит keg-only:

```bash
brew install node@22
export PATH="/opt/homebrew/opt/node@22/bin:$PATH"   # или добавить в PATH заранее на ноутбуке мастера
```

На выделенной машине (`deploy/mb10-admin.service` запускает `/usr/bin/node`)
проверьте `node -v` — должно быть v22.x. Локально допустим и запасной Node 20.

## Запуск на игре (один процесс, без Docker)

```bash
cd admin-web/server && npm install
cd ../client && npm install && npm run build   # собирает SPA в client/dist

cd ../server
npm run create-master -- "Имя мастера"   # один раз — печатает токен для входа, больше нигде не покажется
PORT=2517 npm run build && npm start
```

Сервер сам раздаёт собранный `client/dist` с того же порта (`http://<ip
ноутбука>:2517`) — второй процесс не нужен, mDNS сознательно не делали (см.
ниже).

## Тесты

```bash
cd admin-web/server && npm test    # node --test через tsx: API, детекторы, приём записей
cd admin-web/client && npm test    # vitest + jsdom: чистая логика форм и ключевые экраны с подменённым api
```

Клиентские тесты лежат рядом с кодом (`*.test.ts(x)`), подмена сети — `src/test/mockApi.ts`.

## Оформление

Чёрный фон, кислотно-жёлтый акцент `#FCEE0A` и электрик-циан `#00E5F2` — цвета
самого cyberpunk.net (сверено в браузере по `computed style` живой страницы,
не на глаз). Жёлтый — главный акцент и «важно», циан — информационный (ссылки,
пояснения, «на момент T», причина breach в ленте событий); вместе с красным
(`--danger`) это те же три цвета, что уже были нужны панели «Требует
внимания» для crit/warn/info — `Badge` получил tone `"info"` под циан вместо
четвёртого произвольного оттенка.

Панели, кнопки, поля и бейджи скошены через
[augmented-ui](https://github.com/propjockey/augmented-ui)
(`data-augmented-ui="tl-clip br-clip border"` — два противоположных угла
среза, фирменный силуэт этого дашборда с самого начала, раньше выложенный
руками через `clip-path`/evenodd-рамку; теперь то же самой библиотекой,
которая для этого написана). Библиотека — статика в
`client/public/vendor/augmented-ui.min.css` (не через `npm install` и импорт
в JS/CSS: сборщики минифицируют CSS с ведущей запятой в custom property не
всегда корректно, это описано в её собственной документации; вдобавок игра
идёт в офлайн-сети без интернета, так что CDN-ссылка в проде не годится в
принципе). Подробности и как обновить версию — `client/public/vendor/README.md`.

Меню и кнопки — по образцу cyberpunk.net: сплошная жёлтая заливка на
активной вкладке и у главного действия, остальное — тонкая рамка на тёмном.
Ховер/фокус — не `box-shadow` (его обрезало бы вместе с углом), а
`filter: drop-shadow(...)`, который огибает силуэт. Анимации — только
статус-сигналы (пульс точки «на связи», пульс срочной тревоги) и переходы на
hover/focus, отключаются через `prefers-reduced-motion`; это рабочий
инструмент на живой игре, а не промо-страница, поэтому решено без анимаций
при скролле/загрузке и без движущегося скан-лайна.

## Разработка

```bash
# терминал 1
cd admin-web/server && PORT=2517 npm run dev

# терминал 2 — Vite с прокси /api → :2517, HMR
cd admin-web/client && npm run dev
```

Переменные окружения сервера: `PORT` (по умолчанию 2517), `DB_PATH` (по
умолчанию `./data/mb10-admin.sqlite`), `BACKUP_DIR` (по умолчанию
`./data/backups`), `BACKUP_INTERVAL_MS` (по умолчанию 30 минут), `GAME_SECRET`
(по умолчанию не задан — см. «Секрет игры» ниже), `PUBLIC_URL` (внешний адрес сервера для QR персонажей; задать до печати), `MB10_MODE=production` (см. «Боевой режим»).

## Секрет игры

`POST /api/changes` и `POST /api/slots/:ref/claim` открыты без авторизации
мастера — на них стучится любое устройство игрока, подпись ECDSA каждой
записи и так гарантирует её подлинность. Но сами эндпоинты может задеть и
случайное устройство в той же Wi-Fi-сети на игре — не со зла, а просто шумом
(автосканеры, чужой не тот телефон). `GAME_SECRET` — необязательный общий
пароль игры именно от этого шума, не замена подписи и не авторизация игрока:

```bash
GAME_SECRET=какая-нибудь-строка npm start
```

Если задан — сервер требует заголовок `X-Game-Secret` с тем же значением на
обоих эндпоинтах, иначе 401. Если не задан (по умолчанию) — проверка
выключена целиком, ничего не меняется. В приложении секрет вводится там же,
где адрес коллектора (Настройки → «Мастерский коллектор»), или приходит
автоматически полем QR персонажа (см. `docs/provisioning-qr.md`).

`GAME_SECRET`, если задан, также определяет ключ шифрования лута в QR
контейнеров/шардов (`lib/lootCrypto.ts` → `deriveLootKey`, HKDF-SHA256 от
секрета; зеркало на Android — `LootCrypto.deriveKey`): без него ключ один и
тот же для всех игр (как было в v1, не более чем защита от обычного
QR-сканера мимо мини-игры взлома — см. комментарий в `LootCrypto.kt`), с ним
QR этой игры не расшифровать без знания именно её секрета. Отсюда и
существующее правило «не меняйте `GAME_SECRET` в ходе игры» (см. чек-лист
дня игры): смена секрета не только разлогинит устройства, но и сделает
нечитаемыми уже напечатанные, но ещё не отсканированные QR.

## Боевой режим

`MB10_MODE=production` (в systemd-юните включён) — защита от запуска «открытым»
по недосмотру. Сервер не стартует (код выхода 78, systemd его не перезапускает),
пока не выполнено всё из списка:

- задан `GAME_SECRET` длиной от 8 символов (заглушка из юнита не принимается);
- в базе есть хотя бы один мастер (`npm run create-master`).

Причины отказа печатаются в лог (`journalctl -u mb10-admin`). Без переменной
(разработка, тесты) ограничений нет.

## Резервные копии

Сервер сам, без внешних крон-скриптов, каждые `BACKUP_INTERVAL_MS`
(по умолчанию раз в 30 минут, плюс один сразу при старте) снимает
консистентную копию БД через `VACUUM INTO` в `BACKUP_DIR` (по умолчанию
`./data/backups`) и хранит последние 20 файлов, более старые удаляет сам.
На ноутбуке это было не критично (можно унести домой целиком), на
выделенной машине это единственная копия состояния игры.

Копия — целая БД: вся история `changes` (из неё пересчитывается любое
состояние игроков), очередь доставки правок, журнал мастеров, наблюдение,
контейнеры, заявки на слоты, мастера и хэши сессий.

**Восстановление** (сервер остановить, иначе он перезапишет файл):

```bash
sudo systemctl stop mb10-admin
cd admin-web/server/data
rm -f mb10-admin.sqlite-wal mb10-admin.sqlite-shm      # хвосты старой базы
cp backups/mb10-admin-<время>-<суффикс>.sqlite mb10-admin.sqlite
sudo systemctl start mb10-admin
```

Телефон хранит принятые сервером записи ещё 6 часов (журнал подтверждённых).
После восстановления сервер отвечает телефону меньшим последним номером его
записей (`knownSeq`), и телефон сам досылает всё, что было принято после
момента копии, — при ближайшем обмене, без участия мастера. Правки и
объявления мастера после момента копии досылать некому — их придётся
повторить.

**CSV-выгрузка** (`GET /api/export/<вид>.csv`, нужна сессия мастера):
`players`, `nodes`, `slots`, `history` (вся история `changes` по порядку
получения — для разбора игры постфактум) и `audit` (журнал действий мастеров).
CSV — для чтения и таблиц, не для восстановления: для него нужна копия БД.

## Автозапуск на выделенной машине (systemd)

Для Raspberry Pi/любого Linux-хоста на игровом LAN — готовый юнит в
`admin-web/deploy/mb10-admin.service` (сам не активируется, установка и
правка путей — см. комментарий в начале файла). Даёт автозапуск при
включении машины и автоперезапуск при падении процесса (`Restart=on-failure`).

## Управление игрой (экраны и API поверх наблюдения)

Помимо просмотра данных, дашборд даёт мастеру рычаги и подсказки:

- **Обзор → «Требует внимания»** (`GET /api/attention`): отрицательный баланс,
  крупное поступление за час, пропавший со связи игрок, узел с исчерпанным
  тиражом, который продолжают ломать, повторно аннулированный слот, правка
  мастера, не дошедшая до игрока (критично, если телефон при этом на связи).
  Пороги — переменные окружения `ATTN_BALANCE_JUMP` (1000), `ATTN_SILENT_MIN`
  (10), `ATTN_SILENT_MAX_MIN` (180), `ATTN_UNDELIVERED_MIN` (2).
  Телефон шлёт в heartbeat очередь неотправленных записей (`pendingCount`,
  `oldestPendingAgeMs`): она видна колонкой «Очередь» на экране игроков, а если
  телефон на связи, но самая старая запись лежит дольше `ATTN_SYNC_STUCK_MIN` (3),
  появляется тревога «Записи не доходят до сервера».
  `ATTN_SILENT_MIN` не стоит ставить короче ~40 с: телефон шлёт heartbeat раз в
  ~30 с, и честные телефоны начнут «пропадать со связи». «Разрыв цепочки
  баланса» на стенде e2e появляется всегда: debug-команды `--es balance N` меняют
  баланс без записи об изменении. В настоящей игре так делает только мастер, а
  его правки детектор исключает.
  Проверки целостности (`lib/integrity.ts`, без изменения протокола; окно
  `ATTN_INTEGRITY_HOURS`, по умолчанию 12): разрыв цепочки баланса
  (`oldValue` записи не равен `newValue` предыдущей у того же игрока; значения,
  выставленные мастером, не в счёт), один платёж или предмет, полученный двумя
  игроками (модифицированный клиент), перевод без пары дольше
  `ATTN_TRANSFER_STUCK_MIN` (10) — отправка без получения и отмены либо
  получение без отправки, крупный рост баланса по причине, не дающей денег.
  Зависший платёж мастер разбирает правкой баланса игрока (карточка игрока →
  «Правка»), приложение само его не отменит.
- **Пульс игры** (`GET /api/pulse?minutes=60`, графики на Обзоре): раз в минуту
  (`PULSE_INTERVAL_MS`) сервер пишет в таблицу `pulse_samples` снимок — игроки
  на связи, записи и heartbeat, отклонённые записи по причинам (подпись, формат,
  неизвестное поле, конфликт seq, чужой автор), отказы по лимиту и секрету игры,
  задержка приёма, взломы, выданные эдди, переводы, недоставленные правки.
  Хранится неделю. По нему же работают детекторы (`lib/anomalies.ts`), они без
  состояния: тревога живёт, пока условие держится на последних сэмплах, и сама
  гаснет: массовая потеря связи (онлайн ниже 70% пика два сэмпла подряд,
  `ANOM_SILENCE_RATIO`, `ANOM_SILENCE_MIN_PEAK`), всплеск отклонений
  (`ANOM_REJECT_MIN`, `ANOM_REJECT_SHARE`; подпись и чужой автор — срочно),
  лимит запросов, неверный секрет игры, тормоза сервера (`ANOM_SLOW_MS`), часы
  устройства, спешащие больше чем на `ANOM_CLOCK_AHEAD_MIN` минут. Если сэмплер
  не работает, тревог по пульсу нет. К проверкам целостности добавилась «сумма
  перевода не сходится» (списано не то, что получено).
  Сравнение с обычным ходом самой игры (медиана и «робастная сигма» MAD·1.4826,
  а не константы): скачок эмиссии эдди (последние 3 минуты против часа, нужно не
  меньше 20 сэмплов истории; `ANOM_EMISSION_MIN`) и игроки-выбросы за 15 минут по
  взломам и заработанным эдди (нужно не меньше 5 активных;
  `ANOM_OUTLIER_MIN_BREACHES`, `ANOM_OUTLIER_MIN_EDDIES`, `ANOM_OUTLIER_SIGMAS`).
  Тревогу можно отложить («⏸ 30 мин»): она молчит и вернётся сама, если условие
  останется после срока; отложенные видны по «отложено N», действие пишется в
  журнал мастеров. Кнопка 🔔 включает звук и метку `(!)` в заголовке вкладки при
  новой срочной тревоге (браузерные уведомления на http по LAN недоступны).
  Для стендовых прогонов окно «на связи» (5 минут) сокращается переменной
  `ONLINE_WINDOW_MS`, а минутный пульс — `PULSE_INTERVAL_MS`.
  **Подбор порогов:** `GET /api/anomalies/replay?from=&to=&stepMin=` перебирает
  детекторы по записанному пульсу и записям и отвечает эпизодами (что, когда
  началось, сколько шагов держалось). Прогоните им стендовый прогон или прошлую
  игру и поправьте `ANOM_*` там, где срабатывало лишнее или не сработало нужное.
- **QR персонажа и повторная выдача** (`docs/provisioning-qr.md`,
  `docs/character-reissue.md`). Мастерская → «Персонаж»: позывной, фракция, баланс,
  RAM; адрес сервера и код игры подставляет сервер (`PUBLIC_URL` — внешний адрес
  для телефонов, иначе адрес, по которому открыт дашборд, а с `localhost` в QR
  остаётся адрес из сборки; код игры — `GAME_SECRET`; в API он не отдаётся, но
  лежит в самом QR). Код одноразовый: `POST /api/changes` привязывает выданный
  `id` к ключу первого телефона, приславшего `CHARACTER_CREATED` с этим
  `sourceRef`; второй ключ получает отказ («provision code already applied on
  another device»), а на Обзоре — срочная тревога «Код персонажа применили на двух
  телефонах». Тот же ключ повторно — не ошибка; неизвестный `id` (не выдан этим
  коллектором) принимается как раньше. `POST /api/provisions`, `GET
  /api/provisions` (+ `/:id/qr`, пока код не применён), `POST
  /api/players/:key/reissue`.
  `CHARACTER_RESET` не стирает параметры в снимке: позывной, фракция, баланс, RAM,
  счётчики и история остаются, игроку ставится «сессия сброшена» (`sessionResetAt`).
  «Выдать заново» на карточке игрока подставляет сохранённые параметры (можно
  поправить), гасит прежний код и создаёт новый; когда новый телефон применит его,
  прежний ключ становится «заменён» (`replacedBy`), а у нового видна ссылка на
  предыдущую сессию (`replaces`), история старого ключа доступна. Заменённые
  ключи и игроки со сброшенной сессией не считаются в Экономике, Фракциях, Обзоре,
  игроках на связи, тревогах и рассылках «всем»/«фракции» (в списке игроков они
  скрыты под «выбывшие N»). Предметы при повторной выдаче не возвращаются (решение
  организатора пока не принято).
- **Фракции** (`GET /api/factions`) и **Экономика** (`GET /api/economy`):
  деньги, боевая активность, свои/чужие взломы, кому уходят сигналы СБ; сколько
  эдди в обороте по времени, источники эмиссии, медиана/топ-10%/Джини, богатейшие.
- **Массовая правка** (`POST /api/players/bulk-override`) — выбранным, фракции
  или всем: «установить» или «прибавить» (`+200`, RAM зажимается в 6–13), с
  обязательным предпросмотром (`dryRun`) и основанием. Одиночная правка тоже
  понимает `mode: "add"`.
  Правка доставляется, пока телефон не подтвердит, что применил её (`ackIds`).
  Не смог — сообщает причину (`failures`); после 5 отказов подряд или сразу,
  если повтор бесполезен (поле, которого его версия не знает), сервер перестаёт
  её слать, и она появляется в «Требует внимания» как «Правка не применилась
  на телефоне» — с причиной и числом попыток.
  Применённая правка встаёт в хронологию телефона (он сообщает свой последний
  номер записи в момент применения): записи, сделанные телефоном без связи до
  неё и пришедшие позже, её не откатывают. Неприменённая правка в снимке игрока
  не участвует — там показано то, что у игрока на телефоне.
- **Объявления** (`POST/GET /api/announcements`) — сообщение всем или фракции;
  телефон получает его тем же опросом, что и правки, показывает окном и
  уведомлением, подтверждение (`ackIds`) даёт статус «доставлено N из M» и
  список тех, кому не дошло.
- **События с фильтрами** (`GET /api/events`) — по игроку, фракции («без
  фракции» — `__none__`), типу (деньги / демоны и шарды / взломы / сигналы СБ /
  действия мастера / профиль), причине, узлу и периоду (`since`/`until`), с
  пагинацией. Ссылки с карточки игрока, строки фракции и карточки узла. Первая
  страница обновляется сама. Объявления в общий поток не попадают (по записи
  на адресата), но видны в событиях конкретного игрока.
- **Журнал** (`GET /api/audit`) — кто из мастеров, когда и что делал (правки,
  массовые правки, объявления, аннулирования слотов, созданные контейнеры и QR).
- **Состояние на момент T** — `?until=<мс>` у `/api/players` и
  `/api/players/:key` (по часам сервера): «что было у игрока тогда» для разбора споров.
- **Узлы**: взломы за час в списке, почасовая динамика исходов и список
  взломщиков в карточке узла (`/api/nodes/:id?hours=`).
- **Закладки** (`/api/watch`) — общий для всех мастеров список игроков «под
  наблюдением» с пометкой; виден на Обзоре.

- **Выход и сессии.** `POST /api/auth/logout` закрывает сессию мастера на
  сервере (кнопка «выйти» вызывает его). В базе (и в бэкапах) лежит только
  хэш сессионного токена, просроченные сессии удаляются при следующем входе.
  После обновления с версии, где токены хранились открытым текстом, все
  мастера один раз входят заново.
- **Ограничение частоты на `/api/changes`.** По умолчанию 120 запросов в
  минуту на адрес (обычному телефону нужно ~2); сверх лимита — 429 с
  `Retry-After`, приложение повторяет с нарастающей паузой.
  `CHANGES_RATE_PER_MIN=0` отключает лимит.
- **Время сервера.** «За час» (Обзор, узлы), динамика узла и «последний
  взлом» считаются по времени прихода записи на сервер, а не по часам
  телефона — сбитые часы устройства цифры не искажают.
- **Справочники** `GET /api/meta` — причины событий и типы для фильтров;
  единственный источник подписей (клиент их не дублирует). Типы ответов API
  описаны один раз в `server/src/apiTypes.ts`, клиент импортирует их оттуда.

Мастерские записи (правки, объявления) не считаются признаком того, что игрок
«на связи»: рассылка не должна делать всех «онлайн».

## Что уже есть

Бэкенд (`admin-web/server`):
- `db/index.ts` — схема SQLite версионируется через `PRAGMA user_version`
  (см. `runMigrations`): базовая схема (`CREATE TABLE/INDEX IF NOT EXISTS`,
  безопасна для повторного применения) — версия 1, дальнейшие изменения
  существующих таблиц (то, что `IF NOT EXISTS` не покрывает — `ALTER TABLE
  ADD COLUMN` и подобное) добавляются новым элементом в `MIGRATIONS`, а не
  правкой самой схемы задним числом; порядок версий проверяется
  `validateMigrationSequence` (тесты — `dbMigrations.test.ts`). Аналог
  `docs/db-migrations.md` для Android-стороны (Room).
- `POST /api/changes` — приём батча ChangeRecord, проверка ECDSA-подписи
  (secp256r1, тот же формат, что `IdentityStore` в Android-приложении —
  проверено сквозным тестом), идемпотентность по `id` и по
  `(subjectKeyB64, seq)`, битая подпись не роняет весь батч.
- `POST /api/containers`, `POST/GET /api/slots*` — заливка контейнеров из
  Мастерской и арбитраж тиражного лута. Упрощено по сравнению с исходным
  ТЗ: если коллектор недоступен, уникальный слот просто не выдаётся
  («хранилище недоступно»), без очереди «ожидает подтверждения» и без
  экрана фиксера — обычный лут и эдди начисляются как всегда.
- `GET /api/overview`, `/api/players`, `/api/players/:key`,
  `/api/players/:key/history`, `/api/nodes`, `/api/nodes/:id`,
  `/api/transfers`, `/api/export/:kind.csv` — read-API для дашборда.
  Снимок персонажа — SQL-агрегат по `changes` на каждый запрос, отдельной
  таблицы-снимка нет и не будет.
- `POST /api/players/:key/override` — ручная правка мастера
  (`MASTER_OVERRIDE`, обязательное основание в `source_ref`, пишется в
  `audit_master`).
- `POST /api/auth/login` + мастерские токены (`npm run create-master`,
  выдаёт токен один раз, хранится только хэшем) — сессия сутки.
- `GET /api/changes/recent?since=` — живая лента для Обзора на polling
  (не SSE — сознательное упрощение, см. обсуждение объёма работ).
- `POST /api/master/containers`, `/shards`, `/ram` — генератор QR, перенесён
  из Мастерской в Android-приложении (`MasterToolScreen.kt`). То же
  шифрование содержимого слота (AES-256-GCM, ключ этой игры — `lib/lootCrypto.ts`
  зеркалит `LootCrypto.kt`, см. «Секрет игры» ниже) и тот же формат QR
  (`lib/mb10QrCodec.ts` зеркалит `Mb10QrCodec`), так что телефон игрока
  сканирует результат обычным сканером приложения, не зная и не должен
  знать, откуда напечатан QR. Контейнеры сразу пишутся в БД (видны в
  Узлах/Реестре), шард и RAM-токен — без сохранения (как и в Android-версии).

Фронт (`admin-web/client`, React + Vite + TS, без UI-фреймворка):
- Экраны: Обзор (счётчики + живая лента), Игроки (таблица с поиском/
  фильтром/сортировкой), карточка персонажа (снимок, демоны, шарды,
  ручная правка, история с фильтрами и пагинацией), Узлы, Реестр тиражей
  (аннулировать/вернуть в оборот), Переводы (односторонние подсвечены),
  **Мастерская** (генератор QR контейнеров/шардов/RAM прямо в браузере —
  конструктор слотов лута, картинка QR + сырая строка для печати).
- Своя дизайн-система по §10 ТЗ: монохромный HUD, скошенные панели
  (clip-path), шестиугольные маркеры строк, пунктирные разделители,
  шрифты Jura/JetBrains Mono/IBM Plex Sans самохостятся через
  `@fontsource/*` (собираются в бандл, ничего не тянется из интернета на
  игре).
- Вход мастера, сессия в localStorage, разлогин по 401.

Криптографическая совместимость Мастерской с Android проверена не только
рассуждением, но и напрямую: маленькая Java-программа с тем же кодом, что
`LootCrypto.kt` (javax.crypto — обычный JDK, Android SDK не нужен),
расшифровала payload, сгенерированный Node-сервером, и наоборот — байт в
байт совпало в обе стороны. С появлением `deriveLootKey`/`deriveKey`
(HKDF-SHA256 от `GAME_SECRET`) это ещё и закреплено автотестами с общим
тестовым вектором на обеих сторонах: `lootCrypto.test.ts` на сервере и
`LootCryptoTest.kt` на Android содержат один и тот же секрет и один и тот
же ожидаемый hex ключа — расхождение в реализации любой стороны красит один
из двух тестов, а не требует ручной проверки заново.

Android-клиент (`app/`, пакет `com.megablok10.app.collector`; механика — в модуле `kit`, пакет `com.megablok10.kit.sync`):
- `ChangeRecord` (kit) — зеркало серверной модели, та же pipe-подпись.
- `ChangeRecorder` + `SyncEngine` (kit) и `CollectorSync.kt` (приложение) — локальная очередь (Room, таблица
  `pending_change_records`, переживает перезапуск), фоновая отправка с
  экспоненциальным бэкоффом (1с → 2с → 5с → 15с → 60с). `seq` — сквозной
  счётчик в `IdentityStore`, не зависит от того, что уже вычищено из
  очереди.
- `CollectorClient` — HTTP до коллектора (OkHttp), `network_security_config.xml`
  разрешает cleartext (коллектор в локальной сети без TLS).
- Настройки → «Мастерский коллектор» — ручной ввод адреса
  (`http://<ip>:<port>`), пусто — ничего никуда не шлётся, игра работает
  как раньше. Там же — необязательный «код игры» (`X-Game-Secret`), если
  мастер задал `GAME_SECRET` на сервере (см. «Секрет игры» выше).
- `SlotClaimStore` — если коллектор настроен, уникальные слоты (`copies >
  0`) арбитрирует сервер (`POST /api/slots/:ref/claim`); старый локальный
  P2P-госсип остаётся как есть для бесконечных слотов и для игры без
  настроенного коллектора (тестирование без ноутбука мастера).
- Расставлена эмиссия `ChangeRecord` по игровым событиям: создание
  персонажа, исход взлома и три причины блокировки попытки (нет связи/
  кулдаун/пусто), выдача лута (шард/демон) из контейнера и вручную от
  мастера, эдди за взлом, деньги из шарда, обе стороны перевода, скан и
  расшифровка шарда, апгрейд RAM, сигнал СБ (ушёл/подавлен).

Всё выше прогнано сквозным тестом: curl/скрипт для бэкенда, реальный
браузер для фронта, и отдельно — реальный Android-эмулятор: созданный на
устройстве персонаж с настоящей ECDSA-подписью долетел до сервера и
появился в `/api/players`. После расстановки эмиссии по остальным
событиям проект целиком собирается (`gradle :app:assembleDebug`),
ставится и открывается без крашей на Чате/Кибердеке/Кошельке.

## Известные пробелы (сознательно, см. обсуждение объёма работ)

- Отмена перевода (`cancelOutgoing`) возможна только пока карточка не
  доставлена получателю; уходит на дашборд `ChangeRecord` с причиной
  `TRANSFER_CANCELLED` (тот же `txId` в `sourceRef`) — в «Переводах» такой
  перевод помечается «отменён отправителем», а не висящим односторонним.
- Очередь фиксера и mDNS — вырезаны из объёма; вместо mDNS предполагается
  QR с адресом коллектора через существующий сканер (пока не сделан —
  адрес коллектора вводится вручную в Настройках).
- Формат JSON внутри `oldValue`/`newValue` для `daemons.*`/`shards.*`/
  `counters.*` — рабочий, но не формально зафиксированный протокол; при
  расхождении между Kotlin- и TS-стороной смотреть комментарии в
  `ShardStore`/`DaemonStore`/`SecAlertStore`/`BreachScreen` (клиент) и
  `projection.ts` (сервер).
- Полный игровой прогон (сканирование настоящего QR контейнера,
  прохождение мини-игры взлома) через эмулятор не воспроизведён — камера
  не эмулируется тривиально. Проверено компиляцией, установкой и
  навигацией по экранам без крашей, а не живым взломом.
