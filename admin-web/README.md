# Мастерский веб-дашборд — коллектор

Отдельная папка внутри проекта (не Android, не Gradle). Бэкенд, фронт и
Android-клиент (инструментация основных игровых событий) — рабочие,
проверены сквозным тестом с реальным устройством. Что именно ещё не
охвачено на стороне игры — см. «Чего ещё нет».

## Важно про Node

Нужен именно **Node 20 LTS**, не самая свежая версия. `better-sqlite3` —
нативный модуль, для Node 26 (текущий `brew install node` на момент
написания) под него ещё нет прекомпилированных бинарей и он не собирается
из исходников. На этой машине Node 20 стоит keg-only:

```bash
brew install node@20
export PATH="/opt/homebrew/opt/node@20/bin:$PATH"   # или добавить в PATH заранее на ноутбуке мастера
```

## Запуск на игре (один процесс, без Docker)

```bash
cd admin-web/server && npm install
cd ../client && npm install && npm run build   # собирает SPA в client/dist

cd ../server
npm run create-master -- "Имя мастера"   # один раз — печатает токен для входа, больше нигде не покажется
PORT=8080 npm run build && npm start
```

Сервер сам раздаёт собранный `client/dist` с того же порта (`http://<ip
ноутбука>:8080`) — второй процесс не нужен, mDNS сознательно не делали (см.
ниже).

## Разработка

```bash
# терминал 1
cd admin-web/server && PORT=8080 npm run dev

# терминал 2 — Vite с прокси /api → :8080, HMR
cd admin-web/client && npm run dev
```

Переменные окружения сервера: `PORT` (по умолчанию 8080), `DB_PATH` (по
умолчанию `./data/mb10-admin.sqlite`), `BACKUP_DIR` (по умолчанию
`./data/backups`), `BACKUP_INTERVAL_MS` (по умолчанию 30 минут), `GAME_SECRET`
(по умолчанию не задан — см. «Секрет игры» ниже).

## Секрет игры

`POST /api/changes` и `POST /api/slots/:ref/claim` открыты без авторизации
мастера — на них стучится любое устройство игрока, подпись ECDSA каждой
записи и так гарантирует её подлинность. Но сами эндпоинты может задеть и
случайное устройство в той же Wi-Fi-сети на игре — не со зла, а просто шумом
(автосканеры, чужой не тот телефон). `GAME_SECRET` — необязательный общий
пароль игры именно от этого шума, не замена подписи и не авторизация игрока:

```bash
GAME_SECRET=какая-нибудь-строка npm start
```

Если задан — сервер требует заголовок `X-Game-Secret` с тем же значением на
обоих эндпоинтах, иначе 401. Если не задан (по умолчанию) — проверка
выключена целиком, ничего не меняется. В приложении секрет вводится там же,
где адрес коллектора (Настройки → «Мастерский коллектор»).

## Резервные копии

Сервер сам, без внешних крон-скриптов, каждые `BACKUP_INTERVAL_MS`
(по умолчанию раз в 30 минут, плюс один сразу при старте) снимает
консистентную копию БД через `VACUUM INTO` в `BACKUP_DIR` (по умолчанию
`./data/backups`) и хранит последние 20 файлов, более старые удаляет сам.
На ноутбуке это было не критично (можно унести домой целиком), на
выделенной машине это единственная копия состояния игры.

## Автозапуск на выделенной машине (systemd)

Для Raspberry Pi/любого Linux-хоста на игровом LAN — готовый юнит в
`admin-web/deploy/mb10-admin.service` (сам не активируется, установка и
правка путей — см. комментарий в начале файла). Даёт автозапуск при
включении машины и автоперезапуск при падении процесса (`Restart=on-failure`).

## Управление игрой (экраны и API поверх наблюдения)

Помимо просмотра данных, дашборд даёт мастеру рычаги и подсказки:

- **Обзор → «Требует внимания»** (`GET /api/attention`): отрицательный баланс,
  крупное поступление за час, пропавший со связи игрок, узел с исчерпанным
  тиражом, который продолжают ломать, повторно аннулированный слот, правка
  мастера, не дошедшая до игрока (критично, если телефон при этом на связи).
  Пороги — переменные окружения `ATTN_BALANCE_JUMP` (1000), `ATTN_SILENT_MIN`
  (10), `ATTN_SILENT_MAX_MIN` (180), `ATTN_UNDELIVERED_MIN` (2).
- **Фракции** (`GET /api/factions`) и **Экономика** (`GET /api/economy`):
  деньги, боевая активность, свои/чужие взломы, кому уходят сигналы СБ; сколько
  эдди в обороте по времени, источники эмиссии, медиана/топ-10%/Джини, богатейшие.
- **Массовая правка** (`POST /api/players/bulk-override`) — выбранным, фракции
  или всем: «установить» или «прибавить» (`+200`, RAM зажимается в 6–13), с
  обязательным предпросмотром (`dryRun`) и основанием. Одиночная правка тоже
  понимает `mode: "add"`.
- **Объявления** (`POST/GET /api/announcements`) — сообщение всем или фракции;
  телефон получает его тем же опросом, что и правки, показывает окном и
  уведомлением, подтверждение (`ackIds`) даёт статус «доставлено N из M» и
  список тех, кому не дошло.
- **События с фильтрами** (`GET /api/events`) — по игроку, фракции («без
  фракции» — `__none__`), типу (деньги / демоны и шарды / взломы / сигналы СБ /
  действия мастера / профиль), причине, узлу и периоду (`since`/`until`), с
  пагинацией. Ссылки с карточки игрока, строки фракции и карточки узла. Первая
  страница обновляется сама. Объявления в общий поток не попадают (по записи
  на адресата), но видны в событиях конкретного игрока.
- **Журнал** (`GET /api/audit`) — кто из мастеров, когда и что делал (правки,
  массовые правки, объявления, аннулирования слотов, созданные контейнеры и QR).
- **Состояние на момент T** — `?until=<мс>` у `/api/players` и
  `/api/players/:key` (по часам сервера): «что было у игрока тогда» для разбора споров.
- **Узлы**: взломы за час в списке, почасовая динамика исходов и список
  взломщиков в карточке узла (`/api/nodes/:id?hours=`).
- **Закладки** (`/api/watch`) — общий для всех мастеров список игроков «под
  наблюдением» с пометкой; виден на Обзоре.

Мастерские записи (правки, объявления) не считаются признаком того, что игрок
«на связи»: рассылка не должна делать всех «онлайн».

## Что уже есть

Бэкенд (`admin-web/server`):
- `POST /api/changes` — приём батча ChangeRecord, проверка ECDSA-подписи
  (secp256r1, тот же формат, что `IdentityManager` в Android-приложении —
  проверено сквозным тестом), идемпотентность по `id` и по
  `(subjectKeyB64, seq)`, битая подпись не роняет весь батч.
- `POST /api/containers`, `POST/GET /api/slots*` — заливка контейнеров из
  Мастерской и арбитраж тиражного лута. Упрощено по сравнению с исходным
  ТЗ: если коллектор недоступен, уникальный слот просто не выдаётся
  («хранилище недоступно»), без очереди «ожидает подтверждения» и без
  экрана фиксера — обычный лут и эдди начисляются как всегда.
- `GET /api/overview`, `/api/players`, `/api/players/:key`,
  `/api/players/:key/history`, `/api/nodes`, `/api/nodes/:id`,
  `/api/transfers`, `/api/export/:kind.csv` — read-API для дашборда.
  Снимок персонажа — SQL-агрегат по `changes` на каждый запрос, отдельной
  таблицы-снимка нет и не будет.
- `POST /api/players/:key/override` — ручная правка мастера
  (`MASTER_OVERRIDE`, обязательное основание в `source_ref`, пишется в
  `audit_master`).
- `POST /api/auth/login` + мастерские токены (`npm run create-master`,
  выдаёт токен один раз, хранится только хэшем) — сессия сутки.
- `GET /api/changes/recent?since=` — живая лента для Обзора на polling
  (не SSE — сознательное упрощение, см. обсуждение объёма работ).
- `POST /api/master/containers`, `/shards`, `/ram` — генератор QR, перенесён
  из Мастерской в Android-приложении (`MasterToolScreen.kt`). То же
  шифрование содержимого слота (AES-256-GCM, тот же ключ — `lib/lootCrypto.ts`
  зеркалит `LootCrypto.kt`) и тот же формат QR (`lib/mb10QrCodec.ts` зеркалит
  `Mb10QrCodec`), так что телефон игрока сканирует результат обычным
  сканером приложения, не зная и не должен знать, откуда напечатан QR.
  Контейнеры сразу пишутся в БД (видны в Узлах/Реестре), шард и RAM-токен —
  без сохранения (как и в Android-версии).

Фронт (`admin-web/client`, React + Vite + TS, без UI-фреймворка):
- Экраны: Обзор (счётчики + живая лента), Игроки (таблица с поиском/
  фильтром/сортировкой), карточка персонажа (снимок, демоны, шарды,
  ручная правка, история с фильтрами и пагинацией), Узлы, Реестр тиражей
  (аннулировать/вернуть в оборот), Переводы (односторонние подсвечены),
  **Мастерская** (генератор QR контейнеров/шардов/RAM прямо в браузере —
  конструктор слотов лута, картинка QR + сырая строка для печати).
- Своя дизайн-система по §10 ТЗ: монохромный HUD, скошенные панели
  (clip-path), шестиугольные маркеры строк, пунктирные разделители,
  шрифты Jura/JetBrains Mono/IBM Plex Sans самохостятся через
  `@fontsource/*` (собираются в бандл, ничего не тянется из интернета на
  игре).
- Вход мастера, сессия в localStorage, разлогин по 401.

Криптографическая совместимость Мастерской с Android проверена не только
рассуждением, но и напрямую: маленькая Java-программа с тем же кодом, что
`LootCrypto.kt` (javax.crypto — обычный JDK, Android SDK не нужен),
расшифровала payload, сгенерированный Node-сервером, и наоборот — байт в
байт совпало в обе стороны.

Android-клиент (`app/`, пакет `com.megablok10.app.collector`):
- `ChangeRecord.kt` — зеркало серверной модели, та же pipe-подпись.
- `ChangeRecordStore` — локальная очередь (Room, таблица
  `pending_change_records`, переживает перезапуск), фоновая отправка с
  экспоненциальным бэкоффом (1с → 2с → 5с → 15с → 60с). `seq` — сквозной
  счётчик в `IdentityManager`, не зависит от того, что уже вычищено из
  очереди.
- `CollectorClient` — HTTP до коллектора (OkHttp), `network_security_config.xml`
  разрешает cleartext (коллектор в локальной сети без TLS).
- Настройки → «Мастерский коллектор» — ручной ввод адреса
  (`http://<ip>:<port>`), пусто — ничего никуда не шлётся, игра работает
  как раньше. Там же — необязательный «код игры» (`X-Game-Secret`), если
  мастер задал `GAME_SECRET` на сервере (см. «Секрет игры» выше).
- `SlotClaimStore` — если коллектор настроен, уникальные слоты (`copies >
  0`) арбитрирует сервер (`POST /api/slots/:ref/claim`); старый локальный
  P2P-госсип остаётся как есть для бесконечных слотов и для игры без
  настроенного коллектора (тестирование без ноутбука мастера).
- Расставлена эмиссия `ChangeRecord` по игровым событиям: создание
  персонажа, исход взлома и три причины блокировки попытки (нет связи/
  кулдаун/пусто), выдача лута (шард/демон) из контейнера и вручную от
  мастера, эдди за взлом, деньги из шарда, обе стороны перевода, скан и
  расшифровка шарда, апгрейд RAM, сигнал СБ (ушёл/подавлен).

Всё выше прогнано сквозным тестом: curl/скрипт для бэкенда, реальный
браузер для фронта, и отдельно — реальный Android-эмулятор: созданный на
устройстве персонаж с настоящей ECDSA-подписью долетел до сервера и
появился в `/api/players`. После расстановки эмиссии по остальным
событиям проект целиком собирается (`gradle :app:assembleDebug`),
ставится и открывается без крашей на Чате/Кибердеке/Кошельке.

## Известные пробелы (сознательно, см. обсуждение объёма работ)

- Отмена перевода (`cancelOutgoing`) возможна только пока карточка не
  доставлена получателю; уходит на дашборд `ChangeRecord` с причиной
  `TRANSFER_CANCELLED` (тот же `txId` в `sourceRef`) — в «Переводах» такой
  перевод помечается «отменён отправителем», а не висящим односторонним.
- Очередь фиксера и mDNS — вырезаны из объёма; вместо mDNS предполагается
  QR с адресом коллектора через существующий сканер (пока не сделан —
  адрес коллектора вводится вручную в Настройках).
- Формат JSON внутри `oldValue`/`newValue` для `daemons.*`/`shards.*`/
  `counters.*` — рабочий, но не формально зафиксированный протокол; при
  расхождении между Kotlin- и TS-стороной смотреть комментарии в
  `ShardStore`/`DaemonStore`/`SecAlertStore`/`BreachScreen` (клиент) и
  `projection.ts` (сервер).
- Полный игровой прогон (сканирование настоящего QR контейнера,
  прохождение мини-игры взлома) через эмулятор не воспроизведён — камера
  не эмулируется тривиально. Проверено компиляцией, установкой и
  навигацией по экранам без крашей, а не живым взломом.
