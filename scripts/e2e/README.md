# Прогоны на двух эмуляторах + дашборд

Стенд из двух эмуляторов (Alice/Neon и Bob/Rats), коллектора `admin-web` и сценариев с проверками.
Нужны: Android SDK с AVD `Medium_Phone_API_35` и `Second_API_35` (клон первого), `node@22` (Homebrew; подойдёт и `node@20`), `sqlite3`, `gradle` c JDK 17.

```bash
scripts/e2e/up.sh            # сервер + эмуляторы + APK + персонажи + связь пиров (~3 мин)
scripts/e2e/run-all.sh       # все сценарии; код возврата 1, если что-то красное
scripts/e2e/scenarios/slot-race.sh   # или один сценарий
scripts/e2e/shot.sh имя      # скриншоты обоих экранов
scripts/e2e/down.sh          # остановить всё
```

`up.sh` флаги: `--no-build` (не пересобирать APK), `--keep-data` (не сбрасывать БД сервера и данные телефонов), `--clock N` (игровые часы в N раз быстрее, по умолчанию 60), `--timer N` (таймер взлома ×N, по умолчанию 10).

## Что ускоряет прогон

- **Ускоренные часы** (`DebugConfig.clockSpeed`): кулдаун контейнера 30 мин → 30 с, задержка сигнала СБ 2 мин → 2 с, TTL и агрегация — так же.
- **Растянутый таймер взлома** (`breachTimerFactor`): на медленном эмуляторе тапать сетку вручную не успеть.
- **Автосолвер** (`autoSolve`): сетка решается сама (`BreachAutoSolver`, с тестом).
- **Debug-команды** (`DebugQrReceiver`, только debug-сборка): создать персонажа, задать позывной/фракцию/RAM/баланс, выдать демона, сбросить кулдауны, создать и отменить перевод, подать QR без камеры.
- Анимации системы выключены, лишние системные окна («не отвечает») закрываются автоматически.

Все ручки живут только в debug-сборке (приёмник объявлен в `app/src/debug`), в release значения по умолчанию: часы реальные, автосолвер выключен.

## Сценарии (`scenarios/`)

| Сценарий | Что проверяет |
|---|---|
| `slot-race.sh` | гонка за последний экземпляр слота: ровно один победитель, тираж на дашборде |
| `sec-alert.sh` | сигнал СБ доходит до владельца узла и считается на дашборде |
| `transfer-cancel.sh` | отмена недоставленного перевода + запрет отмены доставленного |
| `offline-sync.sh` | очередь синка копится без сервера и доезжает после его возвращения |
| `master-override.sh` | правка RAM и баланса с дашборда доходит до устройства |
| `announcement.sh` | объявление мастера доходит до телефона, показывается окном, после «Принято» дашборд видит доставку (`DEVICES=emulator-5554` — проверить только один эмулятор) |
| `game-secret.sh` | код игры на сервере: с неверным кодом записи копятся и не теряются, после исправления доходят. Работает только на стенде с кодом: `E2E_GAME_SECRET=строка ./up.sh`, иначе пропускается |
| `wrong-recipient.sh` | карточка платежа адресована конкретному получателю: чужую копию принять нельзя, повтор своей не зачисляется |
| `item-transfer.sh` | передача демона между игроками: отмена недоставленного возвращает предмет, доставленный отменить нельзя, принятие в чате, чек, без дублей |

Новый сценарий — скопировать любой, подключить `lib.sh`; полезные хелперы: `container`, `breach`, `q` (SQL к БД телефона), `api` (дашборд), `dbg`, `check`/`eq`, `wait_until`, `tap_text`.

## Демо-ролик для стейкхолдеров

`scripts/e2e/demo.sh` записывает ≈4-минутный ролик экрана Alice (эмулятор A): сделка с Bob в чате, перевод 100 эдди, передача демона-«блэкаута», пошаговый
взлом узла «Арасака-404» с репликами ICE и демоном-майнером, зашифрованный шард (набор символов → мини-игра дешифратором → текст), пересылка шарда,
оплата 300 эдди и сообщение от неизвестного. Нужны `ffmpeg` (`brew install ffmpeg`) и **свежий** стенд (`up.sh`): сюжет двигает предметы и деньги.

```bash
scripts/e2e/up.sh && scripts/e2e/demo.sh     # результат: /tmp/mb10-e2e/demo/demo.mp4 и demo.gif
RECOMPOSE=1 scripts/e2e/demo.sh              # пересобрать ролик из уже записанных кусков (скорости сцен — speed_of в скрипте)
TARGET=120 RECOMPOSE=1 scripts/e2e/demo.sh   # ужать до ~2 минут (по умолчанию сцены идут почти в реальном темпе, ≈4 мин)
```

Каждая сцена пишется отдельным куском (`screenrecord` ограничен 180 с), ffmpeg склеивает их с разной скоростью и держит последний кадр куска
(`screenrecord` не пишет кадры без изменений экрана). Сообщения Bob и Alice отправляются debug-командами (`say`, `pay`, `give`, `sayas`), потому что
`adb input text` не умеет кириллицу.

## Видео веб-интерфейса мастера

`scripts/e2e/dashboard-demo.mjs` записывает ≈2-минутный обход дашборда с подписями по сценам приложения: обзор с живой лентой событий, игроки,
история Alice и Bob (переводы, передача демона и шарда, расшифровка), узел «Арасака-404», реестр тиражей, переводы, мастерская. Запускать сразу
после `demo.sh` на том же стенде: данные для подписей берутся из API сервера. Без зависимостей: Node ≥ 22 (встроенные WebSocket и fetch),
Google Chrome (headless, управление по протоколу DevTools; кадры screencast приходят только при изменении страницы), `ffmpeg`.

```bash
node scripts/e2e/dashboard-demo.mjs          # результат: /tmp/mb10-e2e/dash/dashboard.mp4
```

## Ограничения

mDNS между эмуляторами не ходит — пиры связываются `DEBUG_PEER` + `emu redir` (`link.sh`; после перезапуска приложения порты меняются, запустить `link.sh` заново). Камера заменена `DEBUG_QR` (нужен открытый экран «Кибердека»). Звук звонков, реальный Wi-Fi и нагрузка на слабые телефоны — только на физических устройствах.


## Как ускорить и не ломать прогоны (практики)
- **Не гасите эмуляторы между прогонами.** Холодный старт двух эмуляторов ≈ 1,5 мин; `./up.sh --no-build` при уже запущенных эмуляторах пересоздаёт только приложения и сервер (≈ 1 мин). Снимки AVD (`snapshot load/save`) на этой связке (Apple Silicon, headless) не работают: «Error -22 while loading VM state».
- **Полный `run-all.sh` ≈ 4 мин** на чистом стенде; в конце печатается время каждого сценария. Если прогон идёт заметно дольше, значит сценарии ждут таймауты красных проверок — смотрите на первый красный, а не на общее время.
- **Не запускайте `run-all.sh` через `| tail`**: сервер, поднятый сценарием `offline-sync`, наследует канал и не даёт команде завершиться. Пишите вывод в файл (`> /tmp/ra.log 2>&1 < /dev/null`).
- **Перед каждым сценарием `run-all.sh` вызывает `reset_ui`**: закрывает «Сообщение от мастера» и возвращает приложение на передний план — иначе окно, оставшееся от прошлого сценария, перехватывает тапы и красит все следующие.
- **Порт приложения** берётся у самого приложения (`DEBUG_CONFIG --es port '?'`), а не из logcat: сценарии делают `logcat -c`, и после этого `link.sh` раньше не находил порт.
- **Ручные эксперименты грязнят стенд** (баланс, контейнеры, незавершённый взлом): перед прогоном сценариев — `./up.sh --no-build`.
- `double-spend.sh` проверяет гонку «двойной тап» (8 одновременных переводов при балансе, хватающем на три) — `pay ... --ei burst N` в debug-приёмнике.
