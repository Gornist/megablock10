# Оркестрация: конвейер большой задачи

Мелкую правку делай сам. Этот конвейер — для работы из 3+ шагов: рефакторинг, массовые правки, прогон нескольких областей. Выведен из реального
рефакторинга 03.10 (20 коммитов, 7 исполнителей) и рецензии Opus; цифры и грабли — внизу.

## Стадии

0. **Скоуп.** Чьё это по `CLAUDE.md`/памяти (Android — `app/`, `kit/`; коллектор, прошивка, netrun — другие сессии: не трогать). Ветка и worktree: `scripts/agent-worktree.sh new <имя>`.
1. **Разведка — ОДИН агент** (sonnet, `Explore`), узкий вопрос, отчёт ≤350 слов. Результат — **досье**: пути, строки, сигнатуры, риск, чем проверять. Исполнителю
   дают досье в промпте, чтобы он не перечитывал код (200–270k токенов → ≈100k). Три разведчика по 200k, как было, — дорого.
2. **Карточки.** Общие правила исполнителя — файл (шаблон ниже), на задачу — короткий промпт: цель, владеемые файлы, что нельзя, критерий «готово».
3. **Исполнение.** Sonnet на код, haiku — только механика (скрипты, чек-листы, поиск), разбор падений — sonnet (ошибка дороже). По умолчанию — **последовательно на
   одной ветке**. Параллельно — не более **2** исполнителей, только если: у каждого своя worktree и ветка, наборы файлов не пересекаются, ни один не трогает общие точки
   (`*.gradle.kts`, `libs.versions.toml`, `AppGraph`, `strings.xml`, `config/detekt`, `docs/progress.md`, PNG-эталоны Paparazzi). Потолок ускорения параллели — ≈1,5×:
   Gradle занимает половину времени исполнителя, а сборки всё равно идут по очереди. После каждого слияния веток — полный прогон (две ветки бывают зелёными порознь и красными вместе).
4. **Проверка** — `scripts/dbx.sh` (см. «Команды»): на шаг `--auto` (набор по изменённым путям, выбирает скрипт, а не агент), перед PR `--full`, после слияния веток — `--full`.
5. **Ревью.** Деньги, предметы, личность, сеть, транзакции — читает диф оркестратор (или Opus по диффу, ≤400 слов); остальное страхуют тесты. Исполнитель не чинит «найденные по пути» расхождения
   инвариантов — записывает в отчёт, решает владелец.
6. **Доставка.** Ветка → PR → `scripts/ci-wait.sh` (один итог) → в `main` только по команде владельца, fast-forward. e2e (17 мин) — только в CI на PR, на devbox не гонять; пока идёт — следующая задача.
7. **Уборка.** Висящих процессов нет (`ps`), ветки/worktree слитых — предложить владельцу к удалению. `./gradlew --stop` на devbox **не вызывать**: демон общий с другими сессиями (простой — `org.gradle.daemon.idletimeout=600000`).

## Команды

| Что | Команда |
|---|---|
| Gradle на devbox, по изменённым путям | `scripts/dbx.sh --auto` (пропускает, если с последнего зелёного ничего не менялось; `DBX_DRY=1` — показать набор) |
| Полная проверка | `scripts/dbx.sh --full` (kit-тесты, detekt, Animal Sniffer, lint, Paparazzi) |
| Своя задача | `scripts/dbx.sh -- :app:testDebugUnitTestNoScreenshots --tests '*XTest*'` |
| Ждать CI | `scripts/ci-wait.sh pr 9` / `sha <sha>` — запускать Bash с `run_in_background`, придёт одно уведомление (код 0 зелёно, 1 красно) |
| Телефон на devbox | `scripts/phone.sh devices\|install\|prov\|qr\|shot\|tap\|log` |

`dbx.sh` сам: коммитит дерево во временном индексе (рабочая копия не меняется), пушит в `refs/dbx/<имя>`, на devbox ставит в очередь `flock` (блокировку держит отвязанный
процесс, обрыв ssh её не снимает), печатает одну итоговую строку `DBX rc=… commit=… очередь=… сборка=…` и при красном — выдержки и путь к журналу. Вызывать один раз и ждать (минуты).

## Ожидание (главная утечка токенов)

Каждое уведомление — отдельный ход со всем контекстом. Поэтому: **никаких Monitor с выводом на каждую итерацию**; ждать одним фоновым Bash (`ci-wait.sh`, `dbx.sh`) с ограниченным циклом
и одним итогом; уведомление не по делу — не отвечать текстом. Пока ждёшь, делай следующую независимую работу. Любой цикл — с пределом итераций; ошибки API (504) переживать.

## Проверки: что страхует, а что нет

- Целевые тесты (`--tests`) выбирает не агент. Они пропускают: скриншоты при правке общей темы, новые находки detekt/lint, Animal Sniffer по kit, соседние модули, миграции Room, сериализацию
  приложение↔сервер, инварианты денег (видны только в e2e). Отсюда: detekt всегда, `--auto` по путям, `--full` перед PR и после слияния, e2e в CI на PR.
- Кэш сборки (`org.gradle.caching=true`) отдаёт результат между worktree: повтор той же задачи — секунды. **Проверка стабильности (Paparazzi на macOS и т. п.) — только с `--rerun-tasks`.**
  Configuration cache не включать: не сериализуется `AndroidUnitTest` (проверено 04.10).

## Шаблон общих правил исполнителя (положить в файл, дать путь в промпте)

```
Проект «Мегаблок №10». Рабочая копия и ветка: <путь, agent/…>. Только там. НЕ пушить, НЕ мержить, основной checkout и main не трогать. Коммиты — локально.
Прочти: CLAUDE.md, .claude/rules/app-invariants.md, раздел «правила» docs/architecture.md. Скоуп: <области>; чужие области (collector, netrun, admin-web, firmware) не менять.
Рефакторинг = поведение не меняется. Неприкосновенно: форматы сети/QR/записей, схема Room, имена prefs, события Mb10Log и MB10DBG, эталоны app/src/test/snapshots
(никогда recordPaparazziDebug, cleanTest*). Gradle на Mac не запускать: только scripts/dbx.sh --auto (на шаг) и --full (в конце); rc=0 — зелёно. Читай код точечно
(grep, диапазоны), файлы >300 строк целиком не читай; готовое досье ниже — не перепроверяй. Циклы ожидания — с пределом. Коммит после каждого зелёного шага: на русском, что и ПОЧЕМУ;
git add только своих файлов. Не вышло за 2 попытки — откати шаг, назови причину. Расхождения с инвариантами — в отчёт, не чинить. Отчёт ≤150 слов: коммиты, что сделано/пропущено, rc последнего полного прогона.
```

## Грабли (были на деле)

- Pre-push хук на Mac берёт `JAVA_HOME` из `scripts/check.sh` (temurin-21); нет системного JDK 21 — `export JAVA_HOME=…` перед `git push`.
- Симлинк `admin-web/*/node_modules` в worktree (его делает `agent-worktree.sh`) заставляет хук гонять тесты сервера: для работы только над `app/` удалить симлинк.
- В zsh `status` — зарезервированная переменная (монитор падал); на macOS нет `timeout`.
- `gh` отвечает 504: не считать это «готово»; повторять.
- Блокировка `flock` не должна наследоваться Gradle (демон удержит её после конца задачи) — в `dbx-run` fd закрыт (`9>&-`).
- Pico и чужие приложения на devbox не трогать без разрешения владельца; общий adb-сервер не перезапускать.

## Базовые цифры (рефакторинг 03.10, для сравнения эффекта)

Субагентов ≈1,9M токенов (разведка 3×≈200k, исполнители 7×≈230k); ≈30 мин чистого времени агентов; ≈40 пустых ходов ожидания; полная проверка (3–5 мин) на каждый шаг.
Цель конвейера: разведка одним агентом с досье (−50% на исполнителях), `--auto` вместо полной на шаг, один итог вместо опроса. После `org.gradle.caching`: новая папка devbox — 118 с на полную проверку, повтор — секунды.
