# netrun-loop — как не терять время и контекст

Все команды — `netrun/tools/dev.sh` (с Mac, из своего worktree). Он сам выводит каталог devbox из ВЕТКИ (`wt-<ветка без agent/>`), льёт `netrun/` через `rsync --delete`,
гоняет gdUnit под `flock` и `timeout` и печатает компактный итог. Полные журналы — на devbox в `~/dev-logs/`, путь в итоге.

## Цикл
1. Правка — инструментами Edit/Write (не python-heredoc'ом: он гоняет весь файл через контекст дважды и не отслеживает файл).
2. `netrun/tools/dev.sh test` — тесты, затронутые изменёнными файлами (по `class_name`, пути и `tests/<имя>_test.gd`); итог — строка на набор. Явно: `dev.sh test hand_view_test avatar_body_test`.
3. Перед коммитом один раз `netrun/tools/dev.sh test --all` — **только в фоне** (Bash `run_in_background`, придёт уведомление), 5–10 минут. Не чаще одного полного прогона на коммит.
4. Кадры: `netrun/tools/dev.sh shot res://assets/preview_X.tscn [арги]` (на дисплее devbox ~6 с). На Mac приходит ОДНА сетка ≤ 1024 px (`/tmp/dev-shots/<каталог>/sheet.png`),
   читать её, а не отдельные кадры. Деталь мелкая — `DEV_CROP=0.3,0.15,0.4,0.7 dev.sh shot …` (доли: левый, верх, ширина, высота) режет каждый кадр до сборки сетки.
5. Ждать — через `run_in_background`/Monitor с until-циклом, не `sleep`; устаревшие мониторы после события не перевзводить.

## Когда делегировать суб-агентам
- Холодный старт суб-агента стоит ≈ 10–20 тыс. токенов: одну сетку дешевле посмотреть самому. Делегировать — цикл из 3+ итераций «правка → кадр» или задачу с большим выводом.
- `visual-reviewer` (sonnet; haiku на пробе дал ложный FAIL — выдумал «заливку» и «линии» на чистых кадрах, sonnet ответил верно): чек-лист «видно / не видно / кадр не битый / элемент на месте» по сетке → PASS/FAIL по строкам. Не доверять ему пропорции, анатомию, зеркальность и ±90°:
  это проверяют числом (тест на `Transform3D` и углы) или главный агент/владелец. Каждый третий его PASS сверять по сетке самому; разошёлся хоть раз — по этой задаче больше не принимать без сверки.
- Параллельно можно: полный gdUnit (фон) + правка документации; два разных превью не гонять одновременно (один дисплей, flock).
- Нельзя делегировать: слияние и пуш в `main` (только по явной команде владельца), решения владельца (`docs/netrun.md`), правки сетевого протокола и формата сообщений
  (зона сессии Godot), Pico, пока очки у владельца. Суб-агенты не коммитят — коммит делает главный поток после сверки.

## Ловушки (все пережиты)
- В каталоге devbox не должно быть чужих `*_test.gd`: `dev.sh` синхронизирует с `--delete`. Руками `rsync` без `--delete` не лить.
- gdUnit, упавший в отладчике («Parser Error → Debugger Break»), не завершается сам: `dev.sh` ставит `timeout` и сообщает `ERROR`; вручную — `pkill -f GdUnitCmdTool`.
- Mac: bash 3.2 (нет `mapfile`, ассоциативных массивов), `sips` для кропа, `python3` без Pillow/numpy. Pillow, Blender (`~/.local/bin/blender`) и Godot — на devbox.
- Каталог devbox — копия без `.git`: «что на devbox» = то, что залил последний `dev.sh sync`; `.dev-branch` и `.dev-sha` в корне говорят, какая это ветка и коммит.
- Классы с константными массивами: `PackedFloat32Array([...])` — не константа GDScript; используй `const X: Array[float] = [...]`.
